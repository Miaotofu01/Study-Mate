# 诊断与健康检查

装上了但看不到「学习模式」、阅读端打不开、工作区读不到时，先跑：

```bash
npx -y @yunmiao/studymate@latest doctor
```

它只读检查，不改任何文件。需要给 issue 或维护者贴结果时用：

```bash
npx -y @yunmiao/studymate@latest doctor --json
```

## 检查什么

- Node 版本；
- `dsh` 是否可运行、版本是多少；
- `~/.dsh/studymate-config.yaml` 能否解析；
- 学习工作区是否存在、是否可写、有没有 `.learning/`；
- 当前 profile 下有没有学习模式 / 答疑模式声明或插件包；
- 上一次插件启动有没有留下失败记录；
- `node` 与 `sh` 是否可用。

输出只有三种结论：

- `OK`：这一项通过；
- `WARN`：不阻断，但会影响部分能力；
- `FAIL`：需要处理，否则完整功能不可用。

报告不会输出 API key、token、完整 prompt 或学习内容正文。

## 常见读法

### `没有找到配置文件`

安装器还没跑过，或 `DSH_HOME` 指到了另一处。检查：

```bash
echo $DSH_HOME      # PowerShell: echo $env:DSH_HOME
```

然后重新安装，必要时显式指定工作区：

```bash
npx -y @yunmiao/studymate@latest install --workspace "D:/StudyMate-workspace"
```

### `配置存在，但 YAML / JSON 都读不出来`

`studymate-config.yaml` 里有语法错误。先备份，再修正；不要整文件覆盖。安装器写的是「注释 + JSON」，手改过的块映射也应当能读。

### `profile 目录不存在`

`--profile` 写错，或桌面端还没有启动过。桌面端路径要先启动一次 DSH Desktop，让它建出自己的 profile。

### `没有找到学习模式预设或插件包`

先确认插件已装进当前 profile：

```bash
dsh plugin --profile web add @yunmiao/studymate
```

然后完全退出 DSH 再重开。旧版安装器路线还要检查 `profile` 是否写对。

### `没有找到 sh；旧版 check.sh lab...`

Windows 通常没有 POSIX `sh`。阅读与课件不受影响；旧版 `check.sh` 实验可能跑不了。新 lab 会使用 Node runner（后续版本）。

### `上次插件启动失败`

报告会带 `stage` 与错误原文。常见阶段：

- `preset-registration`：预设配置解析或注册失败；
- `host-registration`：任务类型 / 路由 / 文件监听挂载失败。

先把 `doctor --json` 的完整输出和该阶段错误贴到 issue，不要只截「UNKNOWN」。

## 运行中的健康路由

DSH 运行时还会提供：

```text
GET /api/studymate/health
```

它与 CLI 共用同一份检查逻辑，但不会启动第二个 `dsh` 进程。阅读端打开时会请求它：

- `FAIL`：顶部红色横幅，不可关闭，提供「重试 / 复制诊断」；
- `WARN`：顶部黄色横幅，可关闭；阅读与作答照常；
- `UNAVAILABLE`：连不上这条路由时显示，不阻塞阅读；
- `MISSING`：旧宿主没有这条路由（HTTP 404）时不显示横幅，避免升级前先被“检查不可用”打扰。

横幅只展示 Host 报告里的原始 `message`，不自行推断安装状态。
