# 安装与更新

DSH 使用 `npx`；Codex 下载 ZIP 后导入。两种安装方式使用同版本的技能与 schema，学习数据保存在独立工作区。

## DSH

需要 DSH 0.1.5-rc.2 及以上、Node.js（支持范围见 `package.json` 的 `engines`）。**不需要 Python**：引擎是随包发的 TypeScript 插件，安装器也不再探测解释器——`npx` 跑完那一句就完事。**桌面端用户同样需要 Node.js**：安装器本身要用 `npx` 运行，而桌面端自带的 Node 不在 PATH 上。

导出静态页面时另需一份 React（`npm i -g react react-dom`，或用 `STUDYMATE_REACT_DIR` 指过去）；只学不导出的话不用装。

安装命令在 macOS、Linux 和 Windows 上是同一条：

```sh
npx -y @yunmiao/studymate@latest install
```

**更新时再运行同一条 `npx` 命令**，然后按下面的说明重启对应的 DSH。旧版通过源码安装的用户也使用此命令，已有工作区配置会沿用。

### 桌面端（DeepSeek Harness Desktop）

桌面端自带 DSH，不需要再装官方 CLI。安装器找不到 PATH 里的 `dsh` 时，会自动使用桌面端自带的那个，并把学习模式注册到桌面端的保留档位 `desktop`（桌面端只引导这一个档位）。

1. 运行 `npx -y @yunmiao/studymate@latest install`。
2. **完全退出 DeepSeek Harness，再重新打开**（正在运行的窗口读不到刚写入的学习模式）。
3. 新建会话时选择「学习模式」。

首次安装前桌面端要至少启动过一次：它会在 `~/.dsh/profiles/desktop/` 初始化自己的档位，安装器需要这个档位存在。还没启动过时安装器会提示先启动一次。

桌面端装在非默认目录时（Windows 默认 `%LOCALAPPDATA%\Programs\DeepSeek Harness`），用 `--dsh` 指向它自带的 dsh：

```powershell
npx -y @yunmiao/studymate@latest install --dsh "$env:LOCALAPPDATA\Programs\DeepSeek Harness\resources\runtime\cli\bin\dsh.cmd"
```

```sh
# macOS
npx -y @yunmiao/studymate@latest install --dsh "/Applications/DeepSeek Harness.app/Contents/Resources/runtime/cli/bin/dsh"
```

### 官方 CLI（`dsh web`、`dsh tui`、`dsh headless` 等）

没有桌面端时，先安装提供 `dsh` 命令的[官方 CLI 包](https://github.com/deepseek-ai/deepseek-harness/blob/master/apps/cli/package.json)：

```sh
npm install -g @deepseek-ai/dsh@latest
npx -y @yunmiao/studymate@latest install
dsh web
```

启动后新建会话，选择「学习模式」。**更新时再运行同一条 `npx` 命令，然后重启 DSH 并新建会话。**

默认注册到 `web` 档位（即 `dsh web`），其他已创建的档位用 `--profile <名称>` 指定：

```sh
npx -y @yunmiao/studymate@latest install --profile headless
```

### 两个都装了

不指定 `--profile` 时，安装器按下面的顺序决定装到哪个档位：

1. `--dsh` 指定的、或 PATH 里的 `dsh` 属于桌面端 → `desktop`；
2. 之前装过一次 → 沿用那次记录的档位（升级时不会因为 PATH 变化装到别处）；
3. 其余情况 → `web`。

PATH 里的 `dsh` 版本过旧（低于 0.1.5-rc.2）时会被跳过，继续找桌面端自带的那个；两个都不能用时，报错会指出找到的版本和位置。

要看住哪个档位，就显式写出来：`--profile desktop` 或 `--profile web`。`desktop` 由桌面端自带的 dsh 独占管理，官方 CLI 会拒绝引导和改动它，所以桌面端用户加 `--dsh` 更稳妥。

### 目录与工作区

默认学习工作区是 `~/StudyMate`，已有配置优先。可以指定其他目录：

```sh
npx -y @yunmiao/studymate@latest install --workspace "D:/StudyMate-workspace"
```

指定目录只改变后续读写的位置，不会自动搬迁原有学习数据。换目录或换机器时，先复制整个学习工作区（包括隐藏的 `.learning/`），再安装并指定复制后的路径。

引擎安装到 `~/.dsh/studymate/engine/`，配置保存在 `~/.dsh/studymate-config.yaml`；设置了 `DSH_HOME` 时使用对应目录。安装器按 DSH 版本注册**两条**预设——「学习模式」（`preset/learning/`，插件入口 `@yunmiao/studymate`）与「答疑模式」（`preset/qa/`，插件入口 `@yunmiao/studymate/qa-preset`，只给阅读端的就地答疑用），不会安装、升级或重启 DSH。升级或降级 DSH 后重新运行安装命令即可适配。

## Codex / ChatGPT Work

1. 从 [最新 Release](https://github.com/Miaotofu01/Study-Mate/releases/latest) 下载 **studymate-openai.zip**。
2. 通过 Codex 客户端提供的插件导入入口安装该 ZIP；没有导入入口时，按 [导入说明](Codex与ChatGPT.md) 使用插件创建器。
3. 新建任务，选择 StudyMate 的 `learning-system` 技能，并说明学习目标和工作区路径。

**更新时下载最新 ZIP，在浏览器中打开已有插件的链接，选择上传新版本，然后新建任务。** 保留原学习工作区即可继续学习。

ChatGPT Work 的使用条件、工作区说明与导出见 [Codex 与 ChatGPT](Codex与ChatGPT.md)。
