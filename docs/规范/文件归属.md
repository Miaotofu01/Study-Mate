# 文件归属（代称 ↔ 路径 ↔ 维护者）

**这份表是文件「代称、功能、路径、维护者」的唯一出处。** 角色规格（`preset/skills/*/SKILL.md`）在正文里用「代称」指代文件，不再反复写全路径；要判断自己有没有权改某份文件，查这张表的「维护者」一列。

## 怎么用

- 代称在 SKILL 正文里写作「共享记忆」这样用「」框住；本表第一列写裸名
- **角色也有代称**（见下节）：正文里可以直接用「总控」「讲解」这类叫法；**「维护者」一列写的是技能名**，按角色代称表对应
- **路径前缀**：`<root>` = 引擎仓库根；`<LEARN_WORKSPACE>` = 学习工作区；`<subject_path>` = `<LEARN_WORKSPACE>/.learning/subjects/<slug>`
- 本表**不重复**各角色的边界正文：边界仍写在各自规格里，只是可以改用代称
- **收录范围**：① 角色与协议规格正文里会提到的文件；② 学生或维护者要用的仓库入口（安装说明、工程约束、本表）。**不收纯开发工具**（发布、打包、预览脚本一类）

## 角色代称

角色（谁在干活）也有代称，正文里可以直接用。**派工给什么值由各角色规格的「输入」节定义**——值归消费者，它最清楚自己需要什么；本表只回答「谁维护哪份文件」，不再复述派工值。本表其余各节的「维护者」写的是技能名。

| 代称 | 技能名 | 一句话职责 |
| ---- | ------ | ---------- |
| 总控 | `learning-system` | 开场、盘问、调度、档案；唯一有用户通道的角色（学生只跟你说话） |
| 资料收集 | `resource-scout` | 收集权威教材与官方核对来源，产「资源清单」；把本地教材与可取到正文的来源转成 Markdown 入库 |
| 采图 | `image-scout` | 抓网页现成的位图，落「图片库」与「图片库索引」 |
| 课设 | `curriculum-designer` | 产「课程大纲」与实验课节点 |
| 讲解 | `learning-coach` | 写「课件内容文件」与「速查页」；配图规范的 owner |
| 出题评估 | `practice-evaluator` | 题目唯一 owner：出题、判分、**实验课验收**（结论写进「学习记录」；不写「评估记录」；阶段评估已删） |
