> skill 管"的指路。系统形状见 [目标态规格](../设计/目标态规格.md)，日常使用见
> [使用说明](../使用/使用说明.md)，工作区数据骨架见 [templates/README.md](../../templates/README.md)。
>
> 本文档的前身是《实施计划》：那份按任务拆的构建台账（Task 1–14、"已交付"清单、依赖 DAG）
> 已随 v0.1 交付删除，**约束部分留在这里**；改引擎只读本文档与上面那几份。
>
> **#83 拆除之后这里少了三节**：模板占位符契约、脚本一览、前端技术选型。页面不再预生成，

## 一、三个区域，互不混用

| 区域 | 位置 | 是什么 |
|---|---|---|
| **引擎项目** | `<root>/`（本仓库） | 系统源码：skills 源、preset 源、schemas、工作区数据骨架（`templates/`）、`lib/` 引擎、`bin/`、docs。学习时只读 |
| **用户级安装** | `~/.dsh/`（DSH）／客户端插件目录（Codex、ChatGPT Work） | 学习模式预设与 `studymate-config.yaml`（工作区定位），standalone 安装另有一份只读材料副本。由 `npx` 安装器或插件 ZIP 管理，与会话目录无关 |
| **学习工作区** | 首次安装默认 `~/StudyMate/`，已有配置会沿用 | 所有学习数据：`.learning/` 与导出的 `export/`。布局见 [使用说明 §六](../使用/使用说明.md#六学习数据存在哪) |

- **会话可在任意目录启动**：总控开场先读 `~/.dsh/studymate-config.yaml` 拿 `workspace`（记为 `LEARN_WORKSPACE`）与 `root`；读写一律基于这两个路径，**不在会话 cwd 里建或找学习文件**。
- **学习数据直接写进配置里的学习工作区**：写盘由插件 Host 半完成，agent 沙箱的可写集不再是前提——**暂存模式已删**（[ADR-0008](../adr/0008-删掉暂存模式.md)）：没有"开场先建 `<SESSION_DIR>/.studymate-stage/<slug>`、收尾问一次落点、再 `cp -a` 搬过去"这套机制，也没有落点偏好文件。技能侧的开场只剩一次工作区摘要工具调用（DSH），无头宿主按各自宿主约定选定工作区。**产物交接用的科目内 `.stage/` 保留**——它服务的是产物门禁，不是权限。**规则全文在 `record-keeping` 的「落点与边界」**。
- **预设目录 `<root>/preset/learning/` 是源**，`npx -y @yunmiao/studymate@latest install` 负责安装并按 DSH 版本注册；**禁止直接改 `~/.dsh/` 下那份**。注册的判定与补丁拼接在 [`lib/preset.ts`](../../lib/preset.ts)（原 Python 安装助手的 TS 替代，返回值形状逐字段一致）。
- **Codex / ChatGPT Work 插件从同一份源构建**：`npm run build:plugin` 把 `preset/skills`、`schemas`、`templates`（数据骨架）与 `openai/studymate/` 合成 `dist/studymate/` 与 `dist/studymate-openai.zip`（`dist/` 不入库）。Antigravity 侧同理由 `npm run build:antigravity` 构建。改这些源会同时影响两侧；**插件清单（`plugin.json`）里的 `version` 由构建器从 `package.json` 注入**，源文件不写版本（写了也不会进产物）。ZIP 由 [`bin/zip.mjs`](../../bin/zip.mjs) 打：零依赖、确定性（固定时间戳与条目顺序，重建逐字节相同）
- 面向学生的输出一律中文；skill 内部指令用中文。

**`lib/` 下的一级目录就是「域」**（`core` / `host` / `tools` / `tasks` / `watch` / `ask` / `lab` / `export` / `katex`——最后一个是随包发的第三方 dist，登记进表是为了不给「新增目录一律要登记」开例外），直接躺在 `lib/` 里的文件属于域 `lib`；允许谁 import 谁由 [`test_architecture_boundaries.mjs`](../../scripts/tests/test_architecture_boundaries.mjs) 顶部那张**域规则表**唯一规定——新增一个一级目录不在表里登记，门禁就红。

**为什么没有示例工作区、页面模板与 Python 引擎脚本**：示例与生成产物不再入库
（[ADR-0009](../adr/0009-示例与生成产物不再入库.md)），页面模板与前端资源随静态渲染一起退役
（[ADR-0005](../adr/0005-静态页面降为导出.md)），Python 引擎迁成了 `lib/**` 的 TypeScript
（[ADR-0002](../adr/0002-引擎改用TypeScript.md)）。测试要用的科目**现造现弃**。

**规则归属（一处定义，别处只给指针）**：

- **文件代称与归属**的唯一出处是 [`docs/规范/文件归属.md`](文件归属.md)（代称 ↔ 路径 ↔ 维护者）：角色规格正文用「代称」指代文件，凡是要照着执行的（命令、路径模板、`cp`）仍写全路径
- **阅读端呈现**（四个面「看起来对不对」的意图判据、问答引用的保持行为）的唯一出处是
  [`docs/规范/阅读端呈现.md`](阅读端呈现.md)——**维护者：仓库维护者**（单维护者项目，`docs/**` 的归属随仓库走），
  随它一起改的是 `lib/client.js` 的呈现面与 `scripts/tests/browser/reading_routes_test.mjs` 那批套件。
  三栏让位顺序仍归 [ADR-0011](../adr/0011-阅读端三栏让位顺序.md)，公式与配图的内容侧写法仍归
  [课件内容格式](课件内容格式.md)——**本文不复述那份规范的内容**（与这里每条同一条规矩）
- **可选方向探索**归 `learning-discovery`，由总控按需加载并亲自执行；问数、会话状态与建课交接见 [协议](../../preset/skills/learning-discovery/SKILL.md)，不新增角色、数据 schema 或持久化探索档案
- **课件**的唯一约束来源是 `lesson-design`（要素／实操规范／讲法倾向／记忆难度／贯穿线索／复用骨架）
- **题目**的唯一规范是 `layered-practice`，出题与评估归 `practice-evaluator`
- **staged 子 agent 交接**的唯一工程协议是 [`Agent交接协议.md`](Agent交接协议.md)；它只验证交接边界，不替代领域校验
- 完成证据核验 `evidence-check`、局部答疑 `local-qa`、学习状态读写 `record-keeping`
- 本文档只写**路径与工程硬约束**，不重复上面那些内容

**分工原则**：角色 skill 只定义"职责 + 做法 + 输入输出格式"，不碰别的角色的文件；总控是唯一被模型直接加载的入口，且**信息源在它上下文里的活（答疑、盘问、四份元数据、全部档案记录）它自己干**；只有需要外部检索／大量生成／独立验证的活才派角色。

**落点偏好落哪一层**：**已随暂存模式删除**（[ADR-0008](../adr/0008-删掉暂存模式.md)）——学习数据直接写配置里的 `workspace`，没有"收尾问落点、记住上次落点"这两步，也就没有会话侧偏好文件这一层。

**等待语义归框架，不归提示词**：子 agent 是后台派出的（continuable 模式返回 `subagentId`，**不是** `jobId`），它那一轮结束会**自动给父会话送通知**并唤醒空闲的父线程——这套机制由 DSH 的系统提示与工具描述保证，技能里**不复述**，也不写 `job_output(wait: true)`（那个 API 只对有 `jobId` 的后台作业有效，对子 agent 无效）。技能只写框架管不到的那半：**同一科目同时只有一个写入者**，上一支没回来别派下一支（规则在 `learning-system` 的「交接与返回」）。

**技能调用面**（`preset/skills/*/SKILL.md` 的 frontmatter，由 `scripts/tests/test_skill_frontmatter.mjs` 校验）：

- 总控与 6 个协议允许模型按名字加载（`skill` 工具）；**5 个角色两个面都关**（`disable-model-invocation: true` + `user-invocable: false`），只作为磁盘上的规格文件，由总控在派发 prompt 里给出绝对路径，角色自行读取
- 预设用 `customSkillDirs` 指向技能源并设 `includeDefaultRoots: false`：学习会话只加载本项目技能，也不往 `~/.dsh/skills/` 装链接

**技能与工具的可见边界**（#87 落定，`scripts/tests/test_skill_visibility.mjs` 守）：

- **技能源住在 `preset/skills/`**，那是学习预设自己的目录。预设用 `customSkillDirs` 指向它（占位符由安装器换成绝对路径）并设 `includeDefaultRoots: false`：入方向——学习会话只加载 StudyMate 自己的 12 个技能，不背机器上别人装的技能。
- **别把技能挪回 `<项目根>/.dsh/skills`**（也别挪去 `.agents/skills`）。宿主的 `skill-filesystem` 默认 `includeDefaultRoots: true`，会按「从工作目录向上第一个含 `.git` 的祖先」找项目根，再扫这两个位置——技能摆在那里，**任何**工作目录落在本仓库/本包里的会话（别的预设、别的任务）都会吃到它们，边界就退化成「会话恰好不在本仓库里」这种巧合。出方向由上面那条套件守：它照宿主规则走一遍当前 cwd，断言那两条路径上什么都没有。
- **工具、面板与 slot 不在同一层**（与 #84 用户故事 36 的**已知偏离**，记账在这里）：八个 `studymate_*` 原生工具在**插件加载**时注册在插件所在 profile 的根作用域上（`bin/dsh-plugin.ts` 的 `ctx.inject(['tools'], …)` → `lib/tools/index.ts`）；客户端面板与 slot 由 `package.json` 的 `dsh.client` 在**包级**声明。两者都不经过预设，所以同一个 profile 里**任何**会话（含宿主内置的 standard 预设）都看得见它们。宿主目前没有「按预设注册工具/面板」的接口：`ctx.tools.restrict()` 要求 agent 作用域，而插件拿到的是 profile 根 ctx（调用直接抛），预设行只能开关插件、收不窄插件自己的注册面。**去向**：不改实现，改为把事实钉住——上面那条套件的最后一条断言就是「工具/面板的注册面仍在预设之外」；哪天宿主给了接口、或有人把注册面收进预设，它会红，届时同步本段与 #84。

## 三、原生工具（退役的「脚本一览」指到哪去）

**引擎没有脚本了**：Python 引擎随 #83 退役，技能与总控调用的是**原生工具**。工具的名称、参数、
返回形状与域边界的**唯一出处是代码**：

| 你要什么 | 去哪看 |
|---|---|
| 有哪几个工具、注册顺序、名字表 | [`lib/tools/index.ts`](../../lib/tools/index.ts) 的注册点与 `STUDY_TOOL_NAMES` |
| 参数表、返回形状、错误形状、域边界（给人读的） | [`preset/skills/learning-system/references/tools.md`](../../preset/skills/learning-system/references/tools.md)——**按需读，别背进上下文** |
| 无头宿主（Antigravity / Codex）怎么办 | 那边没有原生工具，也没有引擎脚本：技能导出时把工具名换成「按 schema 与格式要求逐项自查」，导出走 `npx -y @yunmiao/studymate export`。映射表在两个适配器的 `NATIVE_TOOL_FALLBACK` |
| 导出：产物形状、泄漏守卫、任务模型 | [`lib/export/`](../../lib/export/)；无头侧入口是 [`lib/export/cli.ts`](../../lib/export/cli.ts) |

**本文档不再抄第二份参数表**：抄一份就多一处会漂的副本，而漂了的后果是模型照着一份过时契约调用。
工具说明（写进模型 API 的 `description`）只有一句话，参数表由技能按需加载——这条纪律在
[`lib/tools/define.ts`](../../lib/tools/define.ts) 里焊着（`DESCRIPTION_LIMIT`）。

### 阅读端 HTTP 路由：注册约定与错误信封

阅读端（`lib/client.js`）与 Host 半之间走 `/api/studymate/*` 下的**精确路由**（`library` /
`asset` / `reference` / `attempts` / `qa/session` / `lab-run` / `tasks` / `events` /
`math`——`math` 是公式资源，一条文件一条路由、清单在 `lib/math.ts`；`qa/session` 是 #105 起
「建一条答疑会话」那条，会话按「答疑模式」预设由宿主半建，客户端建不出来（`sessions.create`
丢 `agentPreset`）；面板自己调模型那条 `ask` 已由 #107 退役）。注册在 `/api` 之下
**自动**获得宿主那层的 Host/Origin 检查与浏览器会话认证（`dsh-plugin-api.md` §6.3），不用自己写鉴权。
两条约定，改路由之前先看：

**一、注册约定只有一种：收外层 ctx、自己 `inject(['connection'])`。**
`registerAskSessionRoute(ctx)` / `registerTaskRoute(ctx, service)` / `registerAttemptRoutes(ctx)` /
`registerLabRoute(ctx)` / `registerMathRoute(ctx)` 都是这个形状——「`connection` 就绪才注册、缺了就不挂」由路由自己的模块回答，
`bin/dsh-plugin.ts` 只留一行注册（它那边一律动态 `import`，见文件里的加载边界说明）。注册是有主的
副作用，走 `connectionCtx.effect`，卸载时各自拆各自的。`registerWatchChannel` 是推送通道（SSE）而不是
请求-应答路由，它要的是注入后的那层 ctx。

**二、失败恒为一份信封：`{ ok: false, error: { code, message }, ...extra }`。**
唯一构造点是 [`lib/route-envelope.ts`](../../lib/route-envelope.ts)（`errorBody` / `routeError`），
数据层的回执（`AttemptsRefusal` / `ReferenceRefusal` / `MisconceptionRefusal`）也用它——回执被路由
**原样**递出去，两处各拼一遍就是两套信封。

- `code`：机读短码，客户端按它分支。**词表只有一份**（同文件里的 `ROUTE_ERROR_CODES`），
  新增一个码要加进词表——`scripts/tests/test_host_route_envelope.mjs` 扫源码，用了表外的码就红。
- `message`：给人看的**一句话**，原样显示在界面上（学生照着它能自救），不许是空串。
- `extra`：这一条路由额外要带回去的字段（冲突时的 `attempts` / `version`、面板的 `available` /
  `model`）。`ok` 与 `error` 不许被 extra 覆盖（构造点里排在后面）。
- 成功那一侧**不统一**：`{ok:true, attempts, version}`、`{at, tasks}`、答疑会话那条的
  `{available, ok, sessionId, title…}` 本来就在说不同的事，硬凑成一个形状只会多一层没用的壳。

客户端那侧读它的只有两个函数（`lib/client.js` 的 `routeCode` / `routeMessage`）；它是手写 JS、
不进 `tsc`，所以「只从 `error.code` / `error.message` 取值」由上面那条套件钉着。

**三条路由有意不走这个信封**，别照着它们「统一」回去：`asset` 是图片地址（`<img src>` 直接吃
响应体，回 JSON 没有意义，失败就是 404/500 的纯文本），`events` 是 SSE 流（响应体是一串事件，
不是一份 JSON），`math` 是随包发的公式排版资源（`lib/math-route.ts` 投的是文件字节，失败就是
一句纯文本 404——阅读端据此降级成可读的 TeX 原文）。

## 五、几条实测过的坑

- **YAML 里的日期一律加引号**：`created_at: "2026-09-15"`。不加引号会解析成日期对象，schema 要求字符串，校验失败
- **YAML 值里出现 `": "` 必须加引号**（例如 `Cache-Control: no-store`），否则解析报 mapping values are not allowed here
- **写给工作区的路径一律钉成绝对路径**（配置是机器全局的，留相对路径换个目录开会话就找不到工作区）
- **`curriculum.yaml` / `progress.yaml` / `subject.yaml` / 误解库 / 作答数据按 `schemas/*.json` 校验后才算交付**：校验走 `studymate_validate_curriculum`（写侧三份数据）与 `studymate_validate_lesson`（内容与题库），返回的是逐条问题（文件 + 行号 + 是否阻断），不是退出码
- **技能 frontmatter 只能有一层 YAML 映射**：直接当成完整 YAML 文档解析会因多文档报错；解析器在 [`lib/yaml.ts`](../../lib/yaml.ts)，技能那一侧由 `scripts/tests/test_skill_frontmatter.mjs` 守
- **`lib/yaml.ts` 刻意不支持标签与块标量**：学习文件里没有这些构造，见到就报错是安全属性。两份 cordis 配置要用到时**显式开**（`tags` / `blockScalars` / `documentMarkers`），默认仍旧报错
