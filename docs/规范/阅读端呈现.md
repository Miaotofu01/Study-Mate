## 一、课件页 · 正文（中栏）

判据是「一屏能读下去」，不是「填满窗口」：

- **正文列在面板里占得住宽度**：两条栏收起时，正文是这一页的主体，不是中间一条窄缝。
- **测宽服务于可读行宽**：画布宽了，正文列不跟着无限变宽——两侧留白明显；画布窄了，它铺满中栏。
  这条与「填满窗口」是两件事，别拿「窗口有多宽」当判据。
- **右栏并排打开时正文仍读得下去**：右栏有自己的下限，不会把正文挤成不可读。
- **窗口变窄，正文不被压成一条**：任何画布宽度下都保底一段可读的正文列。
- **配图两条路**：矢量图**随列宽流动**；位图**受列宽约束**——大图缩到列宽（既不横向溢出，也不裁掉），
  本身就小的图保持自己的比例。
- **暗色主题下配图不刺眼**：位图与矢量图在暗色里都被压暗一档；亮色下不给图加任何滤镜。
- **代码块带语言标签**；超长行在块内横向滚动，块本身不超正文列宽。
- **长标识符、长 URL、宽表格不撑破版面**：段落里的长 token 断行，宽表格在自己那一层里横滚，
  页面级不出现横向滚动条。
- **课件页顶部那一条只放真正有用的入口**：课件标题、小节跳转与进度在**同一条**里（原来是分开的两条，
  各占左边一小截），且这一条不空着大半条——内容从左边距铺到右边距。
- **长标题在面包屑里省略得有分寸**：上限按**全角字**（em）算，不按 `ch`——中文下按 `ch` 算会把字砍秃。
- **字号与行高成套**：同一屏里成句的文字只有一种字号，行高跟着字号走，不出现两种正文大小并存。
- **正文里的题目标记一眼看得出它属于哪一组**：标记上写着「练习」+ 组号 + 该组锚点原文 + 题数，
  组号与右栏那一组的编号对得上（点得进去，见 §二）。

## 二、课件页 · 右栏（题目 / 问答）与三栏让位

右栏是「做题与提问的那一栏」，默认收起（形状见 [目标态规格](../设计/目标态规格.md) §4.1）：

- **题型徽标是贴字的标签**：它跟着自己那行字走，不是被弹性行拉高的一根竖条。
- **「当前」组看得见**：点正文里的题目标记之后，右栏**恰好那一组**带「当前」标记（边与组号圈换成品牌色），
  且落在右栏的可见范围里；换一节课，标记不跟过去。
- **tab 的选中态与设计一致**：两个 tab 恰好选中一个，选中态是**下划线**（不是左栏那套胶囊），
  且 tab 条与内容同宽同起边。
- **上一次作答的结果看得见**（这能力早就有，别丢）：来自 `attempts/` 的那一句在右栏里；就地作答之后，
  它换成刚落下的这一次。
- **右栏只出现纵向滚动条**：长题干与长选项在卡片里断行、不被裁掉，右栏自己不顶出横向滚动条。
- **并排装不下时给解释与出路**：画布窄到并排放不下右栏时，点「题目」得到的是**盖在正文上的抽屉**
  ——顶上写着为什么（窗口太窄、拉宽就并排）加一条「收起」，题目本身照样做得成；**静默失败不算实现**。
  抽屉一次只给最近点的那一栏（开一栏不顺手把早先要过的另一栏盖上来）。
- **让步不写回记忆值**，画布变宽自动回到并排。
- **不出现「两栏都打不开」的画布宽度区间**：任何宽度下，最近点的那一栏要么并排、要么以抽屉出现；
  并排的两条栏加起来也永远不挤破中栏的保底。

**让位顺序与阈值（右栏先拿、左栏先让、中栏保底；并排的极限在哪）的唯一出处是
[ADR-0011](../adr/0011-阅读端三栏让位顺序.md)**，本文不复述那些数字。

## 三、主页 / 科目主页 / 搜索

- **主页（工作台）第一屏就告诉去哪继续**：「接着上次」那张卡点得进去，落到的就是它说的那个节点；
  一次都没开始时卡上改说「从这里开始」。**这张卡取哪一门、放哪一格归
  [目标态规格](../设计/目标态规格.md) §4.1**（spec 里这页叫「今天学什么」，那是早先的措辞，已作废），
  本文只管「第一屏就得指得出路，且指的地方真去得了」。
- **空目录与半份数据给得出「没有」**，不是一片空白、也不是错误卡：空工作区说「还没有科目」
  并说清读的是哪个工作区；零节点的科目在卡上写明「还没有节点」；没有课件的节点在路线图卡上写明「无课件」；
  参考资料那一块给「还没有」。
- **搜索结果每一条都看得出它属于哪门科目、哪个节点**；无断点的长 URL 撑不破结果行，
  覆盖层不撑出视口。

## 四、四个面共同的

- **每一处文字在亮暗两套主题下都过得去对比度**：WCAG AA（4.5:1——这是标准给的比值，不是我们定的取值）。
  页面侧由浏览器套件按取样点合成背景后算实测比值，四个面 × 亮暗 × 各档视口逐场跑；
  token 侧的同一条纪律（每个文本 token 压在每个表面上）见 [目标态规格](../设计/目标态规格.md) §4.2。
- **动效四档可切并跟随系统偏好**：`auto` / `full` / `reduced` / `off`；显式档位记在浏览器本地偏好里，
  系统 `prefers-reduced-motion: reduce` 只影响 `auto` 档（显式的 `full` 不受它改写）。
  档位语义与「跟宿主保持一致」的来由见 [目标态规格](../设计/目标态规格.md) §4.4。

## 六、问答面板 · 引用的保持行为

引用（选中正文的那一段）在**捕获那一下冻成一条数据**：`{ 文本, 来源锚点 }`（锚点=哪一课、哪一小节）。
面板只渲染这条数据、只把它随问题一起送出去，**自己不去读实时选区**——面板一打开就会聚焦输入框，
那会儿实时选区已经没了。据此：

- **选中正文 → 面板的输入框上方出现一颗看得见的引用 chip**，上面写着它的来源小节；从正文发问时右栏的
  「问答」tab 自己滑出（附带一条浮动胶囊「就这段问一句」是入口，不是引用本身）。
- **只在选区确实落在正文里、且长度达标时才更新引用。** 太短的选区不算数——**当前取值**是不足四个字
  （按码位数），写在 [`lib/client.js`](../../lib/client.js) 捕获那一处；规范要的是「双击单词、误触这类
  噪音不该变成一条引用」，不是那个数字本身。
- **只跟下一条消息走**：同一段会话里只挂一条引用，**再选一段就把旧的换掉**，学生不用先删。
- **读到空选区不得清空已存在的引用**：在输入框里打字、点面板里别的地方、切到「题目」tab 再切回来，
  引用都还在。**病根就是这条**：文档级 `mouseup` 每次点击都会冒上来，而点输入框会让浏览器把选区折叠成空
  ——「这一次没划中」不等于「学生不要这段引用了」。
- **清除只有两处**：学生点引用上的「删掉」，或**这条消息真的提交出去**——提交那一刻引用已随消息进了会话，
  再留着只会让下一问带上上一问的。**不必等答成才清**：流式回答还没写完、甚至这条链路上没有可用模型，
  只要消息送出去了，这一颗就该让位给下一段。提交没成功（例如宿主把发送拦下、草稿被还原）时引用留着——
  那一次什么都没送出去。
- **提交时引用随这条消息一起进会话**（文本 + 来源锚点），**不写进学习工作区**，也不落进任何学习内容文件
  ——面板不再写误解记录（口径归 [目标态规格](../设计/目标态规格.md) §7.4）。
- **一次只引一段，不要求多段**；**没有引用时面板照样能用**（提问不带那一段，不写空壳锚点）。
- **没有可用模型时如实说明**：不假装会答、不编内容。
- 面板的上下文边界（课件用只读工具按需取 + 选中的这段随引用 chip 进消息 + 开张时注入的共享记忆）归
  [目标态规格](../设计/目标态规格.md) §7.4，本文不重复。

## 七、技能与工具的可见边界（指向工程约束）

**唯一出处是 [工程约束](工程约束.md) §二「技能与工具的可见边界」**，本文不复述。从本 spec 过来的人
只需要知道两件事：

- **技能可见范围由学习模式决定**（技能源住在学习预设自己的目录里），**不依赖「会话恰好不在这个仓库里」**
  ——这一条已达成。
- **工具、面板与 slot 不守同一条边界**：前提（宿主提供「按预设注册工具/面板」的接口）不成立，
  属**宿主侧缺口**，不改实现，改为把现状钉住。所以这一轮有两条**没整条达成**：用户故事 36
  （工具/面板/slot 守同一条边界）**未达成**；用户故事 37（一条自动化检查证明「别的预设里看不到
  StudyMate 的**技能与工具**」）**部分达成**——技能那一半由那条检查证明，工具/面板那一半它断的
  是反面（那条断言钉的是现状：标准预设的会话里也看得见）。
  为什么、现在是什么样、去向在哪，都在工程约束 §二那一节里；钉住它的是
  `scripts/tests/test_skill_visibility.mjs` 的最后一条断言（哪天有人收紧注册面，它会红）。
