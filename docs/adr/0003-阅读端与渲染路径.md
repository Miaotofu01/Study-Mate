# 阅读端走 Vue 组件，HTML 渲染器保留为宿主交付

Status: proposed（2026-10-02 设计会话）

桌面端需要能组件化的阅读端（路线图、课件页、测验、进度），而且一步到位。决定：桌面端阅读端自己实现（Vue 组件，暗色优先），与 [issue #22](https://github.com/Miaotofu01/Study-Mate/issues/22) 的网页阅读端**共享同一批组件与同一份数据**（`curriculum.yaml`、课件内容文件、题库、`progress.yaml`），**不把 VitePress 站点嵌进桌面端**（不做 iframe/webview 边界的双主题）。现有 Python 渲染器与 `templates/` 保留为三个宿主（DSH / Antigravity / Codex 与 ChatGPT）的默认交付与离线入口。

## Considered Options

- **桌面端内嵌 VitePress 站点**：与 #22 完全一致，目录与搜索白拿；代价是 iframe 边界、两套主题、额外一层构建，且「继续学习」这类跳转要跨帧通信。
- **继续用生成的课件 HTML**：零成本、零风险，但路线图、测验与进度无法组件化，桌面端就只是个浏览器。
- **废掉 HTML 渲染器只留 Vue**：工作最聚焦，但会打断三个宿主与「浏览器直接打开 `index.html`」的离线路径。
- **平板两可、以后再说**：把 #22 的阶段 3 提前到现在决定，风险是两套阅读端长期各长一半。

## Consequences

- **双渲染器漂移成为现实风险**（#22 已点名）：两个阅读实现必须只读同一份源文件，并在门禁里加一致性检查（例如课件正文里的题目锚点与题库逐字对应）。
- 课件语法仍以[课件内容格式](../规范/课件内容格式.md)为唯一来源（`:::` 指令、公式、图片池相对路径）；Vue 阅读端不许另立一套语法。
- 阅读端**只读**，不回写学习数据：进度、误解、会话摘要仍由总控按 `record-keeping` 写盘。
- 工程约束 §五 的「Sayo + 共享主题层渲染」仍是 HTML 一侧的口径；桌面端外壳用 Naive UI，阅读端组件与共享主题层的关系（是否复用 `learn-theme.css` 的变量）留到实现期定。
