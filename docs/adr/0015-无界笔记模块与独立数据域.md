# 无界笔记：正式模块、单入口构建与独立数据域

- 状态：本决策为首轮（#262）记录；后续首轮持久化由 [ADR-0016](0016-无界笔记持久化与单文件版本栅栏.md) 补充，懒分块加载由 [ADR-0019](0019-无界笔记懒分块加载.md) 补充（单入口不变），当前能力状态见设计 §0。

无界笔记以**正式模块**接入主线，首阶段只落**形状与边界**：共享源码、单入口构建、保留独立网页做自动化验收；
这一阶段未落持久化。
[无界笔记设计](../设计/无界笔记.md) 定义，本文不重述那些规则，只定**它落在哪、怎么构建、现在做到哪一步**。

正式范围是 [issue #262](https://github.com/Miaotofu01/Study-Mate/issues/262)；
[#261](https://github.com/Miaotofu01/Study-Mate/issues/261) 的历史原型只证明「交互可以隔离地做出来」，
**不构成正式模块的范围依据**，不能再拿它当实现许可。

## 决定

### 1. 共享源码住在 `client/notes/`，宿主适配单独一层

- `client/notes/` 是无界笔记组件的唯一源码，自现已清理的隔离原型组件目录迁入。
- `client/notes/host/bridge.jsx` 是**宿主适配层**：把宿主的会话能力与主题转成组件认识的 props。
  **正式 DSH 入口照旧复用已验证的原生会话适配**——`SessionProvider`、`conversation.content`、用户**显式选择**
  现有会话、引用只进会话草稿。这套原生能力**不退回占位**；本轮只是不做真实消息发送的验收。
- **「占位」专指独立网页验收入口**那一侧：那里没有宿主、没有会话，`ChatPanel` 是不连会话、不发消息的占位。
  两边复用相同组件，宿主差异由 `bridge.jsx` 适配；网页占位不是正式入口的实现。
- `client/` 是新的**一级目录**，与 `lib/` 并列：`lib/` 是引擎，`client/` 是浏览器侧组件源码。
  它**同样进架构边界扫描**（同一条 `test_architecture_boundaries.mjs`），是在那张域规则表里登记为
  「浏览器域」的一员，不是扫描之外的例外——边界规则见 [工程约束](../规范/工程约束.md) §二。

### 2. 单一 exports 入口，构建复用旧阅读端

- 正式包仍是 `@yunmiao/studymate`，`exports` 仍只有一条客户端入口 `./client`，指向 **`dist/client.js`**。
  不新增第二条客户端子路径——多一条路径就多一处「谁才是阅读端」的分叉。
- `dist/client.js` 由同一套构建产出：复用 `lib/client.js` 这个旧阅读端，把笔记子模块作为一段子区块打进去。
  两者同处一个 bundle、同一次产物登记，旧阅读端的加载顺序与注册方式不变。
- **React 与 DOM 留给宿主**（外置，同宿主版本），宿主本体保持**零运行时依赖**。
  前端依赖只许用**已登记的构建期依赖**（构建时内联进产物，不进宿主运行时）；Host 半不因此多一个运行时依赖。
- **CSS 限域**：笔记样式签进自己的类名前缀与容器根下，不落到阅读端与宿主的全局选择器上。
- **学习面板内切换**：无界笔记作为学习面板里的另一个面，不单独占宿主 `main` key 或侧栏入口。
  重启后的入口反馈确认了这一点（[#262 入口纠正](https://github.com/Miaotofu01/Study-Mate/issues/262#issuecomment-6849448141)）；
  注册规则归 [工程约束](../规范/工程约束.md) §二，品牌切换的呈现判据归 [阅读端呈现](../规范/阅读端呈现.md) §九。

### 3. 独立网页原型保留为验收入口

- `prototypes/unbounded-notes/index.html` 与 `vite.config.js` 保留，引用**同一份**共享源码（不再是 `src/` 的另一份副本）。
  它是浏览器的自动化验收入口：能在没有宿主、没有会话、没有模型的前提下把画布与笔记跑起来。
- 该页的 `ChatPanel` 明确是占位：不连会话、不发消息。**占位的范围只到这一页为止**——正式 DSH 入口走
  `client/notes/host/bridge.jsx` 的原生会话适配（决定 1）。旧临时插件已通过官方命令卸载，编译兼容目录也已清理，
  不再保留第二份原生入口。

### 4. 构建与测试入口

| 名字 | 用途 |
| --- | --- |
| `build:client` | 产出正式包的 `dist/client.js`（旧阅读端 + 笔记子模块） |
| `build:notes:preview` | 构建独立网页验收产物 |
| `dev:notes` / `preview:notes` | 独立网页的开发与预览服务 |
| `test:notes:browser` | 共享组件网页与组合学习面板品牌切换的真浏览器验收 |

纯函数测试（导入、媒体、编辑器行号、宿主契约）住在 `scripts/tests/`；浏览器验收套件是
`scripts/tests/browser/notes_test.mjs` 与 `scripts/tests/browser/notes_brand_test.mjs`。真实 DSH 已验收学习内品牌切换、双向保活/隐藏隔离及未选会话时不误发；**本轮不做真实消息发送的验收**。

### 5. 独立数据域的位置定了，内容留待持久化那一轮

- 笔记数据放在 **DSH 数据根下的独立目录**，与学习工作区、插件安装产物、作答数据、学习记录都不重叠。
- 数据域的边界与「谁可写」见 [目标态规格](../设计/目标态规格.md) §4.3 与 §4.6；路径登记见 [文件归属](../规范/文件归属.md)。
- 当时**未冻结**：目录名、文件布局、结构化文件的 schema 与版本迁移方式、宿主存储接口与恢复流程。
  这些由 [ADR-0016](0016-无界笔记持久化与单文件版本栅栏.md) 在持久化那一轮补充决策（产品侧清单在[无界笔记设计](../设计/无界笔记.md) §8.1、§12.2），本文刻意留空。

## 当时状态（首阶段，历史记录）

- **笔记当时是内存数据**：刷新即重置，不写盘（现状态见设计 §0）。它不是「已经能用的笔记」，不要在这里存唯一副本。
- 归属交接、回收站、版本冲突、跨窗口并发、撤销以外的恢复、搜索索引——都未实现。
- 没有独立的 DSH 数据域读写路由（首轮由 [ADR-0016](0016-无界笔记持久化与单文件版本栅栏.md) 新增 `/api/studymate/notes`），没有新增 schema，没有 agent 侧自动读写笔记的工具。
- **正式 DSH 入口的会话适配保留**（原生会话、显式选会话、引用只进草稿），真实会话历史与消息发送的端到端验收尚未执行；
  本轮不做真实消息发送的验收，网页那侧的 `ChatPanel` 仍然是占位。

## 为什么不选另外两条路

- **笔记留在 `prototypes/`，只在网页里跑**：省了构建，但正式模块就没有源码位置，宿主一侧（`./client`）永远接不进来；
  #261 那次隔离验证已经证明「能做出来」不等于「能进主线」。
- **给笔记开第二条 exports（如 `./client/notes`）**：宿主得多认一个入口、两份产物各有一套加载与样式生命期，
  「谁是阅读端」立刻出现第二个答案。单入口让两者同生同灭。
- **当时不冻结笔记数据域（目录名 / layout / schema）**：持久化要解决的问题（并发、归属交接、恢复）还没验证，
  先冻结等于把猜测写进规范。位置先定（DSH 数据根下独立目录），内容留到那一轮再定（后由 [ADR-0016](0016-无界笔记持久化与单文件版本栅栏.md) 冻结）。

## Consequences

- **一处定义**：产品语义看 [无界笔记设计](../设计/无界笔记.md)；模块、构建、目录的工程约束看
  [工程约束](../规范/工程约束.md) §二；数据域边界看 [目标态规格](../设计/目标态规格.md) §4；呈现判据看
  [阅读端呈现](../规范/阅读端呈现.md) §九；每个文件的维护者看 [文件归属](../规范/文件归属.md)。本文只写决定，不写第二份规则。
- **正式入口不降级**：`./client` 里那一侧继续用已验证的原生会话适配，「做笔记」不是把会话能力退回占位的理由；
  占位只出现在没有宿主的网页验收入口。
- **不改学习内容与写入面**：组合客户端的顶栏品牌负责学习／笔记两面切换，学习内部的课程、阅读位置与数据语义保留。
  独立导出的纯阅读端没有笔记模块，不出现无效切换入口。
  笔记的写权限是**新开的一域**，不从 `reference/` 与作答数据那两条路径借道（[ADR-0010](0010-阅读端可直接写参考资料.md) 的范围不变）。
- **安全边界继承原型且不放宽**：静态媒体若走 iframe，`sandbox=""`；不执行 JavaScript、不加载外网；
  权限失败时不发送缓存内容。这些是验收条款，不是实现细节。
- **独立网页是验收设施，不是第二个交付形态**：它不改变 [ADR-0003](0003-阅读端只嵌DSH.md) 的「阅读端只嵌 DSH」，
  也不改变 [ADR-0013](0013-Web运行时移出主线.md) 对「独立 Web 运行时」的定性——那份是自带引擎的第二形态，这份只是验收夹具。
- 完成前不宣称持久化完成：使用说明与 README 不得把未验收的能力写成既有功能。

## 以后要动的时候

- 冻结数据域（目录名、layout、schema、迁移）：单独立决策（已由 [ADR-0016](0016-无界笔记持久化与单文件版本栅栏.md) 承接），先改目标态规格 §4.3 与文件归属表。
- 补正式入口的端到端验收（真实消息发送）：在保留的原生会话适配之上补，不把它换回占位；
  形状照宿主的会话契约验（[工程约束](../规范/工程约束.md) §三「宿主契约」）。
- 归属交接、冲突、回收站：按产品设计的顺序推进，每一条都要有自己的验收场景。
