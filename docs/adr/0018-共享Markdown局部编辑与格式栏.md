# 共享 Markdown：局部语法显现与单格式栏

- 状态：已接受，已实施；已通过默认门禁及使用临时库的真实 Edge 验收。
- 范围：[issue #270](https://github.com/Miaotofu01/Study-Mate/issues/270#issuecomment-6875163063)。
- 前置：[ADR-0017](0017-学习节点笔记与共享即时编辑.md)。其集中数据域、原稿唯一、课程身份、一个保存者及格式 2 升级规则不变；本文接续其中编辑器交互与底层选择。
- 接续：[ADR-0022](0022-无界笔记文档视图与课程关系.md) 补充独立文档视图，快速编辑侧栏的局部编辑模型不变。现行功能说明见[无界笔记设计 §7](../设计/无界笔记.md#7-markdown-编辑与外部来源)，呈现判据见[阅读端呈现](../规范/阅读端呈现.md) §九。

## 背景

首轮 Crepe 富文本编辑把 Markdown 分隔符转成节点和标记，格式工具只能修改富文本结构。用户进一步确认：文件标题下需要常驻格式栏；光标所在的格式片段要露出可直接修改的灰色 Markdown 字符，正文仍保留排版，周围片段不转为源码。整段源码切换或不可编辑的装饰字符都不满足这个要求。

Crepe `7.23.0` 的 TopBar 已有标题、粗体、链接等常驻命令，可参考其功能组织，但开启 TopBar 不会恢复原始分隔符。继续在富文本树上模拟原文会引入位置映射和序列化规范化，不适合作为本轮原稿真相。

## 决定

### 1. 原 Markdown 字符串直接作为编辑文档

复用现有构建期 CodeMirror 6、Markdown 解析与语法高亮，不另加 Host 依赖、数据域或保存队列。编辑器持有原始 Markdown 的字符坐标，格式操作在这些坐标上形成一个可撤销事务；不通过富文本全篇序列化来生成新正文。

仅打开、移动光标、选区、显隐标记、主题改变与自身 props 回传不得调用正文保存。真实输入与格式操作才提交新原文；未改动范围的字符和换行必须保留。超限拒绝而非截断，中文输入与异步外部更新不得覆盖新草稿。

### 2. 只显现当前格式片段的真实标记

Markdown 解析决定格式范围，不能用星号正则把代码或转义内容错认成粗体。未活动的格式片段正常排版并隐藏分隔符；光标或选区触及的格式片段只露出对应的真实、可编辑分隔符，颜色置灰，格式文字仍保持粗体、斜体等排版。邻近未触及的标记继续隐藏，不将整段切成源码。

删除或修改这些字符必须真的改变 Markdown 和随后的排版；不能把不可编辑的 widget、伪元素或覆盖层当成可编辑字符。标题、列表、链接、代码及 GFM 内容按各自格式范围处理。无法安全渲染的扩展内容保持原文可读，不静默丢弃。

### 3. 文件标题下只有一条格式栏

无界与学习侧栏共用 `NoteEditor` 和原有保存者；选择单一常驻格式栏而非富文本状态专用工具，避免引入第二套正文模型。侧栏不再以多模式切换替代局部编辑；独立文档视图后来由 [ADR-0022](0022-无界笔记文档视图与课程关系.md) 补充。现行操作与外观分别由设计 §7 和呈现规范 §九定义。

### 4. 不放宽主题与安全边界

亮暗跟随宿主；灰色标记、格式控件和正文同样满足正常文字对比度要求。HTML 不执行，图片不因渲染而加载外网，链接只在显式安全操作下跳转，公式沿用现有 KaTeX 预算。只读引用和旧格式库不能通过格式命令写入。

## 验收

- 真浏览器验证只有当前格式片段显现、灰色字符确实可编辑、文字保留排版、其他片段不转为源码；表格、代码与块公式之后的末行格式文字也以原生中心点击验收，不靠行上缘绕过命中问题。
- 文件标题与格式栏下的正文内外均无卡片背景、圆角外框或阴影，聚焦后也不恢复外框。
- 格式按钮、选区保持、空选择、撤销重做、标题和链接、转义与代码中的标记、换行与未改动字符。
- 原稿空字符串、只读、超限、中文输入、自身回传和外部更新、快速切走与组件销毁。
- 学习与无界共用原稿，显隐和主题切换不新增保存请求；离线图片、公式、表格与代码安全呈现。
- 所有写入和截图仅使用临时库，不读取用户笔记或连接真实模型。验收状态最终回写设计 §0，未验证的能力不写成已完成。

## 不选的方案

- 只加 Crepe TopBar：能提供格式按钮，不能让原始分隔符成为编辑文档。
- 整段切换为 Markdown 源码：不符合用户明确收窄后的局部显现。
- 用伪元素显示灰色 `**`：看得见但不能编辑，仍无法直接修改格式。
- 为学习侧栏另建正文与保存队列：违背 ADR-0017 的同稿与一个保存者。

## 代价

源码为真相需要承担语法装饰、渲染区域、光标及组合输入的回归。格式栏借用参考项目的功能组织，而不直接调用其依赖富文本状态的命令；实现和测试必须依据原 Markdown 字符坐标。首轮 Crepe 的选择保留在 ADR-0017 作为历史记录，不把已经证明的旧模式验收冒充新交互已通过。
