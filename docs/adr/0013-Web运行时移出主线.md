# Web 运行时移出主线，作为自带引擎的第二形态

独立 Web 运行时（`study-mate-web/`）曾作为「第二条前台」直接落在 `main` 上，但它自带一套 Python 引擎：建课链、产课链、总控会话与状态机各一份，还要把老 Python 脚本当叶子复用。这与主线「一个引擎」的口径冲突（[ADR-0003](0003-阅读端只嵌DSH.md) 否掉独立 Web 应用，[ADR-0005](0005-静态页面降为导出.md) 否掉双渲染），而引擎换 TypeScript 那一轮又把那些 Python 叶子整体删掉。决定：把它从 `main` 移出，另存分支 `web/0.7.0-beta`，定位为**自带引擎的第二形态**——默认形态仍是 DSH 插件端。

## 回流条件

满足以下两条才合回 `main`：

- **必须单一来源**：`schemas/**`、学习工作区布局、[课件内容格式](../规范/课件内容格式.md)、角色规格（`preset/skills/**`）、题库与作答格式。这几样改了 Web 侧要跟着改，不许有第二份。
- **允许各写一份**：产课链、会话/总控、判分的实现。Web 那套 Python 引擎属于这一类，它可以自带一份渲染与校验叶子。

回流之后 `main` 上是两个形态并列，不是一个引擎被另一个吸收。

## 回流手法

**直接 `git merge` 那条分支是空操作**，别这么干。分支的合并基就是它当初落上 `main` 的那个提交，而 `main` 上紧接着有一条撤销提交（`revert(Web运行时)` 那条），两边一比，git 认为「这边已经把 Web 删了、那边相对合并基什么都没改」，合完树上什么都不发生。

要么把分支 rebase 到当时的 `main`，要么在 `main` 上显式 revert 掉那条撤销提交。

## Consequences

- 非 DSH 宿主的学生仍然只有导出这条路（[ADR-0003](0003-阅读端只嵌DSH.md) 不变）；Web 形态是另一条独立的浏览器路径，不是它的替代。
- 两套引擎会各自演进，同一份学习工作区被两边读写。收口只有「回流条件」那两条，这是本决策接受的代价。
- 本仓的规范本体（[目标态规格](../设计/目标态规格.md) §2.3 的多宿主分档、[工程约束](../规范/工程约束.md)）暂不为 Web 留位置——它不在仓里。等它合回来再改那两处。
- 分支上自带的自动检查（`web-ci.yml`）随分支保留，推 `study-mate-web/**` 时照常跑。
