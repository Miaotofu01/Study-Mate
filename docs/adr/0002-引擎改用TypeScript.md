# 引擎改用 TypeScript

引擎今天是一套 Python 脚本（17 个，含 1426 行的课件渲染器与 1056 行的课件检查器），由总控用 bash 调用、靠退出码判断成败。决定：**整体迁 TypeScript**，注册为 DSH 插件的原生工具，Python 退役。

## Considered Options

- **分家**：Python 留作数据与门禁层，TS 只接管内容解析与渲染。省一半重写量，但两套语言、两套测试、两套依赖要长期并存，而"读同一批文件"的边界会一直漂移。
- **保留 CLI**：TS 只产出一个命令行，总控继续用 bash 跑。技能几乎不用改，但拿不到结构化返回，也走不了 agent 沙箱之外的写盘。
- **双轨长期并存**：不删 Python。等于放弃这次重构的一半收益。

## Consequences

- 4000+ 行脚本、40+ 套回归测试、CI 里的 Python 步骤全部重写。
- 技能里所有"跑哪个脚本、看退出码"的句子作废，必须同步改写（次序见[实施路线](../设计/实施路线.md)阶段 6）。
- 收益：校验与渲染变成同一门语言里的纯函数，可被工具、界面与导出三方共用——今天它们分散在三个互不知情的地方。
