# 共享记忆改名 `MEMORY.yaml`（破 ADR-0004 的文件名冻结）

工作区根的共享记忆从 `.learning/MEMORY.md` 改名为 **`.learning/MEMORY.yaml`**，内容改成 **YAML 分节**存放；
随包的骨架（`templates/` 下的 `MEMORY.md`）同步改名为 `MEMORY.yaml`。**节一个都没换**，仍是
「我是谁 / 教学偏好 / 学习习惯 / 跨科目观察」，只是节名从 `##` 标题变成了一级键。

> **后续（[#190](https://github.com/Miaotofu01/StudyMate/issues/190)）**：这一节里的「跨科目观察」撤掉了，
> 换成「积累」（一条 = 中文键 + 一句话，写换一门课仍成立的做法与事实）。注入边界同时收窄：
> **只有画像三节**（我是谁／教学偏好／学习习惯）进上下文，`积累` 与整份科目记忆永不进注入——判据在
> 纯函数域的 `lib/core/memory.ts`，三处**取内容**的消费点（答疑注入、工作区摘要工具、图片库载荷）按同一份
> 投影走，见[目标态规格](../设计/目标态规格.md) §7.4。监听域（`lib/watch/domains.ts`）是第四个会点到这份
> 文件的地方，但它只按**文件名**认它、一个字节的内容都不带——它回答的是「哪一片变了」，不是「取哪几节」，
> 那里没有投影可用。ADR-0004 的破例范围仍是「只破文件名这一处」。
>
> **后续（[#191](https://github.com/Miaotofu01/StudyMate/issues/191)）**：科目的那一半也落地了——
> 每门科目目录下一份 `MEMORY.yaml`（只有 `积累` 一节，写**只对这门课成立**的做法与事实），
> 建科目时从 `templates/subject-MEMORY.yaml` 预置一份带注释的空骨架（源名带范围前缀，因为工作区里
> 两份记忆同名，`templates/` 下不能有两个同名文件）。这是 ADR-0004 布局冻结的**第二处破例，但是新增**：
> 它不改任何已有文件名、旧工作区没有这份文件也照样开（读侧按需存在），所以「旧工作区零迁移」那条承诺
> 原样成立；**目录结构与已有 schema 仍不动**（新增 schema 不属于「改动已有 schema」，边界见
> [ADR-0021](0021-课件页标注与作答数据族扩员.md)：只新增、不改已有），科目目录里除这一个可有可无的文件之外的一切照旧。
> 科目记忆与 `积累` 一样**永不进任何上下文**——监听域给它单开一域（`subject-memory`）而不是并进
> `memory`，正是因为那一域的名分是「注入源变了」。

为什么非改不可：下一步要把这份记忆拆开用——**画像进上下文、干活笔记不进**。今天的形状
（`##` 标题 + 自由 bullet）没有机器可读的节边界，谁想按节取用都得自己写一个 Markdown 解析器，
而节里写什么全凭行文，取出来的是没法对账的一段散文。键是 YAML 给的：节名、节里的条目标题
（「现有技能」「各领域当前水平」…）都成了结构，取哪几节是查表，不是猜。

这是 [#189](https://github.com/Miaotofu01/Study-Mate/issues/189) 定下的。

## 破 ADR-0004 的边界

[ADR-0004](0004-学习数据格式冻结与例外.md) 的承诺是「学习工作区的布局、文件名与目录结构不动」。
本次破的是那句话里的**文件名**一处，范围写死：

- **动的**：`MEMORY.md` 这个名字（模板名与工作区里的名字一起动），以及这份文件自己的内容形状。
- **不动的**：目录结构（`.learning/`、`.learning/subjects/<slug>/` 与科目里的一切）、**已有 schema**、
  其它任何文件名。ADR-0004 的冻结除这一处与它自己那条状态词表例外之外**仍然有效**。
  （本节原文写「五份 schema」：按当时已有的那几份理解。添加新 schema 是 ADR-0004 的另一类破例，
  边界见 [ADR-0021](0021-课件页标注与作答数据族扩员.md)；已有 schema 仍然一个不改。
  作答文件里给已有 schema 加可选字段（`草稿` 与 `作答`）是第三类，边界见 [ADR-0020](0020-作答文本-草稿是状态快照才是事件.md)。）

## Considered Options

- **兼容旧名一段时间**（读侧先找 `MEMORY.yaml`、没有再退回 `MEMORY.md`）：迁移期零成本，但盘上会有
  两个都叫「共享记忆」的位置，读侧那条兜底分支没有自然的删除时机——它能一直活下去，于是「改名」
  永远只完成一半，第三份夹具、第四处注释会继续照旧名写。要断就断干净：读侧不兜旧名、不留兼容分支，
  旧名从此就是一份普通文件。
- **不破冻**：名字和形状都不动。两条路都不行——把 YAML 塞进 `.md` 是让文件名说谎；继续用 `##` 分节
  就是上面那个「没有机器可读的节边界」的问题原样留着，而这次改名的全部理由就是它。
- **连目录结构一起重划**（顺手把 `.learning/` 改个名、把科目文件也搬一搬）：ADR-0004 要保护的是
  学生真实积累的学习档案；为了省一次改名而动整片目录，代价与收益不相称。

## Consequences

- **旧工作区要自己改个名**：一条 `mv .learning/MEMORY.md .learning/MEMORY.yaml`。不随包提供迁移脚本——
  改的是名字，节一个都没动；而读侧拿这份文件当**文本**读（注入、摘要、载荷都取原文），改完名原样能读。
  真到了按节取用那一步，内容形状才需要跟着模板走。
  （**2026-11-15 审计后已补 `migrate` 命令与读侧兜底，见文末「后续」**——#190 之后「按节取用」已经落地，
  这条的前提不再成立。）
- **读侧不认旧名**：`.learning/MEMORY.md` 不再被当成记忆——答疑会话不注入它、摘要工具回报 `present: false`、
  图片库载荷里是空串、监听域把它报成普通的 `workspace` 变更。这几条各有断言钉住，其中一条是**否定式扫全仓**
  （`scripts/tests/test_memory_rename.mjs`）：活文件里一处旧名都不许留。于是旧名只剩三类地方能出现——
  生成的历史（`CHANGELOG.md`，不许手改）、决策记录（ADR 必须同时写出旧名与新名）、自述为历史或当轮快照的文档；
  外加两处**反证输入**（监听域要它落回 `workspace`、答疑注入不该读到它），它们是故意把旧名喂进去的。
  （**2026-11-15 起读侧兜底旧名，见文末「后续」**；否定式扫全仓的豁免名单也随之扩到兜底/迁移的源码与文档。）
- **模板名要三处一起动**：DSH 侧与两个无头宿主插件（Codex/ChatGPT Work、Antigravity）都按名复制
  `templates/MEMORY.yaml`。漏一处，那边的「首次初始化」就会去找一个不存在的模板。
- **宿主契约不动**：摘要与载荷里的字段名（`markdown`、`memory_md`）保持原样——它们是插件与阅读端之间的
  字段契约，这次改的是盘上的文件名，不是契约。名字里的 `md` 因此暂时与文件后缀不一致，属于已知的措辞债，
  等真去动那份契约时一起收。

## 后续（2026-11-15，2.0.4 兼容性审计）

**上面「读侧不认旧名」「不随包提供迁移脚本」两条，在真实用户盘面上被证明会丢数据。** 触发条件不是改名
本身，而是 #190：读侧改成按 YAML 节取用之后，旧文件的内容形状（`##` 分节 + bullet）与新格式不同——
只把文件改个名读不出来。审计用插件自己的解析器复现：把旧工作区的 `MEMORY.md` 喂给 `readMemory`，
得到 `sections=[]`，画像三节与「积累」全部 missing；2.0.x 用户升级后，这些东西会**静默全丢**。

补丁是**读侧兜底 + 一次性迁移**，边界仍按这次改名的原意收紧（不是回到「两个名字长期并存」）：

- **读**：`MEMORY.yaml` 优先；它不在而旧文件在时，按旧格式转换成新格式后读（`lib/memory-file.ts` +
  `lib/core/memory.ts` 的纯函数），每个进程提示一次「请迁移」。写侧仍然只写新文件——兜底没有写回路径。
- **迁**：`npx -y @yunmiao/studymate@latest migrate`（`lib/memory-migrate.ts`）。四条承诺：不覆盖已有
  新文件、幂等、不丢内容（转不了的进 warning 或原样带过去，旧文件整份留底）、可回滚（删新文件、`.bak`
  改回旧名）。`跨科目观察` 并进「积累」，规范之外的旧节原样保留为同名节并给 warning。
- **旧名在仓库里的边界**：只许出现在兜底/迁移的源码、迁移命令帮助、升级文档与反证输入；
  `test_memory_rename.mjs` 的否定式扫全仓据此逐条豁免（每条都写了理由），其余活文件一个字都不许有。
- **监听域仍只认新名**：迁移期手工改 `.learning/MEMORY.md` **不触发**阅读端的记忆域刷新
  （`lib/watch/domains.ts` 按 #189 把旧名当普通的 `workspace` 变更）。App 自己写的一直是新文件，
  受影响的只有「手工改旧文件」这一种；兜底读仍生效，只是刷新要等下次打开。
- **读不出来要说出来**：旧文件里连 `##` 分节都没有时，转换不出任何一节——摘要与日志的提示
  必须说「读不出来」并给出 `migrate --dry-run`，不许沿用能迁移时的「内容不丢」。
- **结束时间**：这是迁移期的例外，不是第二个格式。等迁移命令随版本发布一个周期、旧工作区都迁完，
  兜底分支与豁免名单一起删——删的时候把本节的边界原样收回。
