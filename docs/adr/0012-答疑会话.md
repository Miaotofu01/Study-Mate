# 答疑会话

阅读端的问答面板从「一次一问一答」改成**宿主的一条真会话**：插件在宿主半注册第二条预设（「答疑模式」），
由它决定这段会话的工具面与身份；会话由插件宿主半按预设建出来，面板嵌宿主自己的会话正文
（`conversation.content` 加框架的 `SessionProvider`），只 retain 这一条。选中的那段做成**引用 chip**，
只跟下一条消息走。

这是 [#102](https://github.com/Miaotofu01/Study-Mate/issues/102) 定下的；早先那三条口径
（面板独立调模型、只带三样、回答无痕）由它正式改写。

## Considered Options

- **插件自建多轮**（面板自己拼 messages、自己发请求、自己渲染消息流）：多轮历史、流式逐字、滚动、草稿、
  附件这五样都要重写一遍。它们在宿主里已经存在，而且正是学生每天在侧边栏用的同一套；自建版要么长得不一样，
  要么慢慢往宿主那边漂——而漂的方向就是这次要退役的那条 HTTP 路由与它那份上下文组装。
- **保持一次一问一答**：最省事，但学生追问「那它跟上一句冲突吗」时模型不记得刚才说过什么；
  关掉面板、切个 tab，刚才那段对话就没了。这正是要修的那个落差。
- **把会话搬进中栏**：正文与会话抢地方。右栏本来就是「做题与提问的那一栏」，
  三栏让位照 [ADR-0011](0011-阅读端三栏让位顺序.md) 不动。

## Consequences

- **真会话会落盘**：宿主没有「临时会话」这一档（持久化只看 `sessionPersistence` 服务挂没挂），
  所以每段答疑都会写进 `~/.dsh/sessions/<projectKey>/<id>/session.vN.jsonl.zstd`。
  好处是刷新页面不丢；代价是这些对话与学习数据一样躺在磁盘上。
- **它会作为普通会话出现在侧边栏**：宿主列表只过滤 `origin === 'subagent'`，而那个字段会让通用 prompt 路由
  以 `session/agent-busy` 拒答——靠它换侧边栏干净，等于这段会话聊不起来。标题写成「答疑 · 科目 · 节点」
  （`ISession.rename`），「上一段会话」与「一眼分得出」都靠这个前缀认。
- **「答疑模式」预设藏不住**：`PresetDefinition` 没有 hidden/visible 字段，注册进名册就会被列出来，
  出现在预设选择器与设置页的「自定义」组里。这是宿主侧缺口；我们把它当成一个学生也能自己开的模式，
  而不是藏起来。
- **上下文边界改由三处拼出来**：课件用只读工具（`studymate_lesson_read`）按需取；选中的那段随引用 chip
  进消息；共享记忆在会话开张时由插件宿主半注入一条。插件不再往会话里塞整篇课件，也不再自己拼一份「请求体」。
- **面板不再写误解记录**：`misconceptions.yaml` 的其余写入方（讲解反馈、实验课验收）照旧。
  `local-qa` 里「答完写一条记录」与「同一知识点问到第三次交给总控」两条随之退役——学生真卡住了，
  自己回会话里说。

## 难在哪、回退的代价

它压在四条宿主能力上（读 DSH `0.2.0-rc.2` 源码得出，没在真宿主里逐条跑过）：

1. **按预设建会话**：宿主请求类型与线上 schema 都收 `agentPreset`，但客户端那份 `sessions.create`
   只序列化 `{workspaceId, cwd, sessionId}`，会静默丢掉这个字段——所以建会话必须在插件宿主半做。
   哪天客户端补齐了这个字段，这条可以简化。
2. **按会话地址嵌正文**：`conversation.content` 不接受会话 id，要指向别处那条会话必须用框架给的
   `SessionProvider`，而它只发给「注册声明了至少一个非 root 子座位」的组件。宿主 README 把这件事列在
   **Deferred Work**；我们在用的依据是两个官方插件（`ui-subagent`、`sidebar-right`）也这么做。
3. **引用来源是全局的**：注册的名字不能撞宿主的 `reference`/`skill`/`command`，且**提交那一刻必须还在注册着**
   ——名字撞车或提前注销都会让发送被拦下、草稿还原。
4. **共享记忆靠注入一条消息**：注入时机是「下一个 pre-step」，文档写明可能错过已经领走这一批的 pre-step，
   所以学生开张后立刻提问时可能看不到它。这是已知竞态，先接受。

**回退的代价**：若 `SessionProvider` 那一路被宿主收紧，退路是**面板自己渲染消息流**——流式、滚动、
引用 chip 全自己写，等于把上面五样重抄一遍；再往后退，是恢复那条已退役的 HTTP 路由与上下文组装。
两条退路都把插件从「编排宿主的会话」推回「自己实现一套会话界面」，而这正是本决策要避免的。
