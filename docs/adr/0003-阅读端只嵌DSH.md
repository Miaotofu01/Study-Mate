# 阅读端只嵌 DSH

阅读端做成 DSH 的客户端插件：**两个宿主入口复用同一个阅读端，不另做前端**。左侧「学习」保留全宽主面板；支持原生右栏的 DSH Web 在右栏「开始」页提供「学习」，可与会话并排。Antigravity 与 Codex·ChatGPT Work 继续使用无头 CLI 和静态导出。

## Considered Options

- **双形态**（DSH 插件 + 可独立跑）：一套组件两处用，但工程量最大，且独立形态拿不到宿主的主题 token 与 slot 契约。
- **独立 Web 应用**：与 DSH 解耦，但失去"会话与阅读并排"和"选中正文即问"的体验，还要自建配置与身份。这条否掉的是「拿它替掉插件里的阅读端」；仓库里另有一条自带引擎的 Web 运行时，见 [ADR-0013](0013-Web运行时移出主线.md)。

## Consequences

- 非 DSH 宿主没有阅读端，它们的阅读体验依赖导出（见 [ADR-0005](0005-静态页面降为导出.md)）。
- **全宽和并排各有入口**：`main` 同一时刻只显示一个 key，全宽阅读端仍与会话互相切换。Web 右栏使用宿主的原生标签和现有宽度，复用阅读端的窄布局；不另加工具栏按钮或宿主路由。
- 右栏入口对所有 Web 会话开放，不受项目或预设限制。展开和标签布局归宿主按会话记忆；两个入口读取同一个已配置学习工作区，阅读位置仍由阅读端管理。没有原生右栏的宿主继续用原有全宽入口。
- 界面只能跑在 DSH 里：浏览器回归必须起真宿主或等价的预览环境，不能只开一个静态页。（**这条只管插件里的阅读端**；Web 运行时那份界面是另一条线，见 [ADR-0013](0013-Web运行时移出主线.md)。）
- 本决策的禁令只管 DSH 的阅读端。仓库里曾把一套自带引擎的独立 Web 运行时落上 `main`，现已移出到分支，定位与回流条件见 [ADR-0013](0013-Web运行时移出主线.md)。
- 宿主仍是发布候选版本，slot 名与宿主包接口不做长期假设；只依赖 `--dsw-alias-*` token 与自己写的组件。
