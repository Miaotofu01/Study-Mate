# 阅读端只嵌 DSH

阅读端做成 DSH 的客户端插件，**不做独立 Web 应用**。Antigravity 与 Codex·ChatGPT Work 走无头 CLI + 导出静态页面，先维持可用、后单独演进。

## Considered Options

- **双形态**（DSH 插件 + 可独立跑）：一套组件两处用，但工程量最大，且独立形态拿不到宿主的主题 token 与 slot 契约。
- **独立 Web 应用**：与 DSH 解耦，但失去"会话与阅读并排"和"选中正文即问"的体验，还要自建配置与身份。

## Consequences

- 非 DSH 宿主没有阅读端，它们的阅读体验依赖导出（见 [ADR-0005](0005-静态页面降为导出.md)）。
- **阅读端与会话是切换关系，不是同屏并排**：阅读端占 `main` 槽位的一个 key，而 `main` 同一时刻只显示一个 key，`conversation` 是宿主保留键。想同时看见两者，只能把阅读端降级到会话区的标签页或右侧栏——两者都比占 `main` 更局促。这是本决策换来的代价，也是它最容易被事后质疑的一处。
- 界面只能跑在 DSH 里，浏览器回归必须起真宿主或等价的预览环境，不能只开一个静态页。
- 宿主仍是发布候选版本，slot 名与宿主包接口不做长期假设；只依赖 `--dsw-alias-*` token 与自己写的组件。
