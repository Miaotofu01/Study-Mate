# 作答文本：草稿是状态，快照才是事件（给已有 schema 加可选字段）

主观题（开放题、交付物、预测验证）允许学生写一段最长 **8192 个码点**的文本。文本落两处：一处是
**作答事件**——`attempts/<NNNN>-<节点id>.json` 里历史条目与 `上次结果` 各自可选的 `作答`；另一处是
**当前草稿**——同一文件顶层的 `草稿`（题 id → `{文本, 时}`）。两类都只给已有 schema 加可选字段：
不新增文件、不新增 schema、不改任何已有字段的类型与语义、旧工作区零迁移。

这是 [#213](https://github.com/Miaotofu01/Study-Mate/issues/213) 的实现记录，落地在
[PR #305](https://github.com/Miaotofu01/Study-Mate/pull/305)。判分规则一个字没动：文本不参与判对，
`对` 仍取自评第一档（见[目标态规格](../设计/目标态规格.md) §5.3）。

## 与 ADR-0004 / ADR-0014 / ADR-0021：已有的 schema 加可选字段，是第三类破例

三处规则各自的字面是：

- [目标态规格](../设计/目标态规格.md) §5.3 把 `attempts/<NNNN>-<节点id>.json` 与课件一一对应，
  每题记「题 id / 状态 / 作答历史 / 错因 / 上次结果」，**没有草稿这一项**；
- [ADR-0014](0014-共享记忆改名MEMORY.yaml.md) 把 ADR-0004 的 schema 冻结收窄成「已有 schema 仍然一个不改」；
- [ADR-0021](0021-课件页标注与作答数据族扩员.md) 把「新增 schema」定为 ADR-0004 的例外，并把边界写成
  「已有 schema 不动」。

本条**不是新增 schema，也不是新增文件或目录**；它是对已有 `attempts` schema 的字段扩员。按字面读，
「已有 schema 一个不改」会把「加一个可选字段」也拦住；按 ADR-0014 / ADR-0021 的本意读，冻结要保护的是
**已有字段的语义、必填形状与旧文件可读性**，不是让 schema 永远不能长出新字段。这个缝必须由一份 ADR 钉死，
否则以后每个可选字段都能自称「不是改动」。本 ADR 就是这条边界，后续同类以它为准，不是新的冻结。

边界写死：

- **动的只有一处**：`schemas/attempts.schema.json` 里的三个可选字段——历史条目的 `作答`、
  `上次结果` 的 `作答`、顶层 `草稿`。三者都带 `maxLength: 8192`，都**不 required**；
- **不动的**：已有字段的名字、类型、枚举、必填关系与语义；`attempts/` 的文件名、目录结构与
  「一课件一文件」的对应关系；其余任何 schema；`templates/` 的骨架；
- **旧文件照读**：没有这三个字段的旧 attempts 文件不需要迁移，读侧按需存在（`undefined` / 缺省），
  写回时也不会凭空补默认值去改写旧文件；
- **未来同类**：给已有 schema 加可选字段，必须回到本 ADR 的清单逐条对照（只加可选、不改语义、零迁移、
  有上限、读侧按需），并写明为什么不能放进新 schema。超出这条缝的（新增 schema、加必填、改类型、
  改文件名）仍走 ADR-0004 / ADR-0021 的原有例外，不由本 ADR 授权。

## 三个落点：事件归事件，状态归状态

| 落点 | 是什么 | 什么时候写 | 进不进历史 / 上次结果 |
| --- | --- | --- | --- |
| `历史[].作答` | 一次**离散动作**留下的快照 | 自评这类动作发生时（代跑只写 `跑`） | 进历史，一条动作一条 |
| `上次结果.作答` | 历史末条的同源快照 | 与 `上次结果` 一起，不单独写 | 就是历史末条 |
| 顶层 `草稿` | 学生正在写的**可改状态** | 防抖到点、失焦、失败退避重试 | 都不进 |

- **历史 `作答`**：只在自评这类离散动作落一条；代跑那条写的是 `跑`，不写 `作答`。开放题与交付物写
  `作答`，预测验证仍写 `预测`，两者不混。它不是按键流水，不记录每一次输入。
- **`上次结果.作答`**：沿用「上次结果 = 历史末条」的同源约定，不做独立字段、不单独写。因此它一定与
  某一条历史快照逐字一致；读侧不需要也不允许把它当成另一份真相。
- **顶层 `草稿`**：题 id 到 `{文本, 时}` 的映射。它可被覆盖、可被清空，**不是事件**：不 push 历史、
  不改 `上次结果`、不参与「上次结果 = 历史末条」的同源约定。把它放顶层而不是塞进 `上次结果`，是为了
  不把 `上次结果` 改成可空、也不让一个可改状态伪装成一次作答。
- **不新增导出通道**：导出没有单独的草稿出口，离线页对作答写请求一律回 403，原话是「这次作答只留在
  当前这一屏」（`lib/export/page.ts` 的 `hostScript`）。但导出快照就是整份 `readLibrary()` 结果，
  `attempts` 顶层本来随快照走，草稿作为其中一个键也会被带出（与作答历史同）；它只是快照里的只读一格，
  不会被离线页写回。要把草稿从快照里摘掉，得改 `lib/export/**` 或给 `readLibrary` 加导出专用选项，
  不在本 PR 范围。

判分三轨不变：文本只用于回顾与带进答疑，不参与判对；`对` 仍取自评第一档；没有文本的旧条目照常渲染。

## 上限 8192 码点：写侧截断，不拒绝

- 上限按**码点**数，不按 UTF-16 码元。`😀` 这种代理对在旧客户端会算 2，导致实际只能写 4096 个；
  本 PR 把客户端与服务端统一成 `Array.from(text).length`（服务端 `capText`，客户端 `capAnswerText`）。
- **写侧截断不拒绝**：超过上限时截到 8192 个码点后照常落盘。拒绝会把整段文本丢掉，学生连改的机会都没有；
  截断至少保住前 8192 个码点，且下一次输入仍可继续。
- 静默截断的代价由 UI 的「已写 N 字」承担；不做逐字警告、不弹窗、不把超长当成校验错误。这个数字也按
  `Array.from(text).length` 数，否则 5000 个 emoji 会被显示成「已写 10000 字」。
- 引用 chip 与草稿同一上限：`answerQuoteFor` 先 `capAnswerText` 再拼 chip。
- `预测` 与 `作答` 同一上限：服务端 `toEntry` 对两者都走 `capText`，schema 的 `预测` 也标了 `maxLength: 8192`。
- `预测` 与 `作答` 同一口径：两者都是学生自己写的正文，**原样落盘**（缩进/换行/首尾空格有意义），只有
  空判据按 `trim()` 后的值——只含空白的文本不算写过，两边都不占键（此前 `预测` 被多 trim 一道、`作答`
  却不校验空白，同一族两个口径）。

## 空草稿是墓碑，不是噪声

清空输入框必须落一条 `{文本: '', 时}`，**不能删键**。删键后刷新，读侧会把上一次的非空草稿当成「还在」，
旧文本复活——学生明明清空了，重开却又看见它。墓碑让「清空」这件事本身可持久化。

读侧把空文本（含只含空白）保留成**一条显式清空的墓碑**，而不是「没有草稿」：输入框取空串，
`上次作答` 回落到历史末条快照的时刻，而不是清空那一刻。于是同一屏上「输入框为空」「上次作答是某次真实
作答的时间」两件事同时成立——**即使历史里已经有 `作答` 文本，也不会被重新填回输入框**。只有完全没有
草稿条目时，读侧才回落到历史快照文本（旧工作区没有墓碑，不能因此丢掉上一次的作答）。
不改删键语义、不改协议、不把空文本当成 `null`——服务端对非字符串的 `文本` 会判 400。

## 带进答疑的引用 chip（评审第 2 条）

- chip 文本由客户端拼：题干 + 「我的作答：」/「我的预测：」+ `capAnswerText(作答)`。它不是服务端生成的，
  也没有独立的 chip 数据文件。
- 锚点只有 lesson 级：`anchor = {lesson, section: '', sectionTitle: ''}`。学生引用的是「这道题的作答」，
  不是课件正文里的某一段，所以没有 section。形状与标注 chip（ADR-0021）同源，内容来源不同：
  标注 chip 来自正文选区，作答 chip 来自作答文本。
- 这是作答数据族第一次进答疑上下文；本 ADR 明确授权：只把当前这一条作答随下一条消息送出，
  不写学习工作区、不写误解记录、不常驻上下文。
- [目标态规格](../设计/目标态规格.md) §7.4 说的「选中的那段」在这里指作答文本——正文选区与作答文本
  共用同一个 chip 通道，但来源各自标注清楚。

## Considered Options

- **浏览器 localStorage**：最省事，也能跨刷新。但清一次浏览器缓存就丢、换一台机器没有、模型与另一标签页
  都读不到；#213 要的「刷新还在、换页还在、另一标签页能看见」同时落空。ADR-0021 已经用同一理由否过
  localStorage，这里不重复踩。
- **独立 `drafts/` 文件**：看起来最干净，草稿不污染 attempts。但写入会从**一次一条的写队列**拆成两套
  幂等台账（两份 `operationId`、两份 `expectedVersion`、两次回执、两个失败提示），#213 明确要复用现有
  写队列与版本栅栏；两套台账还会带来「草稿写成功、作答写失败」的半提交与读侧合并顺序问题。为一个可改
  状态再养一套写入协议，代价远大于收益。
- **只在内存里放，不落盘**：刷新就丢，正是 #213 要修的 bug；跨标签页也看不见，直接出局。
- **把草稿塞进 `上次结果` 或每条题条目**：会让「上次结果」变成可空，或者让一条可改状态混进事件列表，
  破坏「上次结果 = 历史末条」的同源约定；读侧还要区分「这是草稿还是历史」，不如顶层一个映射干净。
- **给草稿单独建 schema / 版本号**：草稿是同一个 attempts 文件的顶层键，单独建 schema 等于把一份文件
  拆成两个契约；本条只加可选字段，不改文件身份。

## Consequences

- **每次防抖写都 bump 版本，回执后一次全量回读**：草稿每落一次盘就是一次 attempts 写入，版本栅栏随之
  前进；回执带回整份 attempts，读侧照常采纳。900ms 防抖是可接受的成本；**不要降到 100ms 或按键即写**，
  那会把版本号打成一串无意义的流水，并让每次输入都触发一次全量回读与跨标签页广播。
- **8192 静默截断的代价可见但有限**：UI 只显示「已写 N 字」，不告诉学生「后面被截了」。chip 与草稿同
  上限；8k 中文约等于 8k token，带进答疑时是一次不小的上下文开销，记作已知代价。chip 单独截断留后续，
  本 PR 不做。
- **草稿键只增不回收 → 本 PR 加上限**：写入后若键数超过 200，按 `时` 降序保留最新 200，本次写入的题
  一定保留；**只删键、不重排**——留下的键保持原文件里的先后，写一条新草稿不会把整段草稿重新排序；仍
  不设 TTL。旧文件里已有的超限草稿读侧照读，只在下一次写草稿时收敛。
- **题 id 是 `<锚点文本>#<题号>`**：题库重写后，若锚点文本与题号撞车，旧草稿会被回填到新题上。这是既有
  问题（作答历史同病），本 PR 不改题 id，登记后续 issue。
- **版本冲突重发同一份 patch**：409 时写队列重发同一个 job、同一个 `operationId`、同一份 patch，只换
  `expectedVersion`；每次回执的 `version` 被采纳成下一笔栅栏。读侧另有 `mergeNodeDrafts` 的 dirty 栅栏，
  本地未落盘的文本不会被回读覆盖。
- **旧工作区零迁移**：没有 `草稿` 就是「没有草稿」，没有 `作答` 就是「这条快照没有文本」；不需要迁移命令。

## 明确不做

- 不设草稿 TTL、不做草稿历史、不做跨题/跨课检索；
- 不做 chip 单独截断、不改 `TEXT_MAX`、不改题 id 的生成规则；
- 不在本 PR 改导出快照对草稿的过滤（导出是整份 `readLibrary()` 快照，草稿随 `attempts` 带出；
  彻底摘掉要另开 issue）、不把作答文本写回题库或课件；
- 不新增 schema、不新增数据域、不另起一套写入队列；
- 不修 ask-session 的既有失败（与本条无关，单独开 issue）。
