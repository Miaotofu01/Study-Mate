# 学习节点笔记、共享原稿与即时 Markdown 编辑

- 状态：已接受并实现；当前验收状态以[无界笔记设计 §0](../设计/无界笔记.md#0-状态分层)为准。
- 范围：[issue #270](https://github.com/Miaotofu01/Study-Mate/issues/270)。
- 前置：[ADR-0015](0015-无界笔记模块与独立数据域.md)、[ADR-0016](0016-无界笔记持久化与单文件版本栅栏.md)。独立数据根、原始字节版本栅栏与单客户端入口不变。

## 背景

用户需要在读课程时快速写笔记，再到无界画布组织这些笔记。若学习页另建正文或独立保存队列，页面切换容易覆盖旧稿；若用目录位置表达课程分类，拖到另一节点就会误移动原件。即时编辑还必须保留源码退路，不能把无法理解的 Markdown 静默改写。

## 决定

### 1. 数据仍属个人集中库

同一 `profileContext.home` 下跨项目、跨 profile 共享 `<DSH_HOME>/studymate-notes/`。学习项目只提供课程来源；笔记不写进 `.learning/`，也不属于插件安装产物。原件逻辑父目录 `parent` 与课程关联是两套属性。每篇自有笔记仍是一份真实 Markdown，正文文件的稳定 ID 不因改名或节点分类变化而改变。

### 2. 学习页与无界共用原稿和一个保存者

学习左栏可在课程树与「节点 → Markdown 笔记」之间切换。所有课程节点都保留，包括无课件、无笔记的节点；不插入自定义分类文件夹。右栏增加「笔记」tab，只做单篇原稿的快速编辑，不把整个无界工作空间塞进去。

每个主面板实例只有一个笔记 Board 和一个持久化控制器。`createNotesWorkspace()` 是实例内的快照与命令桥，不读文件、不发 HTTP、不生成第二条保存队列。任一笔记入口首次使用时挂载 Board，之后隐藏保活；隐藏面的焦点、快捷键和即时编辑实例让路。冲突、失败、未保存和升级状态两面一致，不把本地草稿当已落盘。

### 3. 默认笔记本、课程关联与两种范围

每个科目首次新建笔记时，必须显式选择或创建默认笔记本；后续新笔记存进该本，并关联当前节点。更换默认本只影响未来新建，不迁移原稿。一个科目只有一个默认本，但可在多本中有相关笔记；一本可绑定多个科目。

学习视图按当前来源科目聚合笔记，不限原件属于哪一本；无界「节点视图」按笔记本范围展示同一套关联。两者不是分别保存、再互相同步的树。资源视图仍保留普通目录。

关联的身份严格为 `workspace + subject slug + node.id`。同一篇笔记在同一来源科目内只能分类到一个节点，也可以保留其他科目的关联。节点间拖动只替换该科目的关联；不改内容 ID、正文、逻辑父目录、原件归属或画布。已失效来源保留原显示名，要求手动重绑，不按同名猜测。

### 4. 每本画布与课程引用

每本笔记本的卡片、关系和相机独立。布局仍是一个带版本栅栏的文件，节点以 `notebookId` 分区；旧无分区节点在第一本中可见，不静默丢弃。保存预算仍是全库总上限，不因分区扩大。

从节点树拖课程节点到画布只添加引用卡，不移动课程节点、不铺开子笔记、不复制课程正文。课程卡只有标题和跳转按钮，没有摘要或正文预览。选中后，侧边栏只读呈现实际课件；跳转按完整来源身份回到学习节点，保留原画布。失效来源保留卡片与名称，禁用无效跳转并提供手动重新关联。

自有 Markdown 可软删除和恢复；删除期间隐藏卡片，恢复后使用原 ID 恢复显示。不在本轮实现文件夹/笔记本回收站、永久清理或跨笔记本原件交接。

### 5. 共享 Markdown 编辑器

首轮为学习与无界选择共用编辑器和源码退路，采用 [Milkdown Crepe](https://github.com/Milkdown/milkdown) `7.23.0`；当时的富文本即时修改会规范化 Markdown。这个编辑模型与模式安排是**历史选择**，不是现行规则。

后续 [ADR-0018](0018-共享Markdown局部编辑与格式栏.md) 为保留原始字符及支持可编辑标记，改用基于 CodeMirror 6 的原 Markdown 编辑模型；[ADR-0022](0022-无界笔记文档视图与课程关系.md) 接续独立文档视图。本文同稿、课程身份、一个保存者与持久化决定仍有效。现行编辑功能与安全边界只看[无界笔记设计 §7](../设计/无界笔记.md#7-markdown-编辑与外部来源)，呈现判据看[阅读端呈现](../规范/阅读端呈现.md) §九。

首轮候选中，Vditor 的默认 CDN／缓存路径需额外改造；MDXEditor 缺少现成数学能力；Toast UI 的维护和 React 版本适配不适合当时的单入口。编辑器许可统一进入构建许可文件。

### 6. 格式 2 与显式升级

新增字段必须在 Host 与浏览器白名单中共同保留；字段 schema 的唯一代码判据仍为 [contracts.ts](../../lib/notes/contracts.ts)。直接让旧格式接收这些字段会被旧客户端剥掉，故新空库采用格式 2。格式 1 的 GET 只读返回升级标记，拒绝写入；前端还按版本判定旧格式，即使旧服务没有发送该标记，也不放行编辑。未知格式继续拒绝。

用户明确确认后，升级在原 OS 锁内验证整个旧库，先保存旧文件的逐字节备份，再原子切换格式标记。正文 codec 未改变，不为升级重写笔记和布局。失败不切换旧库；重复升级已完成的格式 2 幂等。旧客户端遇到格式 2 失败关闭，不能悄悄写回去掉关联。备份不是跨设备同步，也不等于本轮提供通用恢复/迁移工具。

## 不选的方案

- 学习与无界各存一份正文、各自创建保存控制器：产生副本和旧稿覆盖。
- 拖节点分类时移动原件目录：把课程分类误当归属交接。
- 每个科目强制拥有独占的一本笔记本：妨碍用户集中组织与跨科目关联。
- 将课件复制成笔记正文或按标题修复引用：产生过时副本和错误来源。
- 直接让旧客户端继续写新增格式：白名单会静默丢字段。

## 验收与边界

Node 套件检查身份、关联纯变更、字段往返、默认本约束、共享命令桥、格式升级/备份和 CAS。真浏览器检查首次选择默认本、空节点、两面同稿、拖分类、课程引用跳回、快速切走不丢字、外网阻断及旧库升级门禁。所有写测试使用临时数据根，不读取用户笔记、不连接真实模型或发送消息。

本轮不增加 agent 自动读写权限，不承诺多文件全库事务、跨设备同步、原件交接或所有回收站能力。未完成项继续由 issue 跟踪，不能在使用说明中当作已有能力。
