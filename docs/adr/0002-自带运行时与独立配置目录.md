# 桌面端自带运行时，用独立配置目录，学习模式设为默认

Status: proposed（2026-10-02 设计会话）

桌面端面向不懂命令行的学生公开发布，所以它**自带锁定版本的宿主运行时与 Python 运行时**，并用**自己的 DSH_HOME**——与学生机器上可能已装的 DSH 完全隔离。同时，官方非 GUI 通道都选不了 agent preset（只有 Web Remote 的 `agentPresets.select` 能选），所以桌面端把学习栈**直接装配进自己 profile 的顶层 patch 行**（`system-prompt` 的人设 + `skill-filesystem` 的技能目录）：应用内每个会话都是学习会话，**桌面端就是学习专用工具，不做模式切换**。首次启动向导负责选学习工作区与配模型。

## Considered Options

- **共用学生已有的 `~/.dsh`**：省一次配置，模型与登录能沿用；代价是两套安装写同一份配置，升级时互相踩，且「卸载干净」做不到。
- **做成 DSH 桌面端里的一个模式**：零维护成本，但外观受 DSH 约束，与 [ADR-0001](0001-桌面端外壳与对话通道.md) 的 Codex 三栏目标冲突。
- **跟随最新 DSH**：学生能拿到上游新功能，但上游一改协议或扩展点，桌面端可能直接不能用。

## Consequences

- 学生要在应用内重配一次模型。凭据写在隔离 DSH_HOME 的 `.credentials.yaml`（配置里只放 `apiKeyEnv` 引用，密钥不进 profile patch）。
- 运行时要跟着应用一起发版：DSH 与引擎同一个版本号，学生拿不到上游新功能，但也不会因为上游改动突然坏掉。
- 安装路径复用现有安装器的机制（往 `profiles/<profile>/cordis.patch.yml` 插 preset 与 registry 行），只是把 DSH_HOME 指向应用内部。
- **装配机制已实测（原判断有误，已改）**：`agent-preset-registry` 的 `default` 对 ACP **无效**——ACP 不 inject `agentPresets`，全仓只有 web 网关与 webhook 会 mount preset。所以学习模式不能靠「把它设成默认 preset」，只能靠顶层 patch 行装配。**代价：失去运行时切换人设的能力**，要多套人设就得多份 profile（ACP 没有任何 preset 方法）。
- **安装器尊重 `DSH_HOME`**：实测引擎、预设、配置文件与 profile patch 全部落在指定的临时 DSH_HOME，技能文本里的 `~/.dsh/…` 会被改写成真实路径。独立配置目录这条路成立，可以直接复用既有安装器。
