# 阅读端三栏的让位顺序：右栏先拿，左栏先让，中栏保底

课件页的三栏宽度不是样式表算出来的，而是阅读端按当前画布宽逐档分配：右栏先拿满自己记忆的宽度（上限 640），左栏随后在剩余空间里取（上限 460），中栏永远退让但保底 420。空间不够时**先收起左栏、再收起右栏**，理由是「右栏是点题目标记刚拉出来的，先给它留位」；画布窄到两栏的 min 都放不下时右栏归零。存下来的栏宽按当前画布 clamp，变窄只收起、变宽自动恢复。

**并排装不下时，那一栏降级成「盖在正文上的抽屉」而不是归零**（#88 补）：学生点的那一栏照样打开，只是盖在中栏上，顶上一条说明（窗口太窄、拉宽就并排）加一条「收起」；选项只在右栏渲染，静默归零等于学生做不了题。抽屉一次只给**最近点的那一栏**（开一栏不该顺手把早先要过的另一栏盖上来），宽度照旧按记忆值与画布 clamp、给正文留一条缝、不写回记忆值；画布变宽又自动回到并排。

## Considered Options

- **中栏优先**：先保正文的可读宽度，谁不够谁收起。对「读」最友好，但点题目标记是刚发生的意图——正文被压窄只是不舒服，右栏不出现是**做不了题**。
- **CSS 网格 + 媒体查询**：宽度交给样式表。但栏宽要跨会话记住、并按当前画布 clamp 后恢复，媒体查询表达不了「按记忆恢复」这一层。
- **三栏按比例分**：宽画布下正文会不必要地变宽，而正文自己有测宽上限，多出来的宽度只会变成留白。
- **归零 + 一句提示**：最省事，但学生只是被告知「做不了题」，没有出路。抽屉把「说明」与「出路」合成一件事：那一栏照样能用（#88 验收第 4 条）。

## Consequences

- **窄画布下正文的可读宽会被挤到与右栏同宽**：并排的极限是画布 868px（窄轨 76 + 中栏保底 420 + 右栏 372），此时正文可读宽 = 420 − 左右内边距 48 = 372，正好与右栏一样宽——这是「正文列只有右栏那么宽」的直接来源。要看正文就把右栏收起来或把窗口拉宽；低于 776px 时右栏本来就不再并排，而是盖在正文上。
- **降级不是静默的**：画布不够宽时点「题目」拿到的是抽屉（说明 + 收起 + 题目本身），不是「按了没反应」。这条曾是本决策的已知后果（#84 的现状与差距三），#88 把它收掉了。
- **没有「两栏都打不开」的画布宽度区间**：任何宽度下，最近点的那一栏要么并排、要么以抽屉出现；并排的两条栏加起来也永远不挤破中栏保底。这两条是扫 240–2200px 的不变量断言（`scripts/tests/test_client_panes.mjs`）。
- 栏宽只存在浏览器本地，不写学习工作区；存宽**不覆写**，所以窄的时候收起不会把记忆改小。
- 左栏的收起阈值比右栏低，两级阈值必须与窄轨宽、中栏保底、两栏各自的 min/max 一起改，否则会出现「两栏都打不开」的画布宽度区间。
- **窄轨宽只有一处定义**：CSS 里的 `--smb-rail`（`lib/client.js` 的 token 块），窄轨的 `width` 引它；脚本侧**量渲染出来的窄轨**，再拿去算分配与把手落点（把手位置 = 窄轨 + 这一栏的宽，热区比线宽出来的半格回退在 CSS 里）。原先样式表与脚本各写一遍 38px、把手又各自重算「窄轨 + 栏宽 − 3」，#88 把这条收掉了：`test_client_panes.mjs` 守「脚本里没有第二遍」，浏览器套件守「把手真的落在栏的边缘上」。
- **正文的测宽服务于可读行宽，不是填满窗口**：中栏宽了以后正文列不跟着无限变宽（`max-width: min(100%, clamp(760px, 66%, 900px))`）——窄画布下铺满中栏，宽画布上约占三分之二，再宽就撞上限（13px 正文下一行约 69 个汉字）。这是呈现面的取值，理由与出处写在样式表那一处。
