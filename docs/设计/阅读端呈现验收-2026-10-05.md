## 二、真宿主 DPR 实测（结掉 spec 的「待实测」）

**要回答的问题**（spec 的「诚实边界」原话）：真宿主里的正文列实测约 **500 物理像素**，
而代码里的测宽上限是 **760px**（现在写成 `min(100%, clamp(760px, 66%, 900px))`）——对不上，
上一轮没定论，怀疑是浏览器缩放 / DPR / 面板宽度三者之一。

### 走了哪条路径

**真宿主那条（施工说明 §二 的路径一），证据级别：第一级。**
在**隔离 HOME** 里起了本机装的那个真 DSH（`dsh web`，版本 `0.2.0-rc.2`），profile 的
那份 `@yunmiao/studymate` 软链指到本票这棵树（`/home/tofu/studymate-wt/94`），
再用一个干净 profile 的无头 Chrome 走 CDP 打开它打印出来的带 token URL，点侧栏「学习」进阅读端，
走进课件页，用 `Emulation.setDeviceMetricsOverride` 设设备像素比后读三个数。
下表这六组读数在合入 #93 前后各量了一遍，**逐项相同**（#93 只动右栏的呈现，不动正文列宽度）。
真宿主网格、真 React、真 `lib/client.js` 都是真的；**不真**的只有「显示器与缩放」这一层
——无头 Chrome 的 DPR 是我们显式设的，不是这台机器的物理显示器。上一轮那次读数所在的机器 DPR
无法回溯（那条信息没被记下来，这正是它没定论的原因）。

同一批读数里 `.smb-doc` 的计算 `max-width` 每一组都是
`min(100%, clamp(760px, 66%, 900px))`；窄轨两条加起来 76px（= CSS 的 `--smb-rail` × 2）；
`document.documentElement.scrollWidth − innerWidth = 0`（无横向溢出）。

### 结论：对不上的是**画布宽**，不是 DPR

1. **DPR 只做乘法，不参与布局。** 同一视口下 DPR 1 与 DPR 2 的 CSS 几何逐项相同
   （面板 1160 / 中栏 712 / 正文列 712 / 右栏 372 / 窄轨 76），只有物理像素翻倍（712 → 1424）。
   所以「760 CSS px 的列在 DPR 2 下是 1520 物理像素」——DPR **不可能**把 760 变成 500。
   想让物理像素变小，只有浏览器缩放小于 100%（Chrome 把浏览器缩放折进 `window.devicePixelRatio`，
   所以这一列读数同时就是「显示器缩放 × 浏览器缩放」的乘积；本轮读到的是 1）。
2. **760px 这个上限在 1440 一级的视口下根本没生效。** `min(100%, …)` 里的 `100%` 先到：
   面板 1160 → 中栏 712 < 760，于是正文列 = 712（铺满中栏）。只有面板足够宽时 `66%` 才接管
   （1920 视口：中栏 1192 → 正文列 786.72 = 66%）。
3. **「约 500 物理像素」的可复现来源是两条栏都拉开时的中栏。** 面板 1160、左右两条栏都并排时
   中栏 448 → 正文列 448 CSS px = **448 物理 px**（DPR 1），正落在「约 500」那一带；面板更窄
   （1120 视口 → 面板 840）时是 420。上一轮那句「正文列只占面板可用宽约三成」也对得上这个形态
   （448 / 1160 ≈ 39%，再算上正文列左右内边距，可视行宽更窄）。
4. **所以「500 vs 760 对不上」这个矛盾不是 DPR 造成的**，而是把两种不同的量放在一起比了：
   旧代码的 `max-width: 760px` 是**上限**，而 500 那一侧量的是**画布不够时的实际列宽**（或正文里
   某一段/某个元素的宽）。对得上的口径是：**正文列 CSS 宽 = min(容器宽, max(760, 66% × 容器宽))**，
   物理宽再乘 DPR。本轮实测的每一组都落在这条式子上。

**下一步（要把这一条钉得更死的话）**：在同一台机器上用**真实浏览器窗口**（不经
`Emulation.setDeviceMetricsOverride`）打开 `dsh web`，在 DevTools 里读
`window.devicePixelRatio` 与 `document.querySelector('article.smb-doc').getBoundingClientRect().width`，
再把窗口拉到与上一轮截图同样的宽高（上一轮截图 2259×1428 物理像素）——这样「显示器缩放」也被覆盖。
探针命令见 §七。

2. **「长 URL 溢出 865 → 0px」复现不出**：合并者前后对照是 15px → 0px，865 更像那条 148 字符 URL
   自身的渲染宽度。条目 25 本身成立（改后结果行与列表的横向溢出都是 0px），但那个 before/after
   数字不成立——测量口径交评审。
3. **#90 为条目 24 改了 Host 半契约**：`lib/library.ts` 的 `buildLibrary` 在「工作区在但零可用科目」
   时从抛错改成给空清单，并改写了 `test_host_library_payload.mjs` 里一条特征化断言。**有意为之**，
   供 code-review 复核（真空态语义、`tools/context.ts` 的提示没丢、断言改写是刻意的而不是为了变绿）。

   渲染成空壳；#91 / #92 后来给夹具补了 `dangerouslySetInnerHTML` 与回调 ref 支持。

   （mini-react 每次重渲染整树重建 DOM，被 effect 闭住的旧节点一脱离文档就报 0 宽）。

   截图与断言都跑在 mini-react 上；真 React 下的对照见 §二 的真宿主截图（真宿主里三栏、公式、
   题目标记都渲染正常）。
6. **窄于 696px 画布两栏都想降级时只显示「最近要的那一栏」**，见 §四 第 5 条。
