# 代码块与终端块的呈现

> **性质**：设计类。记的是 2026-10-07 一轮针对「课件里的代码块／终端块看起来不像正经代码块」的重做方向、依据与取舍。
> **状态**：方向已定，**代码一行未动**。本文是给「转 spec 与 tickets」那一轮用的输入，不是实现记录。
> 证据图：[三版对比（暗色）](../images/代码块-2026-10-07/三版对比-暗色.png) · [三版对比（亮色，仅示意）](../images/代码块-2026-10-07/三版对比-亮色-示意.png)

## 一、问题

学生视角：课件页里那个「运行结果」块不像代码块。具体表现——整块横贯正文列而内容只占左边一条、右边大片空白；顶栏像孤零零挂着一个标签；块内一色到底，命令行与输出分不出来。

## 二、现状事实

每一条都带出处，可逐条复核。

- **它不是专门组件，是代码块的一个变体。** 语言标记写 `term` 的围栏，`lib/client.js:1060` 把它记成 `term: true`，`:1373` 据此把顶栏文案写死成 `'运行结果'`（否则显示语言名）。
- **服务端的数据结构里没有 `term`。** `lib/core/format.ts:332` 的代码块只有 `{ kind, lang, text, line }`——`term` 是阅读端自己判出来的。
- **`term` 在规范里没有定义。** `docs/规范/课件内容格式.md:57` 只把它列进「会着色」的语言表，`:219` 有一个例子；`preset/skills/**` 里**没有任何一处**教模型写 `term`，`preset/skills/lesson-design/SKILL.md:29` 只说「语言标签写清楚」。
- **阅读端没有语法着色。** `lib/client.js:1374` 就是 `h('pre', null, h('code', null, block.code))`——没有 `data-lang`、没有高亮。内容格式那张语言表说的「会着色」在这一侧不成立（`lib/core/format.ts:1297` 的 `<pre data-lang>` 是内容层自己的渲染，与阅读端不是同一条路）。
- **这块没用宿主自己的代码块配色。** 宿主主题里**有**一整套代码块 token（亮暗各 7 条）：`--dsw-alias-markdown-code-block`、`--dsw-alias-markdown-code-block-banner`、`--dsw-alias-markdown-code-segment-selected`／`-unselected`、`--dsw-alias-markdown-inline-code`、`--dsw-alias-code-diff-added`／`-deleted`（快照见 `scripts/tests/fixtures/host-theme-tokens.json`）。阅读端**一条都没引**——它用的是通用卡片底色（`lib/client.js:381` 的 `--smb-raise` 与 `:387` 的 `--smb-bg`）。
- **块不支持 `caption`／`alt`。** 带这两个字段的只有 `::: figure` 与 `::: svg`（`lib/core/format.ts:352-359`）；代码块两者皆无，所以解释只能另起一段正文。` ```term caption:x ` 也写不了：`format.ts:685` 的 `isKnownLang` 会拒，`lib/client.js:1058` 的围栏正则 `/^```(\w*)\s*$/` 也不匹配。
- **这套样式全仓只有课件正文一处用**（`lib/client.js:1372`）。题库里的代码、作答原文是另外的规则，只共用字体档。
- **规范只管三条，且都已达成。** `docs/规范/阅读端呈现.md:38`：**代码块带语言标签；超长行在块内横向滚动，块本身不超正文列宽**。当轮验收记在 `docs/设计/阅读端呈现验收-2026-10-05.md:127`（第 11 条，已达成）。

## 三、两条硬约束（决定了下面三版里哪些做不出来）

1. **颜色只能引宿主的 `--dsw-alias-*` token，不许自造色值。** 规矩写在 `lib/client.js:106-108`，`scripts/tests/test_client_tokens.mjs` 兜着（引到的 alias 必须存在；文字与底的对比度必须达 AA）。
2. **暗色下没有比页面更深的底色可用。** `--dsw-alias-bg-base`（暗色 `#151517`）已经是最深的 surface，而 `color-mix` 永远不会低于较暗的那一端。所以「真·黑终端」在这一台宿主上做不出来——想要就得先松上面那条规矩（本条是本轮实测出来的，原先不在预料里）。

## 四、三版方向与结论

| 版 | 骨架 | 结果 |
| --- | --- | --- |
| **A** 文档站风 | 对齐宿主自己的代码块 token ＋ 顶栏语言标记 ＋ 行号槽 ＋ 命令／输出两级 | **立得住**——三版里只有它读起来像正经代码块 |
| **B** 终端会话风 | 三颗单色点 ＋ 提示符槽 ＋ 命令带 | 终端感**没有底可托**（约束 2）：块体与页面几乎同色，读起来是散字加几条细线 |
| **C** 紧凑内嵌风 | 不画外壳，`width: fit-content`（实测 274px）＋ 左侧竖线 | 消掉了右边空白，但读起来像引用块；左竖线对比度只有 1.40:1，几乎看不见 |

亮色那张只是示意：宿主自己的代码块 token 在亮色下顶栏与块体是同一个色值，所以 A 的顶栏在亮色主题里等于没有——这是宿主自己的做法，不是我们做坏了。

## 五、已决方向（2026-10-07 拍下）

1. **底与顶栏**换用宿主自己的代码块 token（`--dsw-alias-markdown-code-block` 与 `--dsw-alias-markdown-code-block-banner`），圆角 8、1px 边框。
2. **顶栏**：左边三颗单色点（终端味，只用中性 token 做层次；不许用红黄绿那类语义色），右边小字写语言标记（如 `term`）。
3. **左边一条行号槽**（2.5ch 右对齐、不可选中）。
4. **行分三档**：`> ` 开头 = 命令（亮一档 ＋ 一条极淡的命令带）；`# ` 开头 = 注释（暗一档）；其余 = 输出（中间档）。
5. **整宽**（不贴合内容）。普通代码块与终端块共用同一骨架。
6. **写死的「运行结果」标题去掉**，改显语言标记。
7. 解释段落仍在块外——给代码块加 `caption` 是另一件事（见遗留）。

## 六、验收候选（转 ticket 时可直接用）

- 亮／暗两套主题下都成立；文字与底的对比度达 AA。
- 三档行（`>`／`#`／其余）各自的呈现可判。
- 保住 `docs/规范/阅读端呈现.md:38` 那三条：语言标签在、超长行在块内横向滚动、块本身不超正文列宽。
- 三颗点与边框只用既有中性 token 做层次，不引入自造色值（`scripts/tests/test_client_tokens.mjs` 不红）。
- 字号与行高走既有阶梯（`--smb-fs-code`／`--smb-lh-code`），`scripts/tests/test_client_typography.mjs` 不红。
- 课件页浏览器套件（`scripts/tests/browser/lesson_body_test.mjs`）补上三档行的读数。

## 七、遗留（各自另开票）

1. **代码块没有 `caption` 槽**——解释只能写在框外。像 `::: svg` 那样给代码／终端块加 `alt`／`caption`，会同时动内容格式规范、解析器与阅读端渲染。
2. **`term` 在规范里没有语义定义**——内容格式只把它列进语言表，技能从不教模型写它。它到底是什么（终端会话回放？只贴输出的摘录？）该有一条口径。
3. 同属这一片、已开的一张：**#113** 导出夹具缺 `::: svg` 覆盖。
