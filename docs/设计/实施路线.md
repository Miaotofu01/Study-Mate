# StudyMate 实施路线

> 状态：**路线**，尚未实施。
> 定位：把 [目标态规格](目标态规格.md) 拆成可验收的阶段，并写清**为什么是这个次序**。
> 边界：本文件只排顺序与验收标准，不写实现细节；目标态本身见规格，理由见 [重构评估](重构评估.md)。

---

## 0. 次序的三条硬约束

这三条决定了阶段不能重排：

1. **内容格式的解析与校验必须先立住。** 它是唯一"错了就全错"的一层——工具、界面、导出全部是它的调用方。今天这份契约散在 `render_lesson.py` 的解析器与 `课件内容格式.md` 里，必须先变成一份带测试的 TS 实现，否则后面每一层都在猜。
2. **数据模型必须先于界面与技能。** 阅读端读进度与作答数据，技能写它们；两者都不能先于格式定稿。
3. **技能必须晚于工具。** 技能改写的内容是"调哪个工具"；工具不存在时改写只会写出悬空引用。

## 阶段 0 · 把地基钉住

**做什么**

- 五份文档入库：[重构评估](重构评估.md)、[目标态规格](目标态规格.md)、本文件、8 条 ADR、`GLOSSARY.md` 补词。
- 现行规范加指针：`设计方案.md` 与 `工程约束.md` 标明"目标态见……"。
- **清理版本记录的矛盾**：仓库里已有 `v0.3.0` 标签且是 HEAD 祖先，但 `package.json` 是 `0.2.0`、`CHANGELOG.md` 顶部也是 `0.2.0`——先确认真实已发布版本，再决定这次重构的版本号从哪起。

**验收**

- 五份文档可点开、互相链接不断。
- `npm test` 行为不变（本阶段只加文档）。
- 版本号与 CHANGELOG 与已发布的 tag 对齐。

**为什么在这**：决策不落纸，后面每个阶段都会重新讨论一遍。

## 阶段 1 · TS 内核（纯函数层，不碰宿主）

**做什么**

- **内容格式解析器**：把 `课件内容格式.md` 的全部规则实现成带行号报错的解析器——`##`/`###`、列表、管道表、围栏、行内语法、8 个 `:::` 指令、front matter 两个字段、锚点与题库逐字对账。
- **校验器**：大纲（DAG 无环、位次不倒挂、实验课前置非空）、进度、科目、交接门禁。
- **纯函数规则层**：层级判定（读懂/改对/查错/造出）、题型与深度的匹配、进度推进。
- 全部零宿主依赖、可单测。

**验收**

- 对**删除前的 `examples/`** 里那 6 课的真实数据逐字复核：解析结果与 Python 版一致，报错位置一致。
- 故意造坏（未知指令、锚点缺失、题库多余键、front matter 多字段），报错信息带文件与行号。
- 纯函数层的测试覆盖率有明确下限，且不依赖文件系统。

**为什么在这**：这是整个重构的**唯一高风险层**。它一旦立住，后面所有工作都是调用方；它立不住，界面做得再好也是错的。

---

## 阶段 2 · 插件骨架与工具注册

**做什么**

- Host 半：注册工具（`workspace.context`、四个校验、重排、空题理由、导出占位）。
- **域声明与运行时强制**：每个工具声明读哪些域、写哪些字段；未声明的读写直接抛错。
- 安装路径改造：不再往 `~/.dsh/studymate/engine/` 拷源码树，引擎就是已安装的插件包。
- 门禁加两条：架构边界测试（真实 import 图 + 依赖无环）、门禁覆盖断言（未登记的测试套件让门禁失败）。

**验收**

- 在真 DSH 里装一次，新建「学习模式」会话，总控能调 `workspace.context` 并拿到结构化摘要。
- 故意让某个工具越权读一个未声明的域，必须抛错。
- `npm test` 里能看到架构边界测试与覆盖断言真的在跑。

**为什么在这**：工具是技能与界面的共同依赖，必须先于两者存在。

---

## 阶段 3 · 数据模型迁移

**做什么**

- 进度三档：`未开始 / 学习中 / 已学完`；`mastery` 移除；读取旧文件时自动映射，写回用新词表。
- 作答数据：`attempts/<NNNN>-<节点id>.json`，幂等写入（`operationId`）+ 版本号冲突拒绝。
- 误解记录改单一落点，字段定型。
- `assessments/` 与 `sessions/` 停止产生新文件。
- schema 更新。

**验收**

- 拿一份 **v0.2 的真实工作区**（含旧六档状态与 `mastery`）跑一遍：读得进、映射正确、写回后旧文件不损坏、旧目录仍可读。
- 并发写同一份作答数据：版本号对不上时拒绝并重读，不丢数据。
- 重放同一个 `operationId` 返回原回执，不产生第二条记录。

**为什么在这**：界面与技能都读它；先定，后面才不会边写边改格式。

---

## 阶段 4 · 任务模型 + 文件监听与推送

**做什么**

- 任务：排队/运行/取消中/完成/失败/已取消；状态查询从不阻塞；等待有上限并给下一步提示；取消说清保留什么；销毁先回执后删。
- 状态活着时在内存；导出这类关键任务落盘可恢复。
- 文件监听 → `/api` 推送变更通知 → 页面按"未变即同引用"更新。

**验收**

- 起一个导出任务：能查状态、能等、能取消，三种结局都有明确回执。
- 关掉 DSH 再开：落盘的关键任务能接上。
- 改一个课件文件：打开的页面收到推送，且未变的视图没有被击穿重渲。

**为什么在这**：阅读端要订阅它，所以先于界面；它又依赖工具层，所以晚于阶段 2。

## 阶段 5 · 阅读端

分片推进，每片独立可验收：

| 片 | 做什么 |
|---|---|
| 5.1 | 骨架与信息架构：今天学什么 / 科目 / 课件 / 搜索 / 问答面板五处入口；组件与样式按 DSH 规范从宿主原语抄，token 纪律 |
| 5.2 | 课件页渲染：正文、配图、公式、提示块、目录；阅读位置三级恢复；锚点四态定位 |
| 5.3 | 题目与三轨判分：客观题即时判、主观题对照自评、实操题由 Host 半代跑测试并把真实输出贴回 |
| 5.4 | 路线图与附件：三档着色、依赖分层、参考文档与学习记录 |
| 5.5 | 跨科目搜索：五类内容的内存索引 |
| 5.6 | 问答面板：选中发起、独立调模型、写一条误解记录 |

**验收**

- 每片配浏览器 QA 用例，出截图集与 `summary.json`（控制台错误、页面错误、失败请求）。
- 对比度测试通过：每个文本 token 在每个表面上都达 WCAG AA，亮暗两套。
- 无障碍：图表有 `aria-label` 与视觉隐藏的 `<table>` 兜底；进度条是真 `role="progressbar"`；动效四档可切。
- 首次引导在窄侧边栏里不越界。

**为什么在这**：数据模型与推送都已稳定，界面只是读与写；提前做会反复改。

## 阶段 6 · 技能与角色清洗

**做什么**

- 删掉暂存模式：开场直接读配置里的工作区，收尾不再问落点、不再 `cp -a`、不再写 `prefs.md`。
- 删掉渲染、搬运、刷新主页、算 `md5` 这些步骤。
- 命令换工具：技能里不再出现路径、参数、命令、exit code。
- 五角色职责清洗；`layered-practice` 改写（新四层、新题型、取消评估题、课型不再限层级）；`evidence-check` 收窄到实验课验收；`local-qa` 与 `record-keeping` 改写。
- 技能瘦身：常驻指令压下来，详细契约按需取。

**验收**

- 完整跑一次真实流程：开新科目 → 盘问 → 大纲 → 学一个节点 → 作答 → 实验课验收 → 收尾。
- 全程**没有一次 bash 调用脚本**。
- 开场不再出现"成品放哪"的问题；工作区直接落在配置的位置。
- 技能里搜不到任何 `.py`、`exit code`、`cp -a`、`.stage`（`.stage` 只允许作为产物交接的暂存目录出现）。

**为什么在这**：技能写的是"调哪个工具"；工具在阶段 2 才存在，界面在阶段 5 才定型。

---

## 阶段 7 · 导出与多宿主无头路径

**做什么**

- `studymate.export`：把工作区渲染成自包含静态页面。
- DSH 侧按需导出；Antigravity / Codex 侧默认导出。
- Node CLI 供无头宿主调用。
- 构建期加泄漏守卫：导出产物不得引用只存在于 Node 的东西。

**验收**

- 导出的页面在 `file://` 下打开：样式、公式、图片、题目全部可用。
- 泄漏守卫故意注入一个 Node 专用依赖，构建必须失败。
- 在 Codex / Antigravity 侧用 CLI 跑通一次建课并导出。

**为什么在这**：它复用阶段 1 的解析与阶段 5 的渲染，必须晚于两者。

## 附录：风险与对策

| 风险 | 对策 |
|---|---|
| **内容格式解析器与 Python 版行为不一致** | 阶段 1 的验收就是"对既有真实数据逐字复核"，不是"看起来能跑" |
| **界面先做、格式后改，返工** | 次序硬约束 2；阶段 3 先于阶段 5 |
| **技能提前改写，写出悬空工具引用** | 次序硬约束 3；阶段 6 晚于阶段 2 |
| **抄宿主原语后宿主升级，观感崩坏** | 只用 `--dsw-alias-*` token（改名只变丑、不崩）；类名带自己前缀；对比度测试兜底 |
| **两套引擎长期并存** | 阶段 8 明确拆除；两端走 CLI 与导出，不保留第二套引擎 |
| **旧工作区读不进来** | 阶段 3 的验收必须用真实 v0.2 工作区，不用构造数据 |
| **DSH 仍是 rc 版本，宿主接口会变** | 只依赖 token 与自己写的组件；宿主 slot 名与包接口不做长期假设 |
| **`examples/` 删除后失去端到端样例** | 阶段 1 的复核是它最后的用途；此后由"测试时现造的临时科目"承担，导出能力承担人工验收 |
