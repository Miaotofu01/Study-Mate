## 1. 为什么要重构

现行系统（v0.2）的形态是：**提示词驱动的技能集 + Python 脚本引擎 + 一次性生成的静态 HTML**。

三处结构性缺口：

| 缺口 | 事实 |
|---|---|
| **学生看到的是产物，不是应用** | 课件页是 `render_lesson.py` 一次性渲染的静态 HTML，`file://` 打开；改样式要重跑生成器，路线图与练习的交互散在模板与科目副本里，不能热更新 |
| **引擎靠命令驱动，不靠接口** | 总控通过 bash 跑 `python3 -B <root>/scripts/xxx.py` 并读 exit code；17 个 Python 脚本（`render_lesson.py` 1426 行、`gen_home.py` 1298 行、`check_lesson.py` 1056 行）承担解析、渲染与校验，没有任何结构化返回值 |
| **插件面几乎是空的** | `cordis.patch.yml` 全文 4 行，`bin/dsh-plugin.mjs` 20 行，只注册「学习模式」预设；零工具、零服务、零界面 |

第三条是关键：**宿主提供的能力（原生工具、后台任务、客户端界面、文件监听）一样没用上**，而这三条缺口全部落在宿主已经提供、我们却没有接的东西上。

## 2. 评估的五个方面与逐项定档

每条给一个**档位**：

- **抄设计**——只要思路，实现自己写；
- **移植实现**——连做法一起搬（含测试策略），代码重写；
- **不采纳**——明确不要，附理由。

### 2.1 前端 / 阅读端

| # | 可取之处 | 档位 | 我们怎么用 |
|---|---|---|---|
| F1 | **能力表冻结**：插件不探测宿主回调是否可用，改用一个冻结的能力对象；共享界面永远不猜 | 抄设计 | Client 半只用一张常量表描述"这个宿主版本支持什么"，界面按表降级，不做运行时探测 |
| F2 | **未变即同引用**：轮询回来的快照按顶层键逐一比较 JSON 文本，没变的键直接返回上一轮的对象 | 抄设计 | 我们改用文件监听 + 推送，但"没变就不换引用"这条要保留——否则每次推送都会击穿所有 memo 化的视图 |
| F3 | **陈旧响应围栏**：写队列 + 合并轮询 + 明确的"旧轮询不许覆盖新作答" | 移植实现 | 作答回写是并发写，必须有这道围栏；与后端 B3 的版本号机制配对 |
| F4 | **阅读位置三级恢复**：捕获 `{sectionOffset, scrollTop, progress}`，恢复时按 section → offset → progress 依次降级 | 抄设计 | 学生从课件跳去提问再回来、或从搜索跳进正文，都靠它回到原位 |
| F5 | **锚点定位四态**：`resolved / stale / ambiguous / missing`，拒绝"有多个匹配就取第一个" | 移植实现 | 我们不做正文级引用，但 `::: quiz` 锚点与题库键的对接会遇到同样的多匹配问题——现状是渲染器报错，新引擎应给出同样的四态 |
| F6 | **定位几何是纯数学**：优先方位 → 按剩余空间换边 → 窄容器停靠底部 → 目标占满时退到内角；零依赖、可单测 | 抄设计 | 首次使用的引导层需要它；DSH 侧边栏很窄，这条正好 |
| F7 | **无障碍是系统性的**：图表用 `aria-label` + 视觉隐藏的 `<table>` 兜底；进度条是真 `role="progressbar"`；动效分 `auto/full/reduced/off` 四档 | 抄设计 | 直接作为阅读端的验收项 |
| F8 | **对比度测试**：解析 token 块 → 算相对亮度 → 断言每个文本 token 在每个表面上都达 WCAG AA，亮暗两套都测 | 移植实现 | **本次调研里最值得抄的一件东西**：把设计系统的约束写成会失败的测试 |
| F9 | **token 纪律**：新规则必须引用 token、不写裸色值；理由是"token 改名只会变丑，不会渲染崩" | 抄设计 | 与 DSH 官方的 `--dsw-alias-*` 纪律完全同构，两边合成一条规矩 |
| F10 | **文档预览的懒加载 + LRU + 两段式渲染**（先低清后高清，缓存统计暴露成 `data-*` 供测试读） | 抄设计 | 参考教材与 PDF 原件要用；但优先级低于主闭环 |
| F11 | **构建泄漏守卫**：把真实服务与真实界面打进演示构建，若服务端专用依赖泄漏进浏览器包就让构建失败 | 抄设计 | 用在导出器上：导出的静态页面绝不能引用只存在于 Node 的东西 |

### 2.2 后端 / 服务与数据模型

| # | 可取之处 | 档位 | 我们怎么用 |
|---|---|---|---|
| B1 | **领域注册表 + 运行时强制**：每个域声明自己拥有的字段、读取依赖、跨域授权、每个动作的写入集；未声明的读或写**直接抛错**，不是靠文档约定 | 移植实现 | 这是本次调研**最高价值**的一条。引擎工具化后，"谁能写哪个文件"必须变成代码里的事实，而不是技能里的一句话 |
| B2 | **架构边界是可执行的测试**：用真实 import 图断言"不许跨域 import"，并断言依赖图无环 | 移植实现 | 我们的 `scripts/tests/` 已有门禁习惯，正好接上 |
| B3 | **幂等追加**：`operationId` + 规范化载荷指纹，重放返回原回执；配 `expectedVersion` 的版本冲突拒绝 | 移植实现 | 作答数据回写的底座 |
| B4 | **两层任务模型**：底层是 owner 作用域的任务服务（FIFO、去重键、abort、进度、有界等待、历史上限）；上层是面向工具的生命周期（状态从不等待、等待有上限并给出下一步提示、取消说清保留什么、销毁先回执再删） | 移植实现 | 直接对应我们"任务有状态、可取消、可恢复"的决定 |
| B5 | **纯函数被运行时与界面共用**：排期逻辑写成零依赖纯模块，界面拿同一个函数做预览 | 抄设计 | 我们的层级判定、进度推进、内容格式校验都该长成这个形状 |
| B6 | **校验前置到两个时刻**：同一套纯函数在"写盘时"与"发布时"各调一次 | 抄设计 | 课件在"生成时"与"导出时"各校验一次 |
| B7 | **宿主端口薄适配层**：把宿主 API 收进一个 `{tools, call, service}` 端口，核心逻辑脱宿主可测 | 抄设计 | 插件 Host 半的核心就该这样切，测试不必起真宿主 |
| B8 | **模型能力缺失是协商结果而非异常**：返回 `{available:false, reason}` 而不是抛错 | 抄设计 | 没有可用模型时，阅读端仍要能读、能导出 |
| B9 | **零依赖的 Office 读取器 + 测试时现造的二进制夹具** | 移植实现 | 对应"测试里现造临时科目"的决定；将来要读 `.docx/.pptx` 时照此办理 |
| B10 | **内容寻址存储的"思路"**：不可变内容文件 + 原子重命名清单 + 损坏分片隔离并拒写 + 逐步迁移 | 抄设计 | 只借思路。**不抄实现**——对方自己承认那套缓存机制是基准驱动的过度工程，且出过别名 bug（见 §4） |

### 2.3 提示词 / 生成管线与 Agent 编排

| # | 可取之处 | 档位 | 我们怎么用 |
|---|---|---|---|
| P1 | **一个 schema 对象同时当提示词文本与校验器** | 移植实现 | 出题与评估的结构化输出都这么做：形状只定义一次 |
| P2 | **「空的 issues 列表不算通过」**：强制逐条检查记录，且条数必须等于对象数 | 移植实现 | 防止模型用"没有意见"糊弄过复核 |
| P3 | **一次指名纠错重试**：重试必须说明具体错在哪，永不盲目重试 | 抄设计 | 适用于一切模型产出的返工 |
| P4 | **打捞优先于丢弃**：从截断的 JSON 里恢复完整对象，且**不当作已通过** | 移植实现 | 长课件与成组题目会被截断；打捞能救回大部分 |
| P5 | **程序拥有答案，模型只写文本字段** | 移植实现 | 出题时答案与选项结构由程序按锚点绑定，模型只写题面、解释与要点——这让返工便宜且安全 |
| P6 | **零成本自动修复先于花一次模型调用** | 抄设计 | 能用规则修的（空格、行宽、锚点格式）绝不叫模型 |
| P7 | **修复资格分类**：只有措辞类缺陷可自动修，事实类与结构类不可修 | 抄设计 | 防止"修着修着把内容改错了" |
| P8 | **把确定性缺陷喂进复核者的提示词**：机器先查出的问题作为输入交给模型复核 | 抄设计 | 便宜的检查给贵的检查铺路 |
| P9 | **指纹范围的复核溯源**：一次复核只覆盖它看过的确切内容；发布时只重审改过的 | 抄设计 | 学生改一道题不必重审整课 |
| P10 | **复核者与作者隔离**：不同系统提示、明确告知不要信任作者；作者自检只作诊断 | 抄设计 | 我们已有"出题与批改同一角色"的隐患，这条是防线 |
| P11 | **分段与并发**：按页切块、按体量分配配额（最大余数法）、并发受限的 FIFO 共享预算 | 抄设计 | 大教材生成用得上 |
| P12 | **源材料标注为不可信证据**，并对 PDF 给出"空间排布不是图表"的专门警告 | 抄设计 | 我们读本地教材与在线来源时同样适用 |
| P13 | **诚实认识论**：`not_checked` 是合法状态；诊断信息由程序重算而非采信模型产出的 JSON；草稿上写明"模型复核不是事实正确的证明" | 抄设计 | 与我们"删掉阶段评估"不矛盾：它讲的正是"别把模型判断当证据" |

### 2.4 架构 / 工程约束

| # | 可取之处 | 档位 | 我们怎么用 |
|---|---|---|---|
| A1 | **门禁覆盖断言**：测试目录下未登记的套件直接让门禁失败 | 移植实现 | 防"新写的测试悄悄没跑"——我们已经有测试目录，缺这道断言 |
| A2 | **测试运行器做三件事**：清洗环境变量（抹掉所有密钥类）、用一次性 HOME、装网络守卫 | 移植实现 | 直接可用 |
| A3 | **生成式夹具**：测试时现造 PDF / ZIP / 文档，不往仓库塞二进制 | 移植实现 | 与"删掉 examples、测试里现造临时科目"是同一个决定的两面 |
| A4 | **浏览器 QA 的实用主义**：找一个本机已装的 Chromium，而不是钉死某个下载版本；每个用例出截图集 + 一份 `summary.json`（控制台错误、页面错误、失败请求） | 移植实现 | 阅读端必须有这条路，否则界面回归只能靠肉眼 |
| A5 | **性能预算写成"相对库规模的比例"**，不写绝对秒数 | 抄设计 | 工作区大小差异极大，绝对秒数必然失真 |
| A6 | **文档纪律**：每个特性带「未验证」小节；站点审计删掉过时宣传；发布验证是独立回执 | 抄设计 | 与 [ADR-0001](../adr/0001-贡献契约.md) 的"不写会枯萎的剧情事实"同源 |

### 2.5 功能 / 产品形态

| # | 可取之处 | 档位 | 我们怎么用 |
|---|---|---|---|
| D1 | **证据资格政策**：延迟重测才算独立证据；明确的"不能算独立通过证据"清单（自评、同日重试、关键词标签、仅浏览过）；分母口径明确，空范围绝不显示 100% | 移植实现 | **本次调研功能面最高价值的一条**。我们删了阶段评估，但实验课验收仍要判"是不是真会了"——这套资格清单正是防自欺的工具 |

| D5 | **可选脚手架永不宣称掌握**：流程里每一步的完成只是"活动"，不是"掌握" | 抄设计 | 阅读端里任何"你已完成 X"的措辞都按此收敛 |
| D6 | **保存的追问可升级为前提题** | 抄设计 | 我们的局部提问已经会写误解记录；再往前一步，就是把反复出现的卡点变成大纲里的前置节点 |
| D7 | **安装自检清单**：从库内容算出，不用模型 | 抄设计 | 阅读端第一次打开时的"还差什么"面板 |
| D8 | **特性按"使用时机"分层**（每门课一次 / 每天 / 周期性），不按付费分层 | 抄设计 | 组织阅读端信息架构的依据 |
| D9 | **反馈台账**：编号 + 影响 / 频率 / 证据 / 状态 | 抄设计 | 有真实用户的开源项目需要它 |

## 4. 明确不采纳的清单

不采纳同样要记账——否则半年后会有人重新提一遍。

| 不采纳 | 理由 |
|---|---|
| 卡片 + SM-2 间隔重复调度 | 方向是**应用技能专攻**，不是应试专攻；复习队列与调度算法都不进本次范围（理由见 [目标态规格](目标态规格.md) 的非目标一节） |
| 正文级逐字引用与来源校验 | 我们的引用需求集中在"图片级来源"与「资源清单」；把正文每段绑到某条来源，成本与收益不成比例 |
| 音频 / 转写 / 字幕 / 直播课堂 | 需外部付费服务与密钥管理，与"应用技能专攻"关联弱；写进非目标 |
| 向量检索 / RAG / 嵌入索引 | 工作区是纯文本、体量小，按需扫描的内存索引足够 |
| 免费 / 付费分层、用量统计、商业化埋点 | 无商业化计划 |
| 双语错误信息的正则表（用字符串匹配做 i18n） | 反面教材：错误文案一改就失配 |
| 内容寻址分片的缓存机制（`FinalizationRegistry` / 共享冻结分片 / 私有模式开关） | 对方自己记录过它引入的别名 bug，且是为一个基准数字调的；SQLite 一类的方案能替掉它的大半 |
| 六种卡片类型 + 案例卷 | 应试形状的题型体系 |
| 数学 / 化学符号证明器、UML 画布、看板、跨工作区笔记本、CSV/Anki 导出 | 与学习闭环正交，或明确被用户否决过 |
| 明说"永不毕业"的实验性决策层 | 对方文档自己写明它不会毕业 |
| 站点（截图 + HTML 字符串替换） | 与产品无关 |
| 三十余路 i18n 分片、六十余份样式表、单文件两千余行的主组件 | 规模本身就是负担；机制可借，切法不抄 |

## 5. 这份评估推翻了我们自己的哪些既有决定

诚实记账。以下每一条都写进了 ADR：

| 被推翻的现行决定 | 现行出处 | 新决定 |
|---|---|---|
| 引擎是 Python 脚本集，靠 bash 命令驱动 | [工程约束 §四](../规范/工程约束.md) | 引擎整体迁 TypeScript，注册为原生工具（[ADR-0002](../adr/0002-引擎改用TypeScript.md)） |
| 静态 HTML 是默认交付，`file://` 打开 | [设计方案 §3.5](设计方案.md) | 降为导出能力（[ADR-0005](../adr/0005-静态页面降为导出.md)） |
| 同时支持 DSH / Antigravity / Codex 三宿主 | [工程约束 §一](../规范/工程约束.md) | 阅读端只嵌 DSH；其余两端走无头 CLI + 导出（[ADR-0003](../adr/0003-阅读端只嵌DSH.md)） |
| 学习数据格式一律冻结 | 本次调研的早期结论 | 布局与文件名冻结，状态词表精简为三档并配映射（[ADR-0004](../adr/0004-学习数据格式冻结与例外.md)） |
