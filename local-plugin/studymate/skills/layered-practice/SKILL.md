## OpenAI 宿主约定（导出时生成）

- **引擎定位**：本文件位于 `<root>/skills/<技能名>/SKILL.md`；从实际文件路径定位包含 `skills/`、`scripts/`、`templates/`、`schemas/`、`docs/` 的插件根目录，记为 `<root>`。引擎与插件缓存只读，学习数据写入另一个可写工作区。所有相对的脚本、模板、schema、文档路径均相对 `<root>`；参考文档中的旧宿主安装说明不参与本插件启动。
- **加载协议**：正文说“加载某技能”时，用宿主文件读取工具读 `<root>/skills/<技能名>/SKILL.md`；不需要专门的技能调用工具。缺少文件读取能力时说明具体缺项，不声称已加载。所有角色的教学职责与文件归属保持不变。
- **工作区**：总控传入的 `<LEARN_WORKSPACE>` 与 `subject_path` 必须是实际绝对路径；新会话按总控的“会话开场”恢复。不要把插件目录、缓存或未知的当前目录当作学习数据目录。角色不另选工作区。
- **工具能力**：只使用宿主实际提供的提问、浏览、文件读写、图片查看、命令执行、委派与预览工具。提问工具不可用时总控用普通对话提问；角色把待问事项交给总控。检索不可用时记录未核验来源与 Gaps，不编造核验结果；图片不可取得时允许空图片库。文件或执行工具不可用时可以继续讨论，但具体生成、持久化与校验必须如实标为未完成。
- **角色执行**：总控阶段的调度动作由总控执行（角色自己能派什么由各自规格决定，规格没写就不派）。有委派工具时按总控规范分工；没有委派工具时由总控按角色规格串行执行，每段读取对应规格，以“准备讲解/核对练习”等工作内容报告进度，完成产物与检查后才切回总控。不得假称启动了子 agent；串行执行仍保留正文→出题→原样搬运→渲染的顺序、题目唯一 owner 与档案归属，不能用总控身份随手改角色产物。
- **暂存位置**：总控在宿主允许的可写临时目录，或工作区内专用暂存目录，分配每会话唯一的 `<STUDYMATE_SCRATCH>`，再按角色与节点分目录并传绝对路径。不同会话、不同角色不共享固定草稿目录；不要假定任何操作系统的临时目录路径。
- **Python 与命令**：先探测 Python 3.10+、PyYAML（`yaml`）与 JSON Schema 校验器（`jsonschema`）可用；`<python>` 表示已验证的解释器调用，可为 `python3`、`python`、`py -3` 或绝对路径；后续调用加 `-X utf8`。PowerShell 调用带引号的可执行文件路径要加 `&`；路径参数使用宿主 shell 的字面值引用与转义（PowerShell 单引号内的单引号写两次）。优先使用工具的参数数组，不能把路径或学生文本拼成未引用的命令。按当前操作系统选择可用的 lab 测试命令。依赖缺失由总控在获准的可写环境内处理，角色不建环境，插件缓存内不装依赖。
- **逐次显式传参**：调用主页生成器始终传 `'<LEARN_WORKSPACE>'`；各命令都传脚本与数据的绝对路径。环境变量、工作目录与 shell 状态不保证跨工具调用保留，确需设置时在每次调用内设置。跨会话只信实际存在的文件，不能以聊天记忆替代磁盘恢复。
- **原样搬运**：用宿主文件复制工具，或 Python 标准库 `shutil.copy2`（文件）、`shutil.copytree(..., dirs_exist_ok=True)`（目录合并）完成；保留 `deliver/` 中相对路径，不经模型重写题面、答案与长产物。Windows 可用 PowerShell 的 `Copy-Item -LiteralPath`；不要依赖别的平台的复制、摘要或打开页面命令。
- **展示与持续保存**：页面写盘并校验后用宿主可用的文件预览/浏览器展示，同时给可点击的绝对文件链接；沙箱文件使用宿主支持的下载/附件链接。无预览能力时仍交付文件链接与位置。ChatGPT Work 或其他临时沙箱中，先核实文件是否能跨会话保留；不确定就明确说明，并在结束时交付包含 `index.html` 与完整 `.learning/`（含隐藏目录）的可下载归档，下一次从用户提供的归档恢复，不承诺本机目录或沙箱会永久保留。

## Codex 内部规范

本文件是供当前执行者读取的规范；加载它不创建新角色，也不改变调用者身份。总控可以按本规范答疑、维护档案和交互断点；委派角色仍只完成自己的产物，不接管学生对话或总控档案。用户直接选择本规范来继续学习时，先读 `<root>/skills/learning-system/SKILL.md` 并恢复当前学习位置，不从头盘问。

# 题目规范

**数据字段**以 `templates/assets/quiz.js` 顶部注释为准，本规范不重复字段表——本规范管**出什么题、怎么要求、什么算过**。（判分要点在字段契约里叫 `criteria`。）

## 一、四层

| 层 | 类型 | 出题要求 | 通过标准 |
|----|------|---------|---------|
| L1 理解 | 判断/解释/预测输出 | 每题追问"为什么" | 能解释原因，不只给结论 |
| L2 改造 | 修改已有代码观察变化 | 给可运行的 10-20 行代码，指定一处改动 | 能预测改动结果并运行验证 |
| L3 排错 | 真实 bug 定位 | 给含 1-2 个 bug 的代码或真实报错 | 能说出根因 + 修复 + 预防 |
| L4 应用 | 放进真实项目 | 任务挂到项目上，交付物明确 | 代码跑通 + 测试通过 + 能解释取舍 |

**层级上限由课型定**：`kind: 概念` 止于 L3；`kind: 实操` 与 `kind: 实验` 可到 L4。**L1-L4 是"题"的词汇，不进页面**：它用来选出题深度、记进评估记录的 `layer` 字段；页面上的题只写题面、选项／参考答案、要点，不挂 L 标，也**不要用 L1-L4 标练习块或练习步骤**（那些标题按内容写，如"第 3 步 · 改造"）。

## 二、四种题型

| 题型 | 长什么样 | 判分 | 适合的层 |
|------|---------|------|---------|
| **选择题** | 页内 `.quiz`，点选项即时反馈 + 一句 `why` | 页内自动判 | L1、部分 L2 |
| **开放题** | 页内出题，学生先自己想/写，**参考答案与判分要点点击展开**（不贴回会话） | 学生自评 | L1 追问为什么、L2 预测、L3 找根因 |
| **实操题** | `lab/` 的留白任务 + 断言 + `solutions/`，学生亲手写代码 | 载体自带的测试命令自动判（`npm test`／`make test`／当前系统可运行的测试入口…） | L2、L3、L4 |
| **评估题** | **阶段评估**时出的 1 题（最多 2 题，开放） | `practice-evaluator` 判 | 按目标层级 |

选题型：**能自动判的优先选择题；要"说清为什么／找根因／解释取舍"的用开放题；要真跑代码的用实操题。**

## 三、出题要求

- 贴近生产场景与真实报错，**坚决避免"背诵定义"的「教条主义」**
- 选择题选项尽量等长、同句式（长度泄露答案，检查只 `WARN` 不阻断）
- **开放题必须同时给参考答案与标准**——学生据此自评，缺一不可；答案不唯一时参考答案要给出可接受的替代方案与判断依据，备好常见错误答案，供批改对照
- 实操题写成可核验的（断言／期望输出／清单），`solutions/` 与任务分开放、做完才对照
- **题量按"学生作答总时长"估，目标 ≤10 分钟**（不设下限也不硬限题数）：实操课与实验课把题量让给练习，概念课可以多问几道；开放题的参考答案要克制，别写成小作文
- **评估题只问理解与权衡**：对比、因果、预测、取舍、迁移（如"改了这一处会怎样""你项目里哪一处能用上"）。**不问机械回忆**——文件名、命令原文、终端输出、报错的行号列号这类东西，要么由 `lab/` 的断言机器验，要么本就没有教学价值；"想不起来"不该成为判定依据
- 一次最多 2 题，**每题最多 3 个小问**；评估的总作答时间 ≤5 分钟
- **题面里的数学写 `$…$`**（LaTeX，页面上由离线 KaTeX 排版）：矩阵、方程组、求和这类直接写公式，别用空格对齐的 ASCII 或 Unicode 下标去凑；**方程组要带大括号**（`cases` 或 `\left\{…\right.` 都行，KaTeX 不会自己加）；`$` 之间首尾不能是空白，正文里的美元号写 `\$`
- **题面超过一行就自己排版**：题面是纯文本写进页面的，`\n` 会原样保留，**换行位置由作者定、不由容器宽度定**。枚举多个小问（①②③）时每项各自起一行；**多行代码一律写进 ` ``` ` 围栏**（起止各占一整行，中间照原样写；字段与写法见 `templates/assets/quiz.js` 顶部契约）。**行长分两类判**（排错题必然要贴代码，代码天生比散文宽）：

  | 这一行是什么 | 上限 |
  |---|---|
  | 纯散文行（题干、设问、说明） | ≤40 字 |
  | 围栏里的代码行 | ≤60 字（按显示宽度算；再长代码块就横向滚动了） |
  | 靠空格对齐的注释列 | **放进围栏**里照原样对齐；裸写的多行会被折叠，读不出对齐 |

  选项（`opts`）不换行；参考答案与判分要点同样适用本条
- 出题前先读节点的 `objective`、学生最近的 misconceptions、目标层级；每题的判分要点写进 `criteria`（必填，学生点开对照时看到的就是它）

## 四、三种课型（「课程大纲」的 `kind`）

| `kind` | 是什么 | 产出 | 题目上限 |
|--------|--------|------|---------|
| **概念** | 普通课，只讲不落 lab | 课件（讲解 + 轻量练习） | L3 |
| **实操** | 普通课，学一点练一点 | 课件 + **自己的小 lab**（当课练习） | L4 |
| **实验** | **里程碑验收课**：与普通课同级插在大纲里，验收"学到目前的知识能做出什么" | **实验说明页**（任务书）+ 实操任务（任务本身就是验收） | L4 |

实验课的前置关系写在 `prerequisites`，实际验收范围另由覆盖目标与运行证据确定；进度与置位规则见 `record-keeping`。

## 五、判分要点

- 结论三档：`通过 / 部分通过（列出缺哪条）/ 不通过（列出原因）`，并给"差一步就能过"的具体建议
- **每条结论必须指向一条具体证据**（作答原文、运行结果、交付物）；指不出具体证据按"不通过"处理
- **不得因为"题是我出的"或"学生说懂了"就判过**——说懂了不是证据。证据可信度排序见 `evidence-check`

## 六、实操题（lab）规范

**载体由总控与学生确定**（写盘时机与搬运见 `record-keeping` 的「科目文件夹」「课件三份产物的归属」）；本节只管载体定下来后怎么做；讲解角色不碰 lab。实验课用同一套要求，另加一份实验说明页——**说明页也是内容格式正文**（语法见 `<root>/docs/规范/课件内容格式.md`），不是 HTML。

不管什么载体，都要做到这五条：**分步引导**（一小步讲解 + 立刻上手，不一次抛完整任务）；**亲手做**（任务留白给学生写，成品只放 `lab/solutions/`，做完才对照）；**可验证**（能自动验的写断言，不能的给自查清单／期望输出）；**即时反馈**（做完立刻能验，不等 agent）；**卡壳先引导**（读错误信息 → 提示 → 线索，不给答案）。教程部分要带结果（其他语言先跑一遍或贴运行结果）；任务写清"要做什么、要点是什么"。

结构（编号与课件同源）：任务与断言放 `lab/NNNN-主题/`（或 `NNNN-主题.ipynb`）；答案放 `lab/solutions/NNNN-主题/`，与任务分开放、做完才对照；`lab/README.md` 写载体与环境依赖 + 任务表与卡壳顺序。

**参考解必须自包含**：学生把 `solutions/` 里的文件拷进自己的任务目录后要能直接编译、直接跑——参考解引用的模板、头文件、夹具都得在它自己那份里；要单独入库的模板（如 `myfastio.h`）另存一份进任务目录，并在 `README.md` 写明两者分工。

## 七、题目位置与锚点

**题目位置**是「课件内容文件」里给题留的位置，讲解角色写成一行指令 `::: quiz <层级> 锚点：<锚点文本>`（指令的准确写法见 `<root>/docs/规范/课件内容格式.md`）。**锚点文本是两个文件之间的唯一接头**：你按它出题，「练习题库」用同一串文本作键（键与「课件内容文件」的锚点逐字对应，对不上渲染器报错；结构见 `<root>/docs/规范/课件内容格式.md` 第 4 节），渲染器按它把题放进页面——锚点写错或被改写＝报错，不会静默少一道题。

- **练习段落不是一个题目位置**：`::: practice` 的层级是给学生看的**徽标**，写 `练习`／`上手做` 这类中文阶段名（见 `<root>/docs/规范/课件内容格式.md`）；它**不写、也不接受 `empty_reason`**——那是给无题锚点用的，只属于 `::: quiz`。
- **`empty_reason` 由你决定、总控用脚本打进去**：某个锚点这轮不该出题，你就对它交回一行 `empty_reason: <理由>`（`scripts/apply_empty_reasons.py` 打进内容文件，讲解角色不写）；**锚点有题却写了 `empty_reason:` 也报错**。
- 每处放几道题按第三节的题量估；位的**数量不预设**、按内容定，但每一处都要有交代（收紧到相邻题，或对该锚点交回 `empty_reason`）。
- **只有 `::: quiz` 的层级是元信息**（理解／改造／排错／应用是选深度的词汇，锚点才是文件之间的接头），它不落到页面上。
- **对照由渲染器完成，没有人手抄**：你只能按锚点逐字对，对不上一律报错——别按序号对照，两处序号不一致时会**静默错位**。

## 本地修改版的数据契约

本节与旧示例冲突时以本节为准。执行前读取 `<root>/docs/使用/本地修改版.md`。使用同一已验证 Python 3.10+ 环境并安装 requirements.txt。学习数据只写独立工作区；使用宿主会话 ID 作为稳定 session_id，所有断点命令传 --session-id 和 --subject，暂存只清理本会话的具体任务目录。

- 页面作答必须先导出，再由 learning_records.py import 归档。聊天回答也按相同题目身份/版本、首答时间和帮助字段留存。不能用“已读”“答对了”替代原文。
- 正式升级经 learning_records.py assess；只更新 covered_objectives 对应节点，附 criterion、原始作答或实际产物哈希。首答错、先看答案或有帮助的成功不能证明独立应用；旧状态保留且标记未核验。mastery 仅是 AI 建议值。
- 继续学习先查询 review_scheduler.py due。仅给关键知识点和真实错题建立 register 项，先独立回忆再四档评分，record 或普通 import 使用同一入口计算日期。未评分不调度，帮助练习不推进正式间隔，错误自评应为 Again。FSRS 到期不改变章节进度，迁移和应用能力仍按实际项目证据判断。
- 有教材文件夹或公开课程时先 source_index.py scan/fetch/search，引用 source_id/source_version/locator；原件只读，扫描 PDF 无文本应注明需 OCR，视频只使用现有字幕。
- 采用原课程时用 course_import.py 的 existing 模式，保持原 unit_id、顺序、章节粒度和作业；生成解释/题目注明补充，不强制 40 分钟拆章或自编实验。更新先审阅差异，不自行传 --accept-changes。
