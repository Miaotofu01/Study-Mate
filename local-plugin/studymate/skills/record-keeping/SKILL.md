## OpenAI 宿主约定（导出时生成）

- **引擎定位**：本文件位于 `<root>/skills/<技能名>/SKILL.md`；从实际文件路径定位包含 `skills/`、`scripts/`、`templates/`、`schemas/`、`docs/` 的插件根目录，记为 `<root>`。引擎与插件缓存只读，学习数据写入另一个可写工作区。所有相对的脚本、模板、schema、文档路径均相对 `<root>`；参考文档中的旧宿主安装说明不参与本插件启动。
- **加载协议**：正文说“加载某技能”时，用宿主文件读取工具读 `<root>/skills/<技能名>/SKILL.md`；不需要专门的技能调用工具。缺少文件读取能力时说明具体缺项，不声称已加载。所有角色的教学职责与文件归属保持不变。
- **工作区**：总控传入的 `<LEARN_WORKSPACE>` 与 `subject_path` 必须是实际绝对路径；新会话按总控的“会话开场”恢复。不要把插件目录、缓存或未知的当前目录当作学习数据目录。角色不另选工作区。
- **工具能力**：只使用宿主实际提供的提问、浏览、文件读写、图片查看、命令执行、委派与预览工具。提问工具不可用时总控用普通对话提问；角色把待问事项交给总控。检索不可用时记录未核验来源与 Gaps，不编造核验结果；图片不可取得时允许空图片库。文件或执行工具不可用时可以继续讨论，但具体生成、持久化与校验必须如实标为未完成。
- **角色执行**：总控阶段的调度动作由总控执行（角色自己能派什么由各自规格决定，规格没写就不派）。有委派工具时按总控规范分工；没有委派工具时由总控按角色规格串行执行，每段读取对应规格，以“准备讲解/核对练习”等工作内容报告进度，完成产物与检查后才切回总控。不得假称启动了子 agent；串行执行仍保留正文→出题→原样搬运→渲染的顺序、题目唯一 owner 与档案归属，不能用总控身份随手改角色产物。
- **暂存位置**：总控在宿主允许的可写临时目录，或工作区内专用暂存目录，分配每会话唯一的 `<STUDYMATE_SCRATCH>`，再按角色与节点分目录并传绝对路径。不同会话、不同角色不共享固定草稿目录；不要假定任何操作系统的临时目录路径。
- **Python 与命令**：先探测 Python 3.10+、PyYAML（`yaml`）与 JSON Schema 校验器（`jsonschema`）可用；`<python>` 表示已验证的解释器调用，可为 `python3`、`python`、`py -3` 或绝对路径；后续调用加 `-X utf8`。PowerShell 调用带引号的可执行文件路径要加 `&`；路径参数使用宿主 shell 的字面值引用与转义（PowerShell 单引号内的单引号写两次）。优先使用工具的参数数组，不能把路径或学生文本拼成未引用的命令。按当前操作系统选择可用的 lab 测试命令。依赖缺失由总控在获准的可写环境内处理，角色不建环境，插件缓存内不装依赖。
- **逐次显式传参**：调用主页生成器始终传 `'<LEARN_WORKSPACE>'`；各命令都传脚本与数据的绝对路径。环境变量、工作目录与 shell 状态不保证跨工具调用保留，确需设置时在每次调用内设置。跨会话只信实际存在的文件，不能以聊天记忆替代磁盘恢复。
- **原样搬运**：用宿主文件复制工具，或 Python 标准库 `shutil.copy2`（文件）、`shutil.copytree(..., dirs_exist_ok=True)`（目录合并）完成；保留 `deliver/` 中相对路径，不经模型重写题面、答案与长产物。Windows 可用 PowerShell 的 `Copy-Item -LiteralPath`；不要依赖别的平台的复制、摘要或打开页面命令。
- **展示与持续保存**：页面写盘并校验后用宿主可用的文件预览/浏览器展示，同时给可点击的绝对文件链接；沙箱文件使用宿主支持的下载/附件链接。无预览能力时仍交付文件链接与位置。ChatGPT Work 或其他临时沙箱中，先核实文件是否能跨会话保留；不确定就明确说明，并在结束时交付包含 `index.html` 与完整 `.learning/`（含隐藏目录）的可下载归档，下一次从用户提供的归档恢复，不承诺本机目录或沙箱会永久保留。

## Codex 内部规范

本文件是供当前执行者读取的规范；加载它不创建新角色，也不改变调用者身份。总控可以按本规范答疑、维护档案和交互断点；委派角色仍只完成自己的产物，不接管学生对话或总控档案。用户直接选择本规范来继续学习时，先读 `<root>/skills/learning-system/SKILL.md` 并恢复当前学习位置，不从头盘问。

学习状态由你（主教练）亲自读写，不派角色。路径以 `<LEARN_WORKSPACE>`（总控开场按用户目录、环境变量、显式配置或既有学习数据确定）为前缀；下面所有路径里的 `<LEARN_WORKSPACE>` 都指这一个值：

## 工作区根与落点交付

**工作区根**：按「OpenAI 宿主约定」选定 `<LEARN_WORKSPACE>`（用户本次指定目录 → 环境变量 → 显式配置 → 既有学习数据），不假定操作系统临时目录路径；暂存与中间产物写本会话的 `<STUDYMATE_SCRATCH>`（或工作区内专用暂存目录），需要后续步骤读到的内容一律写进 `<LEARN_WORKSPACE>`。

- **开课时跟学生说一句**"课程先建在会话目录下的临时工作区，结束时你挑一个位置落盘"
- **暂时写不进去**（工作区不可写）→ 只询问学生保存位置，并说明缺的是哪一项能力；**不要靠反复提权推进**
- **已有科目要接着学**：先把它**拷进 `<LEARN_WORKSPACE>`** 再继续；「会话摘要」与「学习记录」都按 `<LEARN_WORKSPACE>` 写
- **别拿临时目录当中转站**：需要后续步骤读到的内容写进 `<LEARN_WORKSPACE>` 或 `<subject_path>/.stage/<session_id>/`，临时目录只放不需要留存的中间文件
- **落点偏好开场恢复**：顺手读一次 `<STUDYMATE_SCRATCH>/prefs.md` 的 `default_delivery`——有、且那个目录还在 → 记成**默认落点**，收尾时它排在第一项、**不再重复问**；没有或路径已失效 → 照常问一次

**暂存模式的两条硬约束**：

- ① **跨工具接力只在 `<LEARN_WORKSPACE>` 之下成立**：**每次落盘的下一步要能看见它**——建目录、原样复制 组件、渲染、`gen_home.py` 尽量串在同一条 bash 命令里（`&&` 连接）
- ② 角色产出走科目内的 `<subject_path>/.stage/<session_id>/`，落点按 `<角色>-<节点id>/deliver/` 分层，你 原样复制 搬入的随后只清理当前会话的任务目录，**交付前当前会话已交付的任务目录必须清理，其他会话目录保留**

**暂存模式的额外规则**（走暂存工作区时）：搬走后不再当工作区用，下次会话重新建

### 收尾：问一次落点并搬走

走暂存工作区时做，会话目录本身就是工作区时跳过。`gen_home.py` 之后、报告之前，用 宿主提问工具 **问一次成品放哪**——**有默认落点就把它放第一项并标"(Recommended)"**（写成"上次的位置：`<路径>`"），没有就按 **学习工作区**（配置里的 `workspace`，平时都在那，放进去就能续学）／**桌面**／**文档文件夹**／**用户根目录**／自定义路径／"先留在会话目录里"。学生选定后：

- **持久工作区直接保存；临时交付采用归档**：仅清理当前会话任务目录，复制或 ZIP 归档指定产物，核验后交付；不删除整个学习工作区。再把 `<目标>/<slug>/` 的「根主页」呈上（链接是相对的，`cp -a` 后照样能开）。**目标在会话目录里**就不用 原样复制；**落点是学习工作区**时先 `mkdir -p '<LEARN_WORKSPACE>/.learning/subjects'`，搬完 `cd` 过去跑一次 `<python> -X utf8 -B '<root>/scripts/gen_home.py' '<LEARN_WORKSPACE>'` 刷新「根主页」。另外三个目标都在会话目录外 → 这条命令会弹一次提权，**理由里写明"学生已选择目标目录 <路径>"**（整场学习里预期内的唯一一次）
- **落点要记住（这是持久化那一步，别漏）**：搬完用 `write` 把偏好写进 **`<STUDYMATE_SCRATCH>/prefs.md`**，形如 `default_delivery: <绝对路径>`；已有这个文件就**只改这一行**，别整文件覆盖
- **想改全局定位才需要提权**：`宿主的全局工作区配置` 里的 `workspace` 是**机器全局**的、在会话写边界外，**不要默默去改**。要改就先问学生一句"以后默认就用这个位置吗"，他同意后**一条命令**改写那个键（保留其它键不动）；他不同意就只留 `prefs.md` 与摘要
- 会话摘要里写明"这次建在会话目录下的临时工作区、已搬到 `<目标>`"（见「读写规则」第 4 条），并在对话里给一条 `memory_updates` 建议（"最近落点：`<目标>`"），学生确认后写进「共享记忆」的「学习习惯」一节

## 共享记忆

按模板分节（我是谁 / 教学偏好 / 学习习惯 / 跨科目观察）增补与修正。只记跨科目、跨会话仍成立的东西；知识点细节留给该科目的 misconceptions。

## 科目文件夹

1. **新建**：建 `subjects/<slug>/` 与 `lessons/`、`reference/`、`assets/`、`learning-records/`、`sessions/`、`assessments/`；按 `<root>/templates/subject.yaml` 建「科目档案」（`created_at` 填当天）；`assets/` 只从 `<root>/templates/assets/` 拷 lessonfile.SUBJECT_FILES 清单中的五个组件。**`lab/` 不预建**——只有 `kind: 实操/实验` 的节点才需要。盘问时定下的**载体**先随派工 prompt 传给 `practice-evaluator`，等**首个实操/实验节点**建「实操任务」时再写盘进「lab 说明」（那之前没有 `lab/` 不是漏了）
2. **列出**：读各科目的「科目档案」，汇总"科目名 + 状态 + 上次学习日期 + 当前节点"
3. **切换**：切换即换路径，不复制不搬运
4. **共享组件更新后同步到已有科目**：`<root>/templates/assets/` 里的 `style.css`、`quiz.js`、`lesson-toc.js` 一改，各科目「科目组件」里的同名副本就旧了，要一起覆盖——科目自己新增的组件不动
5. **「图片库」是科目自己的**：图片与「图片库索引」**不从 `<root>/templates/` 同步**，由「采图」建、由课件消费。**已引用的图不能删**：删之前先 宿主文本搜索工具 一遍课件与「速查页」，还有页面指着它就留着；补图只增不删。命名与索引格式见采图规格。图片库是**学习产物，随科目整体拷贝或迁移时跟着走**（`.venv` 那类工具链不进包）

## 课件三份产物的归属（`lessons/`）

一个节点的课件是**三份产物**——「课件内容文件」+「练习题库」+「课件页面」——各有 owner，**别手改渲染产物**：

| 文件 | 谁写 | 里面是什么 |
|---|---|---|
| 「课件内容文件」 | 课件正文归「讲解」（它直接写科目目录）；**`kind: 实验` 的说明页由你 原样复制 原样搬入** | 讲解、练习的引入、配图、题目位置（`::: quiz` 的锚点）；出题人交回的 `empty_reason:` 由你跑 `scripts/apply_empty_reasons.py` 打进去 |
| 「练习题库」 | 「出题评估」出题落 `deliver/`、你 原样复制 搬入（**题面与答案一个字都不改**） | 键与内容文件的锚点逐字对应、对不上渲染器报错（结构见 `docs/规范/课件内容格式.md` 第 4 节） |
| 「课件页面」 | `<python> -X utf8 -B '<root>/scripts/render_lesson.py' '<subject_path>' '<节点id>'` | 学生看的页面；谁也不手改 |

- **改课件＝改源文件，再重渲**：内容改「课件内容文件」、题目改「练习题库」，然后重跑渲染器；直接改「课件页面」会在下次渲染时被冲掉，两份文件还会对不上
- **旧的手写课件并存**：`lessons/` 里已交付的「课件页面」不重渲、不搬家，检查照旧判它们（含题目位置残留那条）；新建的节点一律走三份产物——**`kind: 实验` 的说明页不出题，没有「练习题库」，就是「课件内容文件」+「课件页面」两件**
- 渲染报 `<文件>:<行>` 的按归属打回：内容 →「讲解」，题库与锚点 →「出题评估」

## 学习记录

记成「学习记录」（`NNNN-dash-case.md`，编号递增），作为下次教什么的依据。**写一条当且仅当出现可观察的证据**：学生正确用出了概念、主动说明已知某知识、误解被纠正。覆盖了但没证据的不记，纯进度日志不记。被更新的理解标 `Status: superseded by LR-NNNN`，不删除。

## 评估记录

「出题评估」把「评估记录」写成 `deliver/assessments/NNNN-<节点id>.md`，**你 原样复制 搬入**（正文含题面与作答原文）：

1. 命名 `NNNN-<节点id>.md`（编号递增），存 `subjects/<slug>/assessments/`
2. `.md` 文件，**YAML frontmatter 承载 `assessment.schema.json` 的字段**（日期加引号），正文写题面与作答原文
3. 逐题结论的依据写进该题的 `note`（对的是哪条判分要点、缺哪一条）
4. 同时双落点记误解（「误解库」+「学习进度」的 `misconceptions`）

## 项目与实验课

「学习进度」的 `project` **只有一句"在做的是什么"**（`current`；schema 只要求这一个键）。**里程碑不在这里**——它们就是 `kind: 实验` 的验收课节点，进度就在 `nodes` 里（课型见 `layered-practice` 第四节）。

- **实验课通过时（硬规则）**：仅将实际产物和测试覆盖的节点置为「**已通过项目验证**」；前置关系本身不能充当验收证据，再写一条学习记录（"实验通过：<标题>"）。这是"项目推进"的唯一依据，不要凭印象提前置、也不要漏置
`current` 按学生明确选择更新，有歧义才澄清

## 主页刷新

主页是生成产物（模板在 `<root>/templates/`）：**刷新 = 跑 `<python> -X utf8 -B '<root>/scripts/gen_home.py' '<LEARN_WORKSPACE>'`**（一次刷新「根主页」与所有「科目主页」；`<LEARN_WORKSPACE>` 按开场定的工作区根传，暂存模式传临时工作区），覆盖旧文件、不改数据文件。非零退出看 stderr——断链或某个科目数据读不出来，修完重跑。时机：新建科目后、节点状态变化后、材料新增后、会话结束前。

## 读写规则（硬约束）

1. 写前先读现有内容，**增量修改**（不整文件覆盖，「共享记忆」/「科目档案」的新建除外）
2. 写后校验：「课程大纲」「学习进度」「科目档案」、评估记录 frontmatter 分别对照 `<root>/schemas/*.json`；会话摘要对照 `session-summary.schema.json`
3. **写入类型化的状态**：结构化事实进 YAML，偏好与观察进「共享记忆」
4. **会话摘要**（会话结束时）：按 session-summary schema 生成，存 `subjects/<slug>/sessions/<YYYY-MM-DD>.md`（同日多段追加）；**YAML frontmatter 承载 schema 字段**（日期加引号），正文写本次要点；需要确认的 `memory_updates` 先保留在摘要，不在学生结束时追加弹窗；仅在获得实际确认后写入共享记忆
   - **落点也写进摘要正文**：这次收尾搬到哪（"已搬到 `<目标>`"）——下次开场按「工作区根与落点交付」恢复默认落点
5. **恢复视图**（开场自读）：「共享记忆」相关分节 + 当前节点 + 前置节点摘要 + 最近 5 条 misconceptions + 最近 3 条学习记录 + 最近 3 条评估记录 + 实验课节点进度与 `project.current`。只读需要的部分（分段读取/文本搜索），不把长文件整份读进来
6. **进度只认「学习进度」**：「课程大纲」的每个节点也带 `status`/`mastery`（schema 要求），那是**建课时的初始快照**，建课后不再回头维护；运行期的状态只写「学习进度」、也只读它——里面**只记有变化的节点**，没写的按大纲里的初始值算（`gen_home.py` 就是这么合并的）。两份文件都改是漂移的源头

## 边界

- 课程内容归「课设」，课件/题库/lab/页面的归属见上面的表。你只读写状态与元数据，发现不一致以文件为准并修正记录
- 档案存结构化摘要，聊天的原始过程留在会话里
- 科目之间隔离：只读当前科目，唯一的跨科目来源是「共享记忆」
- 只在 `<LEARN_WORKSPACE>/` 下写学习文件，不写插件缓存或工作区之外的会话目录（会话目录是别人的代码仓）；暂存工作区的口径见上面的「工作区根与落点交付」，**不把学习数据写进别的科目**

## Codex 交互断点（总控独占）

在工作区 `.learning/interactions/<session_id>/<subject>/interaction.json` 记录活跃科目、节点、阶段、已收到的选择、待问项与下一步；它只用于衔接，不替代 progress.yaml、评估证据或共享记忆。通过 `<root>/scripts/interaction_state.py` 读写，具体字段与命令见 `<root>/skills/learning-system/references/codex-interaction.md`。

- 首次读不到文件是正常情况，从已有档案恢复；不要迁移或清空 DSH 数据。恢复时还读最近一份会话摘要的 next_step，与真实产物核对。
- 在发问前、接受答案后、材料通过检查后、切换科目和暂停前保存断点，不能只在正常结束时写摘要。先更新对应正式档案、核对产物，再保存指向这些事实的阶段；失败停留在未完成步骤。
- 写入使用读到的 revision；冲突就重读并核对当前请求，不用新 revision 强行覆盖另一会话。损坏、未知版本或无写权限时保留原文件并说明恢复能力受限；本轮仍可对话，不假称保存成功。
- 科目切换时清除旧待问项，选项以题目 id 和科目区分；曾回答的问题不重问，过期或重复回传不再次改档案。学习原始作答按评估规则保存，不能仅存选项标签代替证据。


## 本地修改版的数据契约

本节与旧示例冲突时以本节为准。执行前读取 `<root>/docs/使用/本地修改版.md`。使用同一已验证 Python 3.10+ 环境并安装 requirements.txt。学习数据只写独立工作区；使用宿主会话 ID 作为稳定 session_id，所有断点命令传 --session-id 和 --subject，暂存只清理本会话的具体任务目录。

- 页面作答必须先导出，再由 learning_records.py import 归档。聊天回答也按相同题目身份/版本、首答时间和帮助字段留存。不能用“已读”“答对了”替代原文。
- 正式升级经 learning_records.py assess；只更新 covered_objectives 对应节点，附 criterion、原始作答或实际产物哈希。首答错、先看答案或有帮助的成功不能证明独立应用；旧状态保留且标记未核验。mastery 仅是 AI 建议值。
- 继续学习先查询 review_scheduler.py due。仅给关键知识点和真实错题建立 register 项，先独立回忆再四档评分，record 或普通 import 使用同一入口计算日期。未评分不调度，帮助练习不推进正式间隔，错误自评应为 Again。FSRS 到期不改变章节进度，迁移和应用能力仍按实际项目证据判断。
- 有教材文件夹或公开课程时先 source_index.py scan/fetch/search，引用 source_id/source_version/locator；原件只读，扫描 PDF 无文本应注明需 OCR，视频只使用现有字幕。
- 采用原课程时用 course_import.py 的 existing 模式，保持原 unit_id、顺序、章节粒度和作业；生成解释/题目注明补充，不强制 40 分钟拆章或自编实验。更新先审阅差异，不自行传 --accept-changes。
