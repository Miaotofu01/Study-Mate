## 1. 模型提供商

### 1.1 数据模型

系统支持配置**多个模型提供商**，其中一个处于"当前使用"状态。

- 提供商条目包含：名称、类别（预设 / 自定义）、Base URL、API Key、API 格式（三选一，见第 2 节）、模型列表、启用开关、创建时间。
- 模型列表：每项包含模型名（发送给 API 的 id，即 ZCode 口径的"模型 ID"）、显示名（可空，空则显示模型名）、**输入模态**（文本 / 图片 / 视频 / PDF 四项布尔，见第 3 节）、上下文窗口、**最大输出 Token**（见 §2.1）、**推理档位**（有序档位名列表 + 默认档位，见 §2.1）、能力声明（工具调用 / JSON Schema 输出 / 原生联网搜索；**工具调用默认对所有配置的模型开启**，不再是可选项，上游拒绝 tools 参数时自动回落纯文本，见第 14 节；其余两项仅落盘与展示）、启用开关；每个提供商至少保留一个模型。
- 当前使用状态是"提供商 + 模型（+ 当前推理档位）"三元组，全局生效。
- 停用的提供商不能被设为当前使用，其模型不出现在对话侧的模型选择里；当前使用的模型被停用时，自动回落到该提供商第一个可用模型。
- 模型字段的取值口径**对齐 ZCode**（`properties.inputFormat` / `properties.contextWindow` / `optionSpecs.maxOutputTokens` / `optionSpecs.reasoningLevel`）：模态是多值布尔而不是单选，推理档位是**用户可自由编辑的有序字符串数组**（不写死成固定档位枚举）。
- 预设提供商固定四种：DeepSeek、SiliconFlow、DashScope、OpenAI；预设条目不可删除，但所有字段（含 API 格式）可修改，并提供"恢复默认"；自定义条目可增删改。
- 配置持久化在 `<study-mate-web>/data/settings.json`；系统提示词是独立于提供商的顶层配置项（见第 6 节）。

### 1.2 兼容与迁移

- 旧版单提供商结构在读取时自动迁移为多提供商结构：原配置成为一条提供商记录、其模型名成为该记录模型列表第一项、当前使用指向它；API Key 不丢失。迁移对用户无感。
- 模型的旧字段同样在读取时等价迁移：`视觉覆盖（自动 / 支持 / 不支持）` → 输入模态（"自动"迁为**未配置**，仍走内置前缀表，行为不变）；`思考档位（关 / 低 / 中 / 高）` → 推理档位（关迁为"未启用"；其余档位成为 `off/low/medium/high` 这组档位里的默认项）。缺字段按默认值补齐，读取不报错，迁移结果幂等落盘（不会反复重写）。
- 环境变量 `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` 在运行时覆盖当前使用提供商的对应字段，优先级最高，不写回配置文件。

### 1.3 提供商页（设置的默认子页）

提供商页采用**主从布局**（左列列表 + 右列编辑区；形态对齐 ZCode 的提供商页）：

- 左列为提供商列表：每项显示名称、API 格式徽标、**可用**模型数量；当前使用的项带"使用中"标识；列表上方有名称搜索框，底部有"添加提供商"。
- 右列编辑器（与添加面板互斥）：
  - **头部**：提供商图标、名称、**启用开关**，以及"…"菜单——菜单收纳"设为当前使用"、"恢复默认"（仅预设）、"删除"（仅自定义），不额外发明功能。
  - **连接区**：名称、Base URL、API 格式下拉（"OpenAI 兼容 Chat Completions" / "OpenAI Responses" / "Anthropic Messages"）、API Key（**回填已保存的密钥**，以密码点显示、右侧"显示 / 隐藏密钥"可切明文，不把密钥从界面上"吞掉"）。
  - **模型区**：模型列表为**只读摘要行**——模型名 + 徽标（上下文窗口如 `1M` / `128K`、模态、档位名如 `high`）+ 右侧四个操作：**测试**（该模型连通性）、**编辑**（打开模型编辑弹窗）、**删除**、**启用开关**；右上角"＋ 添加模型"。行内不直接编辑。
- **模型编辑弹窗**（字段与分区对齐 ZCode，见 §1.1）：
  - **基础区**：模型 ID、显示名、**输入模态（复选框组：文本 / 图片 / 视频 / PDF，可多选，不是单选下拉；未配置过模态的模型默认勾选「文本」）**、**最大输出 Token**、**上下文长度**。
  - **「兜底默认」语义**：最大输出 Token 与上下文长度**留空即落盘 null**（输入框只给占位提示，不预填默认值），由使用侧按兜底默认值处理——最大输出 Token 落空时沿用各协议默认值，上下文长度落空时右栏「上下文窗口」栏的分母取兜底默认值（`lib/contextWindow.ts` 的 `DEFAULT_CONTEXT_WINDOW`）。这样"没声明"与"显式声明了这个值"在落盘后仍可区分。
  - **高级（可折叠）**：**推理档位的有序 chip 编辑器**（可添加 / 删除 / 改名 / 排序）、默认档位——启用推理档位时若尚无档位，自动预置 `disabled / enabled` 两档并**默认档位取最高档**；能力声明——**工具调用默认对所有模型开启**（界面作为只读项提示，不提供开关；上游拒绝 tools 时自动回落纯文本），JSON Schema 输出 / 原生联网搜索两个开关仅落盘与展示。
  - **不提供"智能配置"**（不做任何自动探测 / 自动推断模型能力，模态、上下文窗口、最大输出 Token 一律人工填写）；**不提供模型级"启用"开关**（启停在模型行的开关上做）。
- **实时生效**：编辑器（含添加面板与模型编辑弹窗）的改动**防抖落盘、无「保存」按钮**，头部只给"保存中… / 已保存"的轻量反馈；连接测试也不再占编辑器底部按钮（入口见 §1.4）。新建提供商会立即落盘。
- 添加流程：右栏出现添加面板，从四个预设与"自定义"中选择后生成条目并进入编辑。

### 1.4 连接测试

以**模型行为单位**发起（编辑器底部不再有「测试连接」按钮）：按该提供商当前表单值 / 已落盘值向目标端点发一次最小请求，成功显示往返耗时，失败显示上游错误摘要。

- **API Key 取用**：编辑器加载时把**已保存的密钥回填进输入框**（用户看得见、能改、能测）；测试时以输入框的值为准，输入框被清空时才回落到该提供商已保存的 Key——因此"已保存过 Key 的提供商"不会误报"缺少 API Key"。
- 既没有输入值、也没有已保存 Key 时才报"缺少 API Key"。
- 掩码 `********` 仍被接受为"不修改"（PUT 的向后兼容语义），但界面不再用它做回显。
- 模型行上的"测试"走同一套判定，针对该行模型发起。

## 2. API 格式适配

系统通过统一适配层支持三种 API 格式，聊天（流式）与判分 / 评估 / 摘要 / 科目生成（非流式）等所有模型调用都经过它：

- **OpenAI 兼容 Chat Completions**：请求发往 `{base}/chat/completions`，流式响应逐段取文本增量；JSON 输出模式走该协议的结构化输出参数。
- **OpenAI Responses**：请求发往 `{base}/responses`；系统提示词走 instructions；流式拼接 `response.output_text.delta` 事件；JSON 输出模式走该协议的结构化文本配置。
- **Anthropic Messages**：请求发往 `{base}/v1/messages`，鉴权头为 `x-api-key` 与 `anthropic-version`；系统提示词走独立 system 参数；最大输出 tokens 必填（默认 4096）；流式取 `content_block_delta` 的文本增量；JSON 输出模式不可用，以提示词约束与宽容解析替代。
- 消息内容采用统一的内部表示（文本与图片块），由适配层按格式翻译为各协议的请求结构。
- 客户端超时为**读超时**（默认 900s，`STUDYMATE_LLM_TIMEOUT` 可覆盖），**不是单次请求的总时长上限**；总时长由链路的墙钟预算约束（见 §13.1）；上游错误信息原样透出给上层。

### 2.1 推理档位与协议映射

**档位表里混着两种语义**：`low/medium/high/max` 这类是**推理档位**（原样发给协议）；`disabled/enabled`、`off/on`、`关闭/开启` 这类是**思考开关**——「开」没有对应档位名，统一映射到默认档（medium），「关」则完全不发思考参数。开关值不会被原样当 `reasoning_effort` 发出（new-api 网关只认 `none/minimal/low/medium/high/xhigh/max`）。Anthropic 侧认不出的档位名不发思考参数（宁可用协议默认，也不 400）。

推理档位是**模型级能力**：每个模型声明一组**有序档位名**（由用户在模型编辑弹窗里自由增删改与排序，例如 `off/low/high/max`）与一个默认档位；对话侧在**输入区工具条右端（与模型选择器一并靠右，紧邻发送按钮）有一个独立的档位下拉**（档位只有这一个入口；当前模型没有档位时该下拉整体隐藏），**触发按钮只显示档位名**（设置页模型行徽标同样只留档位名），切换写回当前使用三元组。

- 档位到各协议的参数映射由统一适配层完成：Chat Completions 走 `reasoning_effort`；Responses 走 `reasoning.effort`；Anthropic 走 `thinking: {type: enabled, budget_tokens}`（预算按档位取值，并把 `max_tokens` 抬到预算之上以满足协议对 `budget_tokens < max_tokens` 的要求）。
- **模型未启用推理、档位列表为空、或档位为 `off` 时不发送任何思考参数**，请求体与未启用该能力的实现完全一致；无法识别的档位值静默省略而不是把请求打挂。
- OpenAI Responses 与 Anthropic 在开启推理时不再发送 `temperature`（这两类推理模型对非默认 temperature 会直接报 400）。
- **最大输出 Token** 同样由模型声明：非空时作为该模型的输出上限（Anthropic 的 `max_tokens`、其他格式的对应参数），为空则沿用默认值。
- 该能力为模型级声明，不改变聊天以外的调用（判分 / 评估 / 摘要 / 生成）。

### 2.2 工具调用协议映射

当一次调用带工具声明时，适配层按标准 OpenAI function calling 的 wire 形态翻译各协议（不发明自定义 wire 格式）：

- **Chat Completions**：`tools[{type:function,function:{name,description,parameters}}]` + `tool_choice`；assistant 的 `tool_calls{id,type,function{name,arguments}}`（arguments 为**原始 JSON 字符串**）与 `role:tool` + `tool_call_id` 回传。
- **Responses**：`tools[{type:function,name,description,parameters}]`；工具调用与结果表示为 `function_call` / `function_call_output` 输入项（以 `call_id` 关联）。
- **Anthropic Messages**：`tools[{name,description,input_schema}]` + `tool_choice:{type:auto}`；assistant 的 `tool_use` 块与 user 侧 `tool_result` 块（连续结果合并进一条 user 消息，`tool_use_id` 关联）。
- **流式增量聚合**：按 wire `index`（Responses 按 item id）聚合；`id` / `name` 赋值不追加、`arguments` 拼接，协议给出完整块时以完整值为权威（防止网关重复发 id 撑爆参数）。
- **降级**：`tools` 参数本身被上游拒绝（400）时，自动回落一次不带 tools 的调用。

### 2.3 思维链与用量透传

除正文增量外，适配层还把两类附加信息转成独立事件，供「中间过程」折叠区与右栏「上下文窗口」栏使用：

- **思维链**：Chat Completions 取 `delta.reasoning_content`（DeepSeek 系网关的字段名，个别网关用 `reasoning`，两者都探）；Responses 取 `response.reasoning_summary_text.delta` / `response.reasoning_text.delta`；Anthropic 取 `content_block_delta` 的 `thinking_delta`。统一转成 `reasoning` 增量，**与正文分开**——思维链不混进助手气泡正文。
- **用量**：网关在末块带 `usage`（Chat Completions 的 `prompt_tokens/completion_tokens/total_tokens`，Responses / Anthropic 的 `input_tokens/output_tokens`）时统一成一份用量；**不主动发 `stream_options`**（部分上游不认这个参数，而网关默认就带 usage），见到即收、见不到就没有用量事件。
- 两种格式的真实流式（含 tools）仍只覆盖 Chat Completions；Responses / Anthropic 的思维链与用量分支属未验证路径（本机无这两类渠道）。

## 3. 模态能力与自动剔除

设计原则：**输入端不拦截，发送端按能力注入，失败后按错误降级**（对照 DeepTutor 的两段式）。

### 3.1 能力判定

- 模型的视觉能力 = 该模型的**输入模态**优先：配了模态就用其中的"图片"项（显式配置压过内置表）；**未配置模态**时查内置模型前缀表——命中已知视觉模型（gpt-4o 及以后、gpt-4.1+、o3/o4 系列、claude-3+、claude-4+、gemini、glm-4v、qwen-vl、deepseek-vl 等）视为支持，未命中默认不支持。前缀表在后端单处维护。
- 模态里的"视频 / PDF"当前只做落盘与展示，发送侧行为不变（视频 / 音频一律文本占位，见 §3.2）。

### 3.2 发送端第一段（按能力注入）

- 模型支持视觉：图片按当前 API 格式转换为对应内容块随消息发送（Chat Completions 用 data-URL 图片块；Responses 用 input_image；Anthropic 用 base64 图片块）。
- 模型不支持视觉：不注入图片块，在消息文本对应位置插入占位行——"[图片：<文件名> —— 当前模型不支持图片输入，已剔除]"，并向前端发送提示。
- **视频与音频一律按"不支持"处理为文本占位，不实际发送**（三种协议对视频 / 音频输入的支持差异大、可用面窄，此为有意裁剪）。

### 3.3 发送端第二段（错误码剔除重试）

- 当请求携带图片块且调用失败时，对上游错误文本做标记匹配（image / vision / multimodal / image_url / content type / must be a string / expected string / invalid type for 'messages' 等，可结合 400/422 状态码）。
- 命中且模型不在已知视觉名单：剔除全部图片块、替换为占位行，**重试一次**；重试成功则向前端提示"模型不支持图片输入，已自动剔除并重试"。
- 模型在已知视觉名单上：**不降级**，让真实错误原样暴露（避免把真错误吞成误导性的纯文本回答）。
- 重试至多一次；再失败按普通错误处理。

### 3.4 提示事件

- 流式对话新增 `notice` 事件，承载"已剔除 / 已重试"类非致命提示；前端渲染为消息流中的浅色提示条，不写入会话历史。

## 4. 附件

### 4.1 输入入口

- 聊天输入框左侧**单一 📎 按钮**，文件与图片统一走此入口；支持点选、拖拽到输入区、粘贴。
- 受理范围：`image/*`（SVG 例外归入文档类，因视觉模型不收 SVG）+ 文本类（md / txt / csv / json / xml / 常见源码）+ pdf / docx / xlsx / pptx / epub。
- 支持多选；单附件上限 20MB，单条消息附件数上限 10 个，超限即时提示。
- **仅附件、无文字也允许发送**。

### 4.2 上传与存储

- 消息发送前先上传：`POST /api/uploads`（multipart），返回附件标识、文件名、大小与类别（图片 / 文档）；消息体引用附件标识。
- 存储位置：`<study-mate-web>/data/uploads/<会话>/<附件标识>_<文件名>`；消息记录中保存附件元数据。
- 删除会话时连带删除其上传目录；已上传但始终未随消息发送的孤儿文件，由后端启动时清理（超过 24 小时的未引用文件）。

### 4.3 文档解析

解析目标以**功能齐全**为主，在后端实现"字节进、文本出"的确定性管线（对照 DeepTutor 的 document_extractor）：

- **文本类**（md / txt / csv / json / xml / 源码）：多编码回退解码后原样注入。
- **Office 二进制**：pdf 用 pymupdf（缺失回退 pypdf，皆缺则"未解析"占位）；docx 用 python-docx；xlsx 用 openpyxl；pptx 用 python-pptx。解析库列入依赖清单，缺失时优雅降级为占位并提示。
- **EPUB**：标准库 ZIP + OPF 顺序提取。
- **注入方式**：附件提取文本以"附件：<文件名>"为标题块，拼接在用户消息原文之后，随消息进入会话历史与模型上下文。
- **预算**：单附件提取文本上限 20000 字符，单条消息全部附件合计上限 60000 字符，超限截断并提示。
- **解析失败**：注入"[附件 <文件名> 解析失败：<原因>]"占位，不阻断发送。
- 与插件侧的关系：Study-Mate 插件的本地教材转换是 resource-scout 第 0 步的**流程约定**（转 markdown 落 `reference/`，工具由总控准备），本节是 Web 运行时自己的确定性解析，**不改变插件侧流程**。文档内嵌图片不提取；OCR 不做。

### 4.4 前端展示

- 输入框上方横向**附件 chips 行**：图片显示本地缩略图，文档显示图标 + 文件名 + 大小；每项可移除。
- 消息流中，用户消息下方渲染该消息的附件：图片缩略图（点击放大预览），文档名（点击下载）。

## 5. 聊天页

### 5.1 新对话态

- 中央偏上欢迎区：按时段生成的问候标题（早/午/晚三组文案，页面挂载时随机定死一组，避免水合抖动）+ 一句说明 + **建议起点 chips**（讲解一个概念 / 出几道练习题 / 按我的课程进度继续 / 帮我制定学习计划），点击**只把文本填进输入框**（不直接发送），由用户编辑后手动发送。

- 顶栏只保留**会话标题**（+ 紧随其后的**内联重命名**按钮：点击标题旁的小笔进入输入框，Enter 提交、Esc / 失焦取消）与最右的**右侧边栏折叠按钮**；科目关联在输入区上方的关联行里，会话信息与附件区在右侧边栏里（见 §5.2）。

### 5.2 会话态

- 首条消息发出后：欢迎区、起点 chips 与**新对话关联行**一并移除；输入框落底（外层弹性占位收缩 + 650ms 缓动过渡，对照 DeepTutor）；顶栏标题切换为会话标题。
- **用户消息靠右显示并带品牌色气泡**（头像与内容整体右对齐）；助手消息保持左侧裸文本、不加气泡。**消息头像 46px**：用户为圆形（`rounded-full`）、助手为圆角方形；空态欢迎区的品牌大图标不随头像尺寸变动。**助手消息上方有名称栏**，显示产出这条回复的模型标识「提供商 / 模型」（历史消息用落库值，实时回合用当前生效模型；见 §5.5）。
- **右侧边栏**承载：**上下文窗口**（见 §5.5）、**附件区**（仅关联科目后出现，见 §11）与会话信息区（消息数、创建时间、关联科目）；可**拖拽调宽**（宽度持久化），**折叠有宽度过渡动画**（收起时内容保持挂载并置 `inert`，不因折叠丢失区段状态）；新对话默认折叠、已有会话按会话记住折叠状态。
- **科目绑死**：会话的科目关联只能在**新对话态的关联行**里指定，首条消息发出后入口即消失 —— 即"换科目 = 开新会话"（新会话不继承上一会话的科目）。**建课会话（interview）不关联已有科目**：归属由盘问收口→草稿→落点确认链自带。进入建课会话有两条路：新对话态直接以 interview 模式开会话（保留），以及**普通会话里由智能体经 `start_course_interview` 工具切入**（§14；收口判定按"本轮结束时的会话模式"，同轮切入 + 当场收口也成立）。**节点下拉移除**：节点聚焦不再由前端指定，后端在未指定节点时**自动推断**（先取"学习中"节点，否则第一个未开始——对照插件"接着上次学"），推断只作用于注入、不写回会话。
- **小结与沉淀记忆入口悬空**：聊天页右栏的「生成小结」与「沉淀记忆」入口不可达；后端端点与 `MemoryDialog` 组件保留待重新接线（评估结果面板的「沉淀记忆」入口不受影响，见 §12）。
- 消息流、流式光标、自动滚动、错误条、停止按钮、Enter / Shift+Enter 行为保持。

### 5.3 模型快捷切换

- 模型选择器位于**输入框内底部右侧**（不占用顶栏）；下拉按提供商分组列出其**启用**的模型。**选择的作用域分两种**：**新对话态**切换写全局默认（影响之后的新会话）；**已有会话内**切换只写该会话的绑定（`PATCH /api/sessions/{id}` 的 `active`，不动全局默认），刷新/换会话回看仍是它——该会话的聊天与「该会话的」小结/评估都跑在绑定模型上，绑定失效（提供商停用/删除、模型被移除）则回落当前默认模型并给一条提示。API Key 判据同样按「生效的那个提供商」算，绑到没配 key 的提供商时输入框如实禁用。
- **推理档位下拉**紧邻模型选择器（**同在输入区工具条的右端**、紧邻发送按钮），按当前模型声明的档位列表切换，写回当前使用三元组；触发按钮只显示档位名；当前模型未启用推理时整体隐藏（见 §2.1）。
- 无任何提供商配置时显示"未配置"，点击跳转设置页。
- 无 API Key 的禁用与提示逻辑保持。

### 5.4 右侧边栏（聊天页与课程图谱页共用）

聊天页与课程图谱页共用同一个**右侧边栏外壳**，行为一致：可拖拽调宽（宽度按页面分别持久化）、折叠/展开带宽度过渡动画（尊重系统"减少动态效果"偏好）、收起时内容保持挂载（`inert` + `aria-hidden`）而不卸载。

- **聊天页**：右侧边栏装**上下文窗口栏 + 科目「图谱 + 大纲」同屏双栏区（仅科目关联会话；大纲在上、图谱在下，中间手柄拖拽调占比且持久化，整体占满右栏选项卡以下空间；点节点跳 `/courses?subject=&node=`）+ 附件区 + 会话信息**（见 §5.2 / §5.5），折叠按钮在顶栏最右。双栏区由共享组件 `SubjectGraphPanel` 提供（`layout="stacked"`；课程页右栏仍是「图谱（默认）/ 大纲」分段切换）。

### 5.5 消息操作与「中间过程」折叠

**消息操作条**（悬停或键盘聚焦时出现，对照 DeepTutor 的消息操作条）：

- **用户消息**：**复制**、**编辑**（小图标按钮）。
  - **编辑 = 从这条消息重新生成**：气泡就地变成编辑框（文本可改、原有附件默认保留且可逐个移除、可再追加新附件），提交时前端带 `replace_from=<该条下标>` 发同一 `/api/chat/stream`，**服务端先截断该下标起的全部消息再追加新消息**，等于"改完这句让模型重答一遍"。不做"改字不改答复"的原位编辑；编辑提交前会给一句提示，因为该点之后的内容会被丢弃。**因此允许编辑任意一条用户消息**，其后内容一律截断。
  - 截断时，被顶掉消息的附件文件一并清理（仍要重发的原附件不在清理之列，服务端按 id 复用会话目录里的文件，不重复搬运）。
- **助手消息**：**复制**、**记入概念本**、**删除本轮**。
  - **删除本轮**：服务端按"用户提问 + 助手回复"成对删（`DELETE /api/sessions/{id}/messages/{index}`，index 指向该轮任一条）；**内联二次确认**（按钮就地变「删除本轮（问答一起删）？删除 / 取消」），不用模态；附件随之清理。

**用户消息展示文本分离**（`display_content`）：用户消息的 `content` 是**送模型的完整文本**（含附件解析出来的文本），`display_content` 是**用户原文**。**气泡渲染 / 编辑框初值 / 复制 / 再发送一律取 `display_content ?? content`**（用 `??`，空串保留为空、是合法原文而非缺省）；旧消息没有该字段时按 `content` 兜底，**不做数据迁移**。会话标题按「`display_content` 原文 → 附件文件名 → 默认」取名，**不回退展开后的 `content`**。这样附件解析文本等注入内容不会污染用户所见与可编辑的原文。

**「中间过程」折叠区**（按片段顺序内联在助手消息体中，默认各自收起；2026-10-05 随 §5.6 有序 `parts` 调整，状态同 §5.6）：

- **思维链按片段各自折叠**：每个思维链片段一个面板，按片段顺序**夹在工具卡之间**，**展开某一个不影响其它片段**；同时承载**本轮提示事件**（绑定提示 / 图片降级提示 / 重试提示）。**工具调用卡按流位置常显在消息体里**（不折进折叠区；流式期间与回放都直接可见）。
- **片段面板只在有思维链或有提示时渲染**：皆空（如纯工具片段）则不渲染，不留空面板。
- **片段表头标签**：`reasoning` 片段流式期间"正在思考…"、结束后**"中间过程 · 思考"**；`notice` 片段**"中间过程 · 提示"**。**「N 次工具调用」计数只在旧 legacy 整块面板保留**，新片段不显示工具计数。
- **落库持久化**：思维链原文、工具调用与结果都随助手消息落库（`reasoning` / `tools` 字段），**刷新或换会话回看时思维链仍在、工具卡仍常显**。

**盘问收口标记不露出**：建课会话的收口标记 `<!--INTERVIEW_RESULT-->{…}<!--/INTERVIEW_RESULT-->` 是**内部记账**，落库前会被剥掉、前端渲染/复制时再剥一次（含流式期间只吐出一半的「半截标记」）；助手正文同时去掉模型习惯性加的首尾空行。历史消息也按同一规则清洗。

**右栏「上下文窗口」栏**：标签 + 右侧当前模型标识，下方是"最近一轮 prompt tokens / 模型上下文长度 (百分比)"与一条细进度条。分子取**最近一轮请求的 prompt_tokens**（= 系统提示 + 全部历史 + 本轮消息，即当前上下文占用），来自流末的用量事件并落库在会话上（`usage`），刷新后回填；分母取**当前生效模型的上下文长度**，模型未声明时用兜底默认值（见 §1.3）。没有用量时显示"— / <长度>"并提示"本轮结束后显示用量"。

### 5.6 消息片段有序化（`parts`）与流生命周期

**目标**：修复「编辑重发后流式中切会话（A→B→A）导致本轮回复被中途中止、流式增量丢失」，并让工具卡按**实际 SSE 到达顺序**与正文交错呈现。

- **有序片段 `parts`**：助手消息按 SSE 到达顺序记录片段数组，两种形态——`{type: "text" | "reasoning" | "notice", text}` 与 `{type: "tool", tool_id}`。**工具结果不新增片段**，按 `tool_id` **原位更新** `tools[]` 中的原条目；**合并规则：前端只有相邻同类的 `text` / `reasoning` 合并，`notice` 各自独立，后端同前端——每个 notice 事件独立、不合并**；中间隔了工具 / 另一片段即断开。渲染按 `parts` 顺序，还原「正文 ↔ 工具卡」的真实交错。
- **只有 notice 不建空消息**：一轮里若只有提示（无正文 / 思维链 / 工具），**不创建空助手消息**。
- **内部标记跨 part 隐藏**：盘问收口标记（见 §5.5）即使在片段边界被切开，渲染 / 复制时也整体隐藏。
- **旧消息回落**：无 `parts` 的历史消息沿用旧布局（`content` / `reasoning` / `tools`）渲染；旧数据**无法反推**真实交错顺序，**不做数据迁移**。
- **流按会话存活（前端）**：流状态由 `frontend/lib/chatStream.ts` 按 `session_id` 持有，独立于 `ChatView` 挂载。**切换会话或离开 `/chat` 不 abort**；**只有显式「停止」才 abort，且只中止当前会话的流**。A→B→A 切回时优先用 store 恢复本轮已产出内容（不被服务端快照覆盖）；后台流事件只写回所属会话，不串到当前会话。
- **落库原位更新（后端）**：每轮助手回复固定一个 `turn_id`，中途 checkpoint 与终态都按它**原位 upsert**（不重复追加，消息下标稳定）。`stream_state` 取值：`streaming`（中途 checkpoint）/ `completed`（正常结束）/ `interrupted`（断开 / 停止，仍在 running 的工具标为未完成）/ `error`。**中断工具的结果文案为「本轮在工具返回前结束，结果未收到」**。**工具边界立即落盘**，正文 / 思维链按约 0.6s 节流；静默期约 3s 发一次 SSE 注释心跳以暴露断开。
- **停止 / 重载同步**：`GET /api/sessions/{id}` 返回 `streaming`（会话键是否仍被在飞轮次占用）。前端停止后轮询该字段；**重载后同样轮询，最多约 10s**，仍未结束则给一条**可重试的同步错误**（不静默），用户可再点同步。这只同步**已落盘片段**，**不承诺硬刷新能续跑后台任务**。
- **不做持续后台任务**：刷新或关闭浏览器**不保证**本轮继续；后台续流只覆盖**当前页面应用生命周期内**的切换（切会话 / 切路由 / 回到 `/chat`），**不等于服务端脱离页面继续跑**。重载后只能看到**已落盘的片段**。

> 状态：**已实施**。前端 `frontend/lib/chatStream.ts` + 后端 `turn_id` / `stream_state` 原位 upsert、有序 `parts` 均已落地。门禁与用例条数以 `pytest` / `npm run test:e2e` / `npm run test:component` 输出为准（快照与映射见[E2E 测试流程](StudyMate-Web_E2E测试流程.md)）。

  保存后立即生效（无需重启）；写入失败以 422 透出原因，配置与目录创建失败时回滚到改前内容。
- **新会话内选工作区**：**新对话态输入区上方的关联行**里有「工作区」下拉（与「关联科目」并排，见 §5.1）——空选项 = 当前默认工作区，候选 = 发现路径 / 插件默认 `~/StudyMate` / 环境变量覆盖值（去重），选中即按该工作区重载科目列表。
- **会话级工作区绑定**：会话可各自绑定一个工作区（绝对路径，存会话元数据；null = 跟随当前默认工作区）。绑定的作用是**该会话内的一切科目读写都落在它自己的工作区里**：对话的课程上下文、开场切片与记忆读取、会话小结与评估的落盘、附件区清单与原文，全部按该会话的工作区解析；打开历史会话时前端会切到它绑定的工作区加载科目列表。后端实现上只有一个收口点（`curriculum_store` 的工作区解析读请求级绑定），科目类读接口可带 `?workspace=<绝对路径>` 显式指定；`GET /api/workspace?path=` 提供只读预览。**约束**：绑定要求目录已存在（否则 422）。
- 工作区目录按需创建；`STUDYMATE_WORKSPACE` 存在的机器上，设置页改选不会改变实际生效路径
  （env 优先级最高，页面如实展示来源）。
- **跨工作区的只读资源前缀**：非默认工作区里打开课件页 / 工作区主页时，页面内的相对引用（CSS / JS / 图片 / 字体）不带 `?workspace=`；以 `GET /api/workspace-files/{token}/...` 前缀式路由承载（token 为工作区绝对路径的 base64url 编码、去 padding），相对引用自然保留前缀、落在同一工作区；该路由**只读并委托既有课件 / 主页处理器**，不是通用读盘口子。HTML 产物保持原样，不改资源引用。

## 13. 生产侧（产课 / 建课 / 采图 / 方向探索 / 质检工单）

Web 以**角色子代理**形态承担生产职责，子代理分两支：**工具化 agent 循环**（默认，对所有配置的模型开启，见第 14 节）与**无工具单次调用**（工具循环无交付时的回落兜底 / fixture 模式下的既有 envelope 契约）；建课链与产课链按此分流，交付契约与检验收口不变。备用（回落 / 直连）角色在任务卡上带 `execution_mode ∈ {tools, fallback, single_call}` 与 `fallback_reason` / `max_seconds` / `elapsed_s` / `message`，**按真实 start / done / error 呈现**；**单次派工返回 envelope 只表示这次调用有回复，不等于自检通过**。生产侧的链路细节（建课 / 产课 / 采图 / 方向探索 / 质检工单、真实 LLM 选型口径）见 [docs/StudyMate-Web_建课链路.md](docs/StudyMate-Web_建课链路.md)。

### 13.1 编排过程可见性与单次时长上限

- **过程可见性**：编排（建课 / 产课）期间每几秒向前端发一条 `progress` 快照（`{stage, round, elapsed_s, reasoning_chars, text_chars, tool_calls, last_tool}`）；`progress` 事件不落库。
- **墙钟上限**：聊天一轮 `STUDYMATE_CHAT_MAX_SECONDS`（默认 300s）、建课/产课单次派工 `STUDYMATE_ORCH_MAX_SECONDS`（默认 1800s）；到点用现有内容收尾，`stopped_reason="wallclock"` 并给出提示，已产出的文本与思维链照常落库，审计另记 `agent_wallclock` / `agent_wallclock_turn`。`chat_once` 总时限由 **`STUDYMATE_LLM_MAX_SECONDS`（默认 300s，覆盖重试退避）** 约束；编排角色 `max_seconds` 用 ORCH 1800s。
- **备用派工可见性**：工具循环未交付回落到单次派工时，备用角色**如实标 `execution_mode=fallback`**、带回落原因、墙钟时限与已等待秒数，终态按真实 `done` / `error` 呈现——**保留原始失败与真实终态，不把 envelope 返回当作自检通过、不假造模型过程、不刷屏**。墙钟预算不变（编排角色仍 `ORCH_MAX_SECONDS` 1800s）。
- **统一错误对象与红色错误详情（本轮已实施）**：错误统一为 `ErrorInfo = {code, status, upstream_code, phase, summary, detail, retryable, stopped_reason, request_id, source, operation}`（`code` 为开放 string）。SSE `error` 事件把 ErrorInfo **平铺**进 data（另带 `message`）；HTTP 错误体为 `{detail: summary, error: ErrorInfo}`；助手消息把本轮错误**持久化**为 `error` + `stream_state="error"`——**空正文但有 error 的消息不得被空消息过滤丢弃**，刷新 / 切会话后仍可回放诊断。前端 `ErrorNotice` 以 `role="alert"` 渲染，`data-error-tone` 区分 **danger（红，异常）** 与 **neutral（用户主动停止）**，提供摘要、HTTP 状态徽标、**展开详情**（含 `upstream_code` / `phase` / `request_id` / `detail`）与**复制诊断信息**；聊天消息流与产课任务卡（`task-error`）复用同一组件。上游流**缺少结束标记**（finish / `message_stop` / `response.completed`）判 `UpstreamEOFError` → `upstream_eof`，不再当成功静默半截。**停止按轮作用域**：`request_stop` / `consume_stop` 以 `(session_id, turn_id)` 定位，**`user_stop` 仅由停止入口显式登记**，取消 / 断线映射为 `disconnect`，不冒充用户停止。

### 13.2 旧工单最小恢复（归属确认 / 放弃）

质检工单的**归属**决定它归哪个学习工作区。**归属不明的旧工单**（早于归属机制、元数据缺 `workspace` 的记录）曾无从判定，本节描述其最小恢复流程。

- **unknown 判定**：**缺 `workspace` 的旧非 draft 工单一律判为归属不明（unknown）**，**包括与当前默认工作区同名的那些**——不再按 `legacy_default` 猜测归属；**`legacy_draft`（草稿期旧单）为全局例外**，保持可判定。**写入类操作对 unknown 同样 409**（不因缺 `?workspace=` 放行），owned / draft 缺 query 兼容。
- **列表可见性与提示**：unknown 旧单在前端**可见**并给出**归属未确认**提示；列表可带 `include_unscoped=true` **额外列出全部 unknown（绕过 slug 过滤）**，便于定位、删除与清理；**他人已归属（owned-other）的单不泄露**。
- **详情统一**：工单详情统一给出 `ownership` / `workspace_ambiguous` 与 `base_dir`（unknown 时 `base_dir` 为 `null`），前端据此渲染。
- **前端入口与交互**：科目头部的质检工单列表**覆盖无节点单**；`/courses` 默认「我的课程」（零科目）下也显示 **global「待归属」条**并展示原 slug（该入口带 `include_unscoped=true`）；节点页 / 聊天页既有工单入口**复用同一标记与弹窗**。unknown 弹窗给出**候选工作区 + 可手动输入**，必须**显式确认**（**确认前禁止产物读 / 改**；**无确认输入时不自动选择**）；确认后**持久化归属、重载仍保持弹窗状态**；统一标记 `type` 可为 `null`。
- **确认归属（claim）**：带 `{workspace}` 发起，**校验真实目录 / 科目 / node 后持久化归属**，落定后按正常单处理；**不限候选列表**（不强制只能选后端推荐的工作区）；**已归属且目标相同的重复 claim 幂等**。
- **放弃（abandon）**：unknown 旧单可 **status-only 放弃并附 reason**，**不触碰任何产物**（不搬移、不清理）。
- **不可复活**：**已关闭（closed）的单不能复活**。
- **并发**：归属相关的**执行 / 确认 / 放弃**持有**同一 `ticket_key` 租约**，避免同一工单上的写竞争。
- **不变**：**新工单**与**归属可判定的旧单**的重试 / 复检 / 快改行为不变。

> 状态：**前端与后端均已实施**（后端 `tickets` / `production` / `models` / `concurrency.ticket_key` + 定向 `test_legacy_ticket_recovery`；前端 `LegacyTicketRecovery` 组件 + `legacy-ticket-recovery` E2E），legacy 主流 UI / claim 并发 / 放弃均经独立复验 ACCEPT。用例条数以命令输出为准。

### 13.3 任务卡原位更新、结果透传与记录修复（2026-10-05 已实施）

- **`task_update` 原位更新**：SSE 新增 `task_update`，事件形如 `{id: <父 tool id>, task: <完整 snapshot>}`。前端按 `id` **原位更新同一条 `tools[].task`**，**不追加消息**（任务进展不产生新消息、不重复落库）。**role 内工具按命名空间隔离**；每张任务卡**常显 `stage` / `elapsed`**。
- **打开课件**：产课成功后经 Next `Link` **同 tab（SPA 导航）**打开该 **workspace 绑定的课件**，不整页刷新。
- **`tool_result` 透传**：工具结果透传 `task` / `lesson` / `assessment` 字段，供前端呈现任务、课件与评估。
- **评估系统状态（真相兜底）**：assessment 结果带系统状态——**`saved`（已落盘）vs `failed`（失败）**，且 **`background:false`**（**不承诺后台完成**）。系统状态卡是**兜底真相**：采用**受控提示 + 系统 assessment 真实状态卡**的双保险；**模型输出仍不可完全保证、不宣称绝对可靠**，最终以系统状态为准（E2E 故意让模型输出"我认为通过"，界面仍显示 **failed**）。
- **任务角色正文截断**：任务角色返回的正文**超过限额即截断并带明确提示**，不返回完整无限日志。
- **records 解析修复**：解析失败**最多做一次格式修复**，**机械分隔符修复优先**；修复结果须与原始语义快照**递归等价**（字段、题数、判分、原答、note 全部不变）；**无可信锚时保守失败、不落盘**。**不保证任意坏 YAML 都能修复。**
- **records 语义 mapping 校验**：落盘前做**完整语义 mapping 校验**，**类型不符（含 bool / number 冒充）同样拒绝**，不因"能解析"就放行。
- **备用派工角色展示与真实终态（本轮事故修复）**：回落 / 直连单次派工的角色在任务卡上标 `execution_mode`（`tools` / `fallback` / `single_call`）并展示 `fallback_reason` / `max_seconds` / `elapsed_s` / `message`；**`role_start` / `role_end` 反映真实执行阶段，`envelope` 返回不视为自检通过**，失败原样保留、不刷屏、不虚构模型过程。**真实 timeout 直接落到角色任务终态**（角色以 `error` 收尾，不留悬空 running）；**任务非 running 时任务卡隐藏「当前阶段」**；**本地停止时 roles 一并置终止态**。**既有产物复用与 `regenerate` 契约见 §14（本轮已实施并验证）。**
- **统一错误终态与红卡（本轮已实施）**：产课 / 聊天失败统一走 §13.1 的 `ErrorInfo`；任务卡 `error` 位改由 `ErrorNotice` 渲染（`danger` 红），**空正文亦有错误可回看**；任务 **非 running 隐藏「当前阶段」**，避免终态快照仍声称某阶段在跑。

## 14. 工具化调用（Agent 循环）

系统对**所有配置的模型**默认采用**工具化 agent 循环**替代单次大派工（对齐插件基线的 harness 形态）。
循环终止判据是"某轮不再发起工具调用，其文本即最终答案"。

- **轮次预算**：探索 8 轮（工具可用）+ 收尾 3 轮（工具仍可用，但注入"尽快收尾"提示）+ 强制无工具收尾 1 轮；
  "只思考不行动"（某轮既无文本也无调用）最多救 2 次；连续 3/5/8 次完全相同的调用发提醒（不阻断）。
  预算耗尽仍无最终答复时降级：带已有内容收尾并给出提示。
- **工具失败**一律转成 `role:tool` 的错误文本回喂，让模型自愈，不中断循环；单次结果超限截断。
- **文件边界**：相对路径以会话工作区 / 科目目录为基准；写操作前当场重新规范化并校验包含关系；
  越界返回稳定的可读拒答标记。加宽边界只有"转质检工单 / 人工确认"一条通道，不开放自由路径。
- **审计**：同一份事件序列既推前端又追加写 `data/audit/<编排或会话 id>.jsonl`——派工值、模型原始回复、
  每次工具调用与结果都落盘，**失败不清除**（供事后审计与堵点定位）；敏感参数在工具声明处脱敏。
- **chat 链路**：**只读三工具** `list_workspace` / `read_course_file` / `read_skill`，外加 **`start_course_interview`**（把普通会话切进建课盘问模式：落库 `mode=interview`；已绑科目拒绝、重复调用幂等；收口判定按"本轮结束时的会话模式"，同轮切入 + 当场收口成立）（读根限已绑定科目目录
  或工作区科目目录、以及仓库 `.dsh/skills`）；**科目关联会话额外开放动作工具 `produce_lesson` / `assess_node`**（未关联会话不得凭空产课/评估）。`produce_lesson` 不传 `node_id` 时**按大纲顺序取第一个尚无课件的节点**（与 curriculum schema 顺序一致），**不沿用会话注入的节点聚焦**；显式给出 `node_id` 时以它为准。工具调用与结果以**工具卡**呈现在会话流里（兼审计 UI）——**工具卡常显在消息体、不折进「中间过程」面板**；含动作工具的回合墙钟用 `ORCH_MAX_SECONDS`（1800s）。会话提示词只加一行动作说明，细节规范由模型 `read_skill` 按需读取（不整篇注入）。**（已实施）** interview 仅在用户**明确确认建课**的当轮进入收口：注入 `schemas[]`，最多 **2 个 LLM 轮 / 默认 120s**（`STUDYMATE_INTERVIEW_FINALIZE_MAX_SECONDS`，不超过 chat 的 300s）；**否定 / 疑问不触发**收口；**普通 interview 仍走工具循环**；输出完整收口标记后**停止后置工具**。收口阶段**只限制无关工具**，不采用"全部 interview 会话改走纯文本"的解法。收口 `schemas[]` 校验：收到 **name-only / 占位符 / 非字符串**等**缺信息**时**不建 draft**（保守失败）。
- **建课链**：大纲角色用 `submit_curriculum` 提交 DAG，后端**立即跑门禁并把报错原文回喂**，模型循环内自修；
  后端在循环之后再强制跑一次门禁（不信任模型自查）。**（已实施）** 区分**循环内自检事件**与**外层交付检查事件**，避免前端重复出现两条「完成」卡。
  **tools-enabled 角色提示按链路接线**：建课（`generate`）→ `submit_curriculum`；产课 → `write_deliver_file` / `run_check`；**工具循环无交付时的单次 fallback 仍走 envelope 契约**。
- **产课链**：角色用 `write_deliver_file` 交付产物、`run_check`（渲染 + 检查）在循环内自查自修；
  循环结束的交付仍走既有渲染/检查收口与质检工单兜底。**实操 / 实验的 lab 交付（本轮已实施）**：`kind=实操` 的 `produce_quiz` 与 `kind=实验` 的 `produce_experiment` 必须一并交付 `lab/<NNNN>-stage/README.md`（任务材料）、`lab/solutions/<NNNN>-stage/README.md`（参考解）与 `lab/README.md`（任务总表，**保留原表并增补本课**）；课件内容文件的 lab 入口相对链为 `../lab/<NNNN>-stage/README.md`。**required 缺一份即不 promote**（防相对路径写错 / 假解决），fixture 与真实派工同契约。**无效打回与次数（本轮已实施）**：打回耗尽后的 `error` 分开给出**修复派工轮 `repair_rounds`** 与**总控复检次数 `rechecks`**（`code=quality_check_failed`、带 `ticket_id`）；**纯总控归属（仅公共资源缺失）只复检一次、不占修复派工轮**，不再谎报"2 轮"。
- **既有产物复用与 `regenerate`（本轮已实施并验证）**：角色派工前先判**可复用**——① 本轮该角色无新交付文件；② `regenerate=false`；③ 本次上下文 `check_passed=true`；④ 该角色 required 目标文件存在、可读、非空（出题 = `*.quiz.json`，其余 = `*.md`）——四者同时成立才**接受既有产物、不再派工**，任一不满足即正常派工。`regenerate` 为布尔、默认 `false`、**严格 bool 校验（非布尔值拒绝）**；显式 `true` **强制重做、不复用**，**且必须显式给出 `node_id`（缺则拒绝）**。**quiz / 工单（ticket）交付同样走 required 文件 gate**（防相对 path 写错 / 假解决）。**非 UTF-8 内容不得复用**。**强制重做（检查打回后的重派轮）与工单 retry 一律禁复用**。
- **开启范围**：**工具调用默认对所有配置的模型开启**（不是可选项）；上游若不接受
  `tools` 参数，适配层自动回落一次不带 tools 的纯文本调用（工具声明本身不会打挂请求）。fixture 模式下
  仅显式工具场景走循环、其余保持固定流（测试稳定）。
- **不变量**：SKILL.md 全文注入保留（另加 `read_skill` 按需补充）；上游脚本零重写；门禁由后端在写盘后强制执行；
  采图保持纯后端爬虫，不进角色体系；工具循环无交付时回落既有单次派工链兜底。**共享检查器为脚本自身修复**：`check_lesson.py` 用 `HTMLParser` 只取**真实元素**的 `href/src`，`<pre>/<code>` 里转义的教学示例不再误报缺资源，**真实缺资源仍拦**——**不是 Web 第二份引擎、不绕过检查、「脚本只复用不重写」不变**。
