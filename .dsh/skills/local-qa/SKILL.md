# 局部提问与答疑规范

学生在阅读端选中一段看不懂的文本/代码/报错提问时，**问答面板就地打开、独立调模型回答**——不经过总控，也不背整个会话。目标是让他快速理解、不打断节奏。

**上下文只带三样**：当前课件、选中的那段、共享记忆。别把会话历史、别的科目或整本大纲带进去——答一段话要的就是这三样。

## 怎么答

- **先给答案，再给一句为什么**：代码问题给最小修复片段，概念问题给一句话例子；简短，别写成讲义
- **只给思路与最小示例，完整练习留给学生自己写**——面板不是替他把题做掉的地方
- 答完**停在原地**：面板就在正文旁边，他接着读、接着做那道题
- **问题超出片段范围**（变成"整块知识都没懂"）→ 明说这值得**单独讲**，让他回到会话里跟总控说——**面板不承担盘问、确认与调度**，不替他安排课程
- **面板不可用时**（无头宿主，或面板还没接上模型）：学生贴回的那段由总控就地答，规则照本节走，答完同样写一条误解记录——**别把"没人答"拖成流程里的一步**

## 答完写一条误解记录

面板回答**无痕**（不往会话里塞东西），但要往该科目的「误解库」写一条——**单一落点**，字段定型在 `schemas/misconceptions.schema.json`：

| 字段 | 写什么 |
|---|---|
| `topic` | 片段涉及的知识点，一句话，与正文锚点或节点标题对得上 |
| `source` | `问答面板` |
| `evidence` | **提问原文**（连带选中的那段）——这是这条记录唯一有用的部分 |
| `status` | `未处理`；补练过还没重验写 `已补练`，学生在新情境里自己走通了才写 `已消解` |
| `at` | 当天日期 |

- **不写 `null`**：没有内容就写「无」，或者干脆把这条记录省下——**没有证据的记录，下次开场读不出任何可用的东西**。
- 同一知识点问到**第三次**：**别再单点答疑**了——`evidence` 里写清"这是第三次问同一处"，`status` 留 `未处理`，让总控下次开场读到、由它决定要不要安排一次专门讲解（**调度是总控的事，面板只留证据**）。
